## Acceptance
- **R184 / AT184:** With the add-on option remote_access on (default off), the product is served under the public path /arx (option remote_path) on the customer's HA hostname through a Cloudflare remotely-managed tunnel route (path ^/arx(/.*)?$ -> http://<addon-hostname>:8099, no ports: mapping): /arx redirects to /arx/, the prefix is stripped server-side, API, WebSockets, images, downloads and hash routes work unchanged, /arx is 404 when the option is off, a no-op service worker at /arx/sw.js takes the /arx/ scope from HA's root service worker, X-Remote-User-* headers are ignored on this channel while Ingress trust stays bound to the Supervisor proxy address, security headers (CSP, frame-ancestors 'self', no-store on api) apply, and every route except an explicit allow-list answers 401 without a session (CR-008 §3a/§3e).
- **R185 / AT185:** A designed SmplWise Arx login page signs in with the HA username and password through HA's own login flow on the same origin (/auth/providers, /auth/login_flow with PKCE, the MFA step, /auth/token), stores the tokens (arx.auth.v1, and seeds hassTokens in HA's AuthData shape so the embedded WisKey panel is signed in), refreshes them, and exchanges the access token for an HttpOnly SameSite=Strict session cookie scoped to /arx/; the server validates the token against HA core (auth + auth/current_user), builds the same principal as Ingress (HA user id, VMS roles unchanged), re-validates at most every 60 s so a revoked refresh token or disabled user loses access within a minute, rate-limits the exchange per client IP, forwards the client IP to HA, never runs the bootstrap grant remotely, never exposes the Supervisor token, and audits remote logins, rejections, revocations and logouts (CR-008 §3b).
- **R186 / AT186:** SmplWise Arx is installable as a PWA (manifest with scope /arx/, own service worker that never caches the API, install prompt and an iOS guide) with Web Push (VAPID keys kept in /data, a subscription table per user, a notify path from the rules/alerts engine limited to events the user may see, click opens the event); a later Capacitor wrapper loads the customer's /arx origin, supports several sites, biometric unlock and native push through a SmplWise push relay (CR-008 §3d).
