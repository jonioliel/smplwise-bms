## Acceptance
- **R196 / AT196:** Device registration and signed fetch (CR-012 §3): the Android app registers per server and user a Keystore signing key and its push kind/address (push_subscriptions kind fcm|unifiedpush|socket); background calls are signed with that key; GET push/device/pending returns the device's pending notices re-checked against current permissions, categories and quiet hours; sign-out, server removal, remote-access revocation, sign-out-everywhere and device revocation remove the registration; notices map to the right server by an opaque server_ref.
- **R197 / AT197:** FCM content-less wake (CR-012 §4A): the Arx server asks a central SmplWise relay (installation key authentication, opaque per-device handles, rate limits, counts-only logs) to send a high-priority data-only FCM message carrying only server_ref and an opaque id (TTL 1 h, collapse per server); the app fetches the notice from its Arx server and always shows a visible notification (a generic one when the fetch fails); channels אזעקה/התראות/דלתות/תקלות/מערכת, lock-screen public version per the owner's choice, actions open-camera and acknowledge (unlock required), Android 13 permission asked in context.
- **R198 / AT198:** UnifiedPush fallback (CR-012 §4C): the app registers with the user's distributor through the UnifiedPush connector and gives Arx a Web Push endpoint and keys; Arx sends with the existing push.py (RFC 8291, VAPID) to push servers on a per-site allow-list entry; notifications behave as in the FCM path.
