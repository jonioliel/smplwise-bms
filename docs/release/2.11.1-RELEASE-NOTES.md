# SmplWise Arx 2.11.1 - Release notes / הערות שחרור

Source of truth for the text below: smplwise_vms/CHANGELOG.md (section 2.11.1, bilingual per item). Small release on top of 2.11.0
(`release/2111`): seven branches (DDAREA-295, TESTDEBT3-295, SMALL3-295, MASKSWITCH-295, TEMPREP-295, HAUSER-295, BREAKUI-295) merged without textual conflicts (one stale token-lint colour fallback in MASKSWITCH was fixed on the release branch). No full gate: verified by the targeted
run in docs/release/GATE_2112_TARGETED_RUNBOOK.md, whose verdict is recorded separately. No test result is claimed here.

## 2.11.1 (pilot) — Small release after 2.11.0: the home floor and area pickers follow the phone dropdown choice; a WisKey people-list refresh no longer gets lost; the connection test deadline is a setting (default 30 s); the temperature report type no longer changes the range, with an honest empty state and an optional every-sample list; a privacy-mask write switch row (default OFF); ten layout fixes on the new screens; the HA username comparison; flaky-test fixes and soak sampler hardening. The new switch and the new report option are OFF by default.
**After installing:** no database migration (still 0001..0145), no bridge change (stays 0.9.5), no new route (API inventory unchanged at 1196; the two temperature report routes take one new optional query parameter `samples`). Nothing needs to be switched on or off; no new permission. Two new options exist and are OFF by default (the privacy-mask write switch, the report option "every sample").
- **עברית:** אחרי ההתקנה: אין מיגרציה חדשה של מסד הנתונים (נשאר 0001..0145), אין שינוי בגשר (נשאר 0.9.5), אין נתיב API חדש (שני נתיבי דוח הטמפרטורה מקבלים פרמטר שאילתה אופציונלי אחד חדש, `samples`). אין מה להפעיל או לכבות; אין הרשאה חדשה. נוספו שתי אפשרויות שכבויות כברירת מחדל (מתג הכתיבה של מסכות הפרטיות, אפשרות הדוח "כל הדגימות").

### What was changed - מה השתנה
- **English:** Soak sampler hardening (SMALL3-295, scripts only, not part of the add-on runtime): the privacy-mask soak sampler (`scripts/soak/mask_soak.py`) is hardened and its heartbeat is written atomically, a full disk is logged and tolerated, the sampler refuses to start with less than 1 GiB free, and an unreadable heartbeat is reported honestly (helpers in `scripts/soak/soak_guard_io.py`). What the soak writes to the NVR is unchanged.
- **עברית:** חיזוק דוגם ה-soak (SMALL3-295, סקריפטים בלבד, לא חלק מזמן הריצה של התוסף): דוגם ה-soak של מסכות הפרטיות (`scripts/soak/mask_soak.py`) הוקשח, פעימת הלב נכתבת באופן אטומי, דיסק מלא נרשם ומתקבל בסבלנות, הדוגם מסרב להתחיל עם פחות מ-1 GiB פנוי, ופעימת לב שאי אפשר לקרוא מדווחת בכנות (העוזרים ב-`scripts/soak/soak_guard_io.py`). מה שה-soak כותב ל-NVR לא השתנה.
- **English:** The connection-test wall-clock deadline is now a setting: environment variable `SW_PROBE_DEADLINE_S`, default 30 s (was a fixed 8 s), range 1 to 120 s (out-of-range values are clamped, unreadable values fall back to 30). Behaviour at the deadline is unchanged and fails closed (`timeout`, sockets shut down).
- **עברית:** מגבלת הזמן הכוללת של בדיקת חיבור היא עכשיו הגדרה: משתנה הסביבה `SW_PROBE_DEADLINE_S`, ברירת מחדל 30 שניות (היה קבוע של 8 שניות), טווח 1 עד 120 שניות (ערך מחוץ לטווח מקוצץ, ערך שלא ניתן לקריאה חוזר ל-30). ההתנהגות בסוף הזמן לא השתנתה והיא נכשלת בצורה סגורה (`timeout`, החיבורים נסגרים).
- **English:** Temperature report, optional list of every sample (TEMPREP-295): the report dialog gets a content option "every sample", OFF by default, for both report types. When on, the PDF carries a table per unit of every recorded sample (installation-zone time, value, unit, flags: defrost / door open / off / out of range / alert / 5-minute average). It is capped at 5000 rows per PDF, shared between the units, and the PDF says so and prints the true count; the dialog preview shows 8 rows with the true counts and the same digest as the PDF. The sha256 line and the signature box are kept. The existing report routes take one new optional `samples=0|1` query parameter (no new route). Words in he / en / ar / ru (ar / ru initial), 44 px targets on phones only.
- **עברית:** דוח טמפרטורה, רשימה אופציונלית של כל הדגימות (TEMPREP-295): בחלון הדוח נוספת אפשרות תוכן "כל הדגימות", כבויה כברירת מחדל, לשני סוגי הדוח. כשהיא דולקת ה-PDF כולל לכל יחידה טבלה של כל דגימה שנרשמה (שעה לפי אזור הזמן של ההתקנה, ערך, יחידה, סימונים: הפשרה / דלת פתוחה / כבוי / מחוץ לטווח / התראה / ממוצע 5 דקות). הרשימה מוגבלת ל-5000 שורות ל-PDF, משותפות בין היחידות, וה-PDF מציין זאת ומדפיס את המספר האמיתי; תצוגת החלון מראה 8 שורות עם המספרים האמיתיים ועם אותו תקציר כמו ה-PDF. שורת ה-sha256 ותיבת החתימה נשמרות. נתיבי הדוח הקיימים מקבלים פרמטר שאילתה אופציונלי חדש `samples=0|1` (אין נתיב חדש). מילים בעברית / אנגלית / ערבית / רוסית (ערבית ורוסית ראשוניות), יעדי 44 פיקסלים בטלפון בלבד.
- **English:** Privacy-mask write switch (MASKSWITCH-295): Settings > Security > Privacy masks gets one plain switch row, for people holding `system.configure`, wired to the existing setting `nvr.privacy_mask_write`. Turning it ON asks first with an inline confirm (nothing is written to the NVR before the per-write confirm button); turning it OFF is one press. The view-only state of the editor follows the switch live. The default stays OFF. No backend change (the settings route already accepts the key). Words in he / en / ar / ru (ar / ru initial), 44 px targets on phones.
- **עברית:** מתג כתיבה למסכות פרטיות (MASKSWITCH-295): במסך הגדרות › אבטחה › מסכות פרטיות נוספת שורת מתג אחת, למי שמחזיק `system.configure`, המחוברת להגדרה הקיימת `nvr.privacy_mask_write`. הפעלה מבקשת קודם אישור בתוך השורה (שום דבר לא נכתב ל-NVR לפני כפתור האישור של כל כתיבה); כיבוי הוא לחיצה אחת. מצב התצוגה בלבד של העורך עוקב אחרי המתג בזמן אמת. ברירת המחדל נשארת כבויה. אין שינוי בצד השרת (נתיב ההגדרות כבר מקבל את המפתח). מילים בעברית / אנגלית / ערבית / רוסית (ערבית ורוסית ראשוניות), יעדי 44 פיקסלים בטלפון.

### Bugs fixed - באגים שתוקנו
- **English:** The floor and area chips of the devices screen ignored the "dropdown on the phone" setting (DDAREA-295): on a phone they always opened as a bottom sheet. They now follow the owner's choice like every other dropdown: "sheet" keeps the bottom sheet, "list" opens a popover under the picker (the area list hangs from the picker's far edge so it stays inside the screen). The floors / areas tree of the home screen is untouched.
- **עברית:** כפתורי הקומה והאזור במסך המכשירים התעלמו מהגדרת "תפריט נפתח בטלפון" (DDAREA-295): בטלפון הם נפתחו תמיד כגיליון תחתון. עכשיו הם ממלאים אחר בחירת הבעלים כמו כל תפריט נפתח אחר: "גיליון" משאיר גיליון תחתון, "רשימה" פותח חלון קופץ מתחת לבורר (רשימת האזורים תלויה מהקצה הרחוק של הבורר כדי להישאר בתוך המסך). עץ הקומות והאזורים של מסך הבית לא שונה.
- **English:** WisKey people list (TESTDEBT3-295, the one product change of that branch): a refresh that arrived while a page was loading is now run afterwards instead of being dropped, and a refresh waits for a "load more" in flight. Before, the dropped reply left the "load more" button disabled until a reload and the "directory changed" notice never appeared.
- **עברית:** רשימת האנשים של WisKey (TESTDEBT3-295, השינוי היחיד במוצר בענף הזה): רענון שהגיע בזמן טעינת עמוד רץ עכשיו אחריה במקום ללכת לאיבוד, ורענון ממתין ל"טען עוד" שבדרך. קודם התשובה שנזרקה השאירה את הכפתור "טען עוד" מושבת עד טעינה מחדש, וההודעה "הספרייה השתנתה" לא הופיעה.
- **English:** Flaky tests (tests only, no product behaviour): the long-press helper of the ticket-device spec holds the button until the menu or window shows; the WisKey people mock and spec cover the refresh above; the lat1 toggle-latency bound follows the disk's measured commit time as well as the CPU, and the messaging registry isolation helper names the notification module it needs instead of relying on import order. `docs/release/PIXEL_FAILURES_2026-10-21.md` classifies the 28 constant pixel failures of the nightly as stale baselines (analysis only: no baseline was regenerated, no test skipped).
- **עברית:** בדיקות לא יציבות (בדיקות בלבד, בלי שינוי התנהגות מוצר): עוזר הלחיצה הארוכה בבדיקת כרטיסי המכשיר מחזיק את הכפתור עד שהתפריט או החלון מופיעים; הדמיה ובדיקה של רשימת האנשים של WisKey מכסות את הרענון שלמעלה; גבול זמן ההשהיה של lat1 עוקב גם אחרי זמן הכתיבה הנמדד של הדיסק ולא רק אחרי המעבד, ועוזר בידוד רישום ההודעות מציין במפורש את מודול ההתראות שהוא צריך במקום להסתמך על סדר הייבוא. המסמך `docs/release/PIXEL_FAILURES_2026-10-21.md` מסווג את 28 כשלי הפיקסלים הקבועים של הלילה כקווי בסיס מיושנים (ניתוח בלבד: לא נוצרו קווי בסיס מחדש, אף בדיקה לא דולגה).
- **English:** Temperature report type (TEMPREP-295): the compliance (HACCP) button silently moved the range from 24 hours to the previous month and forced the signature line, and the standard button never gave either back; on a days-old module the previous month holds no samples, so both types showed a table of dashes and 0% coverage and looked broken. The server and the PDF were correct. Now the type is a pure switch: the compliance type no longer changes the range for good (it defaults 24 hours to the month so far and remembers what it changed; the standard type restores it; a range chosen by the user is kept), and a range with no samples shows one plain "no data in this range" state in the preview and in the PDF. A custom range without an offset is read in the installation zone (not the browser's), so the daily table's midnights hold wherever the browser is, and the fallback PDF prints out-of-range minutes as a duration.
- **עברית:** סוג דוח הטמפרטורה (TEMPREP-295): כפתור התאימות (HACCP) העביר בשקט את הטווח מ-24 שעות לחודש הקודם ואילץ את שורת החתימה, והכפתור הרגיל לא החזיר אף אחד מהם; במודול בן ימים בודדים החודש הקודם ריק מדגימות, ולכן שני הסוגים הציגו טבלה של מקפים וכיסוי 0% ונראו שבורים. השרת וה-PDF היו תקינים. עכשיו הסוג הוא מתג בלבד: סוג התאימות כבר לא משנה את הטווח לצמיתות (ברירת המחדל שלו עוברת מ-24 שעות לחודש עד כה והוא זוכר מה שינה; הסוג הרגיל מחזיר אותו; טווח שהמשתמש בחר נשמר), וטווח בלי דגימות מציג מצב אחד ברור "אין נתונים בטווח" בתצוגה ובקובץ ה-PDF. טווח מותאם בלי היסט נקרא לפי אזור הזמן של ההתקנה (ולא של הדפדפן), כך שחצאות הלילה בטבלה היומית יציבים בכל דפדפן, וה-PDF החלופי מדפיס דקות מחוץ לטווח כמשך.
- **English:** Layout fixes on the new screens (BREAKUI-295, CSS only; no behaviour, words or switches changed): ten fixes found with worst-case data (long and unbreakable names, huge numbers, phone 44 px targets). Door-window chips wrap instead of being cut; the event-rule editor's door list and confirm text; the privacy-mask camera rail, frame box-sizing and review / results / confirm columns; the WhatsApp pacing card inputs and cells; the bridge key card wrapping and phone targets; the floor / area picker option rows. The report is `docs/release/BREAKUI_2111_REPORT.md`.
- **עברית:** תיקוני פריסה במסכים החדשים (BREAKUI-295, CSS בלבד; בלי שינוי התנהגות, מילים או מתגים): עשרה תיקונים שנמצאו עם נתוני מקרה קיצון (שמות ארוכים ובלתי שבירים, מספרים עצומים, יעדי 44 פיקסלים בטלפון). צ'יפים של חלונות הדלתות נשברים לשורות במקום להיחתך; רשימת הדלתות והטקסט לאישור בעורך כללי האירועים; מסילת המצלמות של מסכות הפרטיות, ה-box-sizing של המסגרת ועמודות הסקירה / התוצאות / האישור; שדות ותאים בכרטיס קצב ההודעות של וואטסאפ; עטיפת הטקסט ויעדי הטלפון בכרטיס מפתח הגשר; שורות האפשרויות בבורר קומה / אזור. הדוח הוא `docs/release/BREAKUI_2111_REPORT.md`.
- **English:** Username comparison (HAUSER-295): Home Assistant 2026.10 trims and lower-cases usernames; the "username already in use" check of the user-admin service now compares both sides with the same strip + casefold normaliser as the rest of the identity code (an empty name is never reported as in use). Identity stays keyed by the HA user id everywhere; no duplicate path was found. The review is `docs/release/HA_2026_10_COMPAT_NOTE.md` (a code review with fakes; nothing was run against a live Home Assistant).
- **עברית:** השוואת שמות משתמש (HAUSER-295): Home Assistant 2026.10 מקצץ רווחים וממיר לאותיות קטנות בשמות משתמש; בדיקת "שם המשתמש כבר בשימוש" בשירות ניהול המשתמשים משווה עכשיו את שני הצדדים באותה נורמליזציה (strip + casefold) כמו שאר קוד הזהות (שם ריק אף פעם לא מדווח כתפוס). הזהות נשארת מבוססת על מזהה המשתמש של HA בכל מקום; לא נמצא מסלול ליצירת כפילות. הסקירה היא `docs/release/HA_2026_10_COMPAT_NOTE.md` (סקירת קוד עם תחליפים; שום דבר לא הורץ מול Home Assistant חי).

### What is OFF by default and how to enable - מה כבוי כברירת מחדל ואיך מפעילים
- **English:** Nothing is switched on by this release. Everything that was OFF in 2.11.0 stays OFF. The chips follow the existing "dropdown on the phone" setting (no new switch). The probe deadline needs no action (default 30 s); to change it set `SW_PROBE_DEADLINE_S` in the add-on environment (an environment variable, not a screen setting), 1 to 120.
- **עברית:** הגרסה הזו לא מפעילה שום דבר. כל מה שהיה כבוי ב-2.11.0 נשאר כבוי. הכפתורים עוקבים אחר ההגדרה הקיימת "תפריט נפתח בטלפון" (אין מתג חדש). מגבלת הזמן של בדיקת החיבור לא דורשת פעולה (ברירת מחדל 30 שניות); לשינוי מגדירים `SW_PROBE_DEADLINE_S` בסביבת התוסף (משתנה סביבה, לא הגדרה במסך), 1 עד 120.
- **English:** The privacy-mask write switch is OFF by default (`nvr.privacy_mask_write`); to turn it on, a person holding `system.configure` uses the new switch row on Settings > Security > Privacy masks and confirms. The temperature report option "every sample" is OFF by default (tick it in the report dialog per report).
- **עברית:** מתג הכתיבה של מסכות הפרטיות כבוי כברירת מחדל (`nvr.privacy_mask_write`); להפעלה, מי שמחזיק `system.configure` משתמש בשורת המתג החדשה במסך הגדרות › אבטחה › מסכות פרטיות ומאשר. אפשרות הדוח "כל הדגימות" כבויה כברירת מחדל (מסמנים אותה בחלון הדוח לכל דוח).

### Known limits - מגבלות ידועות
- **English:** 2.11.1 is released on TARGETED verification only (the runbook in `docs/release/GATE_2112_TARGETED_RUNBOOK.md`), by owner decision, not on a full gate. The Playwright specs for the chips (`dropdown-area-nav-phone.spec.ts`, `evidence-area-nav.spec.ts`) and the WisKey people spec are part of that targeted run only; the full suite ran for 2.11.0 on `release/2111`, not for these changes. The four later branches (temperature report, privacy-mask switch, layout fixes, username comparison) are covered by the targeted run only as well. Not included: HMACACT2, W11TPL and the other 2.12.0 items.
- **עברית:** 2.11.1 משוחררת על בדיקות ממוקדות בלבד (ספר ההרצה ב-`docs/release/GATE_2112_TARGETED_RUNBOOK.md`), בהחלטת הבעלים, ולא על שער מלא. בדיקות ה-Playwright של הכפתורים (`dropdown-area-nav-phone.spec.ts`, `evidence-area-nav.spec.ts`) ובדיקת רשימת האנשים של WisKey הן חלק מההרצה הממוקדת בלבד; הסוויטה המלאה רצה עבור 2.11.0 על `release/2111`, לא עבור השינויים האלה. גם ארבעת הענפים המאוחרים (דוח טמפרטורה, מתג מסכות פרטיות, תיקוני פריסה, השוואת שמות משתמש) מכוסים בהרצה הממוקדת בלבד. לא כלולים: HMACACT2, W11TPL ושאר פריטי 2.12.0.
