# 2.5.5 integration notes (integ/255)

Base `origin/main` @ `c117e9a9` (2.5.4). `integ/255` = main + `pilot/FIX-table-menus-255`. Nothing contacted a real device, NVR, WhatsApp account, tunnel, Cloudflare or Home Assistant: fakes and fixtures only.

## Content
- Root cause of the owner's screenshot: the status / handler menu was a child of the table cell (`td.cellmenu > .pop`, `position: absolute`) inside `.tw` (`overflow: auto`, a `backdrop-filter` ancestor), so
  the scroll box clipped it and an open menu grew the box's scroll area (inner vertical bar, 2 entries visible with one row).
- `frontend/src/tickets/overlay-menu.ts`: `placeOverlay` (pure: below the trigger, flipped above when that side holds the menu or has more room, `max-height` only when the menu is taller than the room, viewport clamp,
  RTL grows from the trigger's right edge) and `openOverlay` (shows a `popover="manual"` element in the top layer and applies the placement), `menuKey` (arrows / Home / End).
- `tickets-table`: the open menu is rendered once, after the `.tw` box (`.pop.ov[data-overlay]`), repositioned after each render, on resize and on scroll; Escape returns the focus to the trigger, Tab and an outside click close,
  the phone's compact list has no cell menus (the menu closes when the width drops under 768). `.tw` stays `block-size: auto` (max-height unchanged) so a few rows leave no empty area / vertical bar; the sticky header is unchanged.
- `ticket-card`: the "..." menu uses the same overlay (cards view and board). The bulk bar's assign / priority dialogs are in-flow lists inside `sw-dialog` (no floating menu) and the toolbar popovers sit outside any scroll box: unchanged.
- No new skin rule (Bubble budget untouched): `.pop.ov` paints `var(--sw-menu-surface)`, registered by the existing menu-lint rules.
- Settings lists: `tickets-dept-editor` emits `dept-reload` after every successful write (the screen re-reads the departments instead of trusting a hand patch), `createDepartment` re-reads, and `LiveRefresh` (the 2.5.4 helper)
  polls the departments and permissions tabs (`system-tickets`), the members card and the contacts directory (the latter only while no editor / create form is open). Message templates already re-read after every write.
- Bulk delete of ONE selected row ends as `ticket-deleted` (not `bulk-done`) and had no handler in the table: the row stayed until the next poll. The table now drops it at once; `not_found` rows of a bulk answer leave too.
- No migration (last 0084), no new add-on option, API inventory unchanged (version line only).
