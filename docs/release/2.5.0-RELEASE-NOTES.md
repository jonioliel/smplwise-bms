## 2.5.0 (pilot) — Service management (CR-038): a new optional module for service requests

**After installing:** **five database migrations, applied automatically at start**: 0079 (core), 0080 (contacts and handler links), 0081 (message channel), 0082 (messaging accounts), 0083 (cost claims); the sequence is now 0001..0083 (0084 stays unused). **No bridge change** (0.8.0). **One new add-on option, `tickets_public` (default `false`)**: starts the handler page's own listener on container port 18093 (declared, never mapped to the host). Reload the installed web app once. **The module is OFF by default: an installation that does not switch it on sees no change.** **Nothing here was run against a real ha-whatsapp, Cloudflare tunnel, phone, SMTP server or Home Assistant: fakes and fixtures only.**

- **עברית:** אחרי ההתקנה: **חמש מיגרציות של מסד הנתונים, שרצות אוטומטית בהפעלה**: 0079 (ליבה), 0080 (אנשי קשר וקישורי מטפלים), 0081 (ערוץ ההודעות), 0082 (חשבונות הודעות), 0083 (תביעות עלות); הרצף עכשיו 0001..0083 (0084 נשאר ללא שימוש). **אין שינוי בגשר** (0.8.0). **אפשרות תוסף חדשה אחת, `tickets_public` (ברירת מחדל `false`)**: מפעילה את השרת הנפרד של דף המטפלים בפורט 18093 (מוגדר, לא ממופה אל המארח). טוענים מחדש את אפליקציית הרשת פעם אחת. **המודול כבוי כברירת מחדל: בהתקנה שלא מפעילה אותו אין שום שינוי.** **שום דבר מכאן לא הורץ מול ha-whatsapp, מנהרת Cloudflare, טלפון, שרת דואר או Home Assistant אמיתיים: רק מערכות מדומות ונתוני בדיקה.**

## Naming - שמות
- **English:** the module is "service management" and its item a "service request"; the name is configurable in Settings (module-name field, `tickets.configure`) and every text follows. Internal identifiers stay `tickets`.
- **עברית:** המודול נקרא "ניהול השירות" והפריט "בקשת שירות" (בקשות שירות ברבים); השם ניתן לשינוי בהגדרות (שדה שם המודול) וכל הטקסטים במערכת מתעדכנים. המזהים הפנימיים נשארים `tickets`.

## What was added - מה נוסף
- **English:**
  1. **Skeleton and internal requests** (0079): module switch `tickets.enabled`, list / detail / create screens, statuses, four priorities, one visibility rule for every row.
  2. **Departments and SLA**: managers and members, categories, templates, a department x priority SLA matrix, link-lifetime and send-hours policy with overrides, automatic close of "done" requests.
  3. **Device integration**: a service-requests tab on a device, creation from a device (also by long press), place from the map, a frozen 24-hour device history.
  4. **Contacts, handler links and the public handler page**: a directory of outside people and vendors; a private link to a small page on its own listener (**port 18093, behind the add-on option `tickets_public: false`**), where the handler updates the status, adds a note or photo, or answers "not mine".
  5. **WhatsApp account selection per use** (0082) and **the message channel** (0081): outbox with send hours, pacing, retries, e-mail and copy-link fallbacks; inbound replies matched to the request; editable templates; the WhatsApp master switch is off by default.
  6. **Stuck / escalation monitor, manager board and notifications**: per-department thresholds, a reminder ladder, a manager alert, the board `#/tickets/board`.
  7. **Board table view**: sort, filters, CSV export (up to 5,000 rows), bulk actions on 1-50 requests, saved views.
  8. **Verification codes (option B)**: six digits by the other channel, settings for lifetime / attempts / lock, lock card with "send a new link". The public page's "code sent" line now shows the configured code lifetime.
  9. **Cost claims** (0083): vendor claim step (invoices, photos, VAT), manager review, a close gate overridable with a reason. A costs settings tab (installation and department defaults), cost fields in the contact editor, notification sources `ticket.cost_submitted` / `ticket.cost_missing`.
- **עברית:**
  1. **שלד ובקשות פנימיות** (0079): מתג המודול `tickets.enabled`, מסכי רשימה, פרטים ויצירה, סטטוסים, ארבע עדיפויות, כלל נראות אחד לכל שורה.
  2. **מחלקות ו־SLA**: מנהלים וחברים, קטגוריות, תבניות, מטריצת SLA לפי מחלקה ועדיפות, מדיניות תוקף קישור ושעות שליחה עם עקיפות, וסגירה אוטומטית של בקשות שבוצעו.
  3. **שילוב עם התקנים**: לשונית בקשות שירות בהתקן, פתיחה מתוך התקן (גם בלחיצה ארוכה), מיקום מהמפה, ותמונת היסטוריה קפואה של 24 שעות.
  4. **אנשי קשר, קישורי מטפלים ודף המטפלים הציבורי**: מדריך של אנשים וספקים חיצוניים; קישור פרטי לדף קטן בשרת נפרד (**פורט 18093, מאחורי אפשרות התוסף `tickets_public: false`**), שבו המטפל מעדכן סטטוס, מוסיף הערה או תמונה, או משיב "לא שלי".
  5. **בחירת חשבון וואטסאפ לפי שימוש** (0082) ו**ערוץ ההודעות** (0081): תור יוצא עם שעות שליחה, קצב, ניסיונות חוזרים וגיבוי בדואר או בהעתקת קישור; תשובות נכנסות מותאמות לבקשה; תבניות ניתנות לעריכה; המתג הראשי של וואטסאפ כבוי כברירת מחדל.
  6. **ניטור תקיעות והסלמה, לוח מנהל והתראות**: ספים לכל מחלקה, סולם תזכורות, התראה למנהל, הלוח `#/tickets/board`.
  7. **תצוגת טבלה בלוח**: מיון, מסננים, ייצוא CSV (עד 5,000 שורות), פעולות המוניות על 1-50 בקשות, תצוגות שמורות.
  8. **קודי אימות (אפשרות ב)**: שש ספרות בערוץ האחר, הגדרות לאורך חיים / ניסיונות / נעילה, כרטיס נעילה עם "שלח קישור חדש". שורת "הקוד נשלח" בדף הציבורי מציגה עכשיו את אורך חיי הקוד שהוגדר.
  9. **תביעות עלות** (0083): שלב תביעה לספק (חשבוניות, תמונות, מע"מ), בדיקת מנהל, חסימת סגירה הניתנת לעקיפה עם סיבה. לשונית עלויות בהגדרות המודול, שדות עלות בעורך אנשי הקשר, ושני מקורות התראה על תביעות.

- **English - WhatsApp test send** (owner decision 14.10): Settings › ערוץ ההודעות › the chosen account › "שליחת בדיקה": type a number, press "שליחה", confirm; one fixed text, at most 5 per hour per account, `messaging.accounts.manage`, local sessions only, works while the master switch "שליחה בוואטסאפ" (default OFF) is still off; no environment switch. The account / entry shapes and the send path were verified live by the owner; the guide no longer marks them unverified.
- **עברית - שליחת בדיקה בוואטסאפ** (החלטת בעלים 14.10): הגדרות › ערוץ ההודעות › החשבון הנבחר › "שליחת בדיקה": מקלידים מספר, לוחצים "שליחה" ומאשרים; הודעה קבועה אחת, עד 5 בשעה לכל חשבון, למחזיקי `messaging.accounts.manage`, מחיבור מקומי בלבד, עובד גם כשהמתג הראשי "שליחה בוואטסאפ" (כבוי כברירת מחדל) עדיין כבוי; בלי מתג סביבה. צורת החשבונות ונתיב השליחה נבדקו חיה; המדריך כבר לא מסמן אותם כלא מאומתים.
- **English - security and hardening (review of 14.10, all in this release):** the module key rotation and the handler page's public settings (address, trusted proxies, client-address header) change from a local session only; nobody approves or adjusts a cost revision they entered themselves (409 `self_approval`); the service-request CSV uses the module's formula guard; an incoming WhatsApp reply without an account id is ignored ("account unknown", no content kept) while more than one account is linked (buttons still match through their own code); uploaded photos are decoded strictly even after the bill-PDF library switched Pillow to accept truncated images process-wide (found by the release gate: a broken picture could be stored as a half-grey image).
- **עברית - אבטחה והקשחה (מהסקירה של 14.10, הכול בגרסה הזאת):** החלפת מפתח המודול והגדרות הכתובת הציבורית של דף המטפלים משתנות מחיבור מקומי בלבד; אי אפשר לאשר או לתקן הגשת עלות שהזנתם בעצמכם; ייצוא ה-CSV של בקשות השירות משתמש בהגנת הנוסחאות של המודול; תשובת וואטסאפ נכנסת בלי מזהה חשבון לא משויכת לבקשה ("חשבון לא ידוע", בלי שמירת התוכן) כשמחוברים כמה חשבונות; תמונות שמועלות מפוענחות בקפדנות גם אחרי שספריית ה-PDF של החשבוניות הורתה ל-Pillow לקבל תמונות קטועות (נמצא בשער השחרור).

## How to enable - איך מפעילים
- **English:** (1) Settings › the module switch (`tickets.enabled`, `system.configure`). (2) Permissions: `tickets.view`, `tickets.create`, `tickets.manage`, and the sensitive `tickets.external`, `tickets.all_departments`, `tickets.configure`, `tickets.costs`, `tickets.costs.view`, `messaging.accounts.manage`. Eight single-permission roles: `tickets_view`, `tickets_create`, `tickets_manage`, `tickets_external`, `tickets_all_departments`, `tickets_configure`, `tickets_costs`, `tickets_costs_view`. (3) Outside handlers: add-on option `tickets_public: true`; a dedicated Cloudflare tunnel route to container port 18093 (do not map the port to the host; origin keep-alive under 5 s, at most 8 idle connections); the public address in Settings and its address check; the Cloudflare rate-limit rule and the Home Assistant recorder exclusions (full steps: `docs/user-guide/he/46-tickets_HE.md`). (4) WhatsApp: pair a dedicated number in ha-whatsapp, map accounts in Settings, run the live checks, then switch sending on. Rollback: switch the module off (data kept); reinstalling 2.4.11 leaves migrations 0079-0083 unused.
- **עברית:** (1) הגדרות › מתג המודול (`tickets.enabled`, `system.configure`). (2) הרשאות: `tickets.view`, `tickets.create`, `tickets.manage`, והרגישות `tickets.external`, `tickets.all_departments`, `tickets.configure`, `tickets.costs`, `tickets.costs.view`, `messaging.accounts.manage`. שמונה תפקידים בני הרשאה אחת: `tickets_view`, `tickets_create`, `tickets_manage`, `tickets_external`, `tickets_all_departments`, `tickets_configure`, `tickets_costs`, `tickets_costs_view`. (3) מטפלים חיצוניים: אפשרות התוסף `tickets_public: true`; נתיב ייעודי במנהרת Cloudflare אל פורט 18093 (לא ממפים את הפורט אל המארח; keep-alive במקור מתחת ל־5 שניות, עד 8 חיבורי סרק); הכתובת הציבורית בהגדרות ובדיקת הכתובת; כלל הגבלת קצב ב־Cloudflare והוצאת ההודעות מהמקליט של Home Assistant (השלבים המלאים: `docs/user-guide/he/46-tickets_HE.md`). (4) וואטסאפ: מצמדים מספר ייעודי ב־ha-whatsapp, משייכים חשבונות בהגדרות, מריצים את הבדיקות החיות, ואז מדליקים שליחה. החזרה לאחור: מכבים את המודול (הנתונים נשמרים); התקנת 2.4.11 משאירה את מיגרציות 0079-0083 בלי שימוש.
