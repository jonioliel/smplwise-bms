# SmplWise Arx 2.2.1 - Release notes / הערות שחרור

Source of truth for the text below: smplwise_vms/CHANGELOG.md (section 2.2.1, bilingual per item).

## 2.2.1 (pilot) - security fixes for 2.2.0, gate fix and visual baselines, Frigate add-on option, bundled Android APK, mobile contract v2

**After installing:** no database migration (the sequence still ends at `0067`). The bridge stays 0.7.0. Reload the installed web
app once. 680 API routes (678 + 2: the Frigate event-control read and the bundled app download file). New setting
`security.second_factor_bearer` (default `enforce`); new add-on option `frigate_enabled` (default `false`).

### Security fixes (review of 2.2.0)
**Important.** The optional TOTP second factor (and the `admins` policy) now also applies to **token-based sign-ins** (a client that
signs in with a Home Assistant access token instead of the browser session), over HTTP and on the live WebSocket connection.
**2.2.0 had a bypass on this path:** an installation that enabled the second factor on 2.2.0 should treat it as weak until it runs
2.2.1. Users without a factor are unchanged. `security.second_factor_bearer` = `enforce` (default); `off` restores the 2.2.0
behaviour and audits every skipped check (not recommended).
**Also fixed.** Enabling the factor ends the user's other remote sign-ins and an administrator's reset ends the target's sign-ins; an
administrator cannot reset their own factor, and an enrolled administrator confirms a reset with their own code; the plan DXF export
and signed plan package carry only the anchors the caller may see; the plan package import has size / shape limits, one import in
flight per user and a per-user rate, and a foreign or retired-key package needs the trust confirmation already at the preview;
announcement rules re-check the saver's permission on every run, markup is stripped from announcement text, and the cooldown holds per
speaker; Frigate event ids and camera keys are validated before use; installation-wide Frigate change-log rows are shown only to
recorder administrators; the public app-download route is rate-limited per address.
**How to enable.** Nothing to do (on by default). Where the factor is required, users of token-based clients need a client that can
send the code.

### Release gate fix and refreshed visual baselines
**Fixed.** The gate re-runs every failed test alone; the retry result was matched by file and line, so for a test inside a loop
(several skins or screens on one source line) a passing sibling hid a real failure as "flaky". It is matched per test title now. The
Linux visual baselines that this exposed were regenerated after two intended layout changes (seven images). The flaky tests of the
2.2.0 gate were root-caused and fixed (`docs/release/TEST_POLICY.md`); two Frigate backend tests that depended on the calendar day are
pinned to their fixture clock.

### Frigate selectable through an add-on option
**Added.** Add-on option `frigate_enabled` (**off by default**, unchanged behaviour): when on, the Frigate recorder type is
selectable in Settings (before, only the server environment variable `SW_FRIGATE=1` did this). Frigate write classes stay off per
recorder. Also: the review detail shows the retain flag and sub-label, an operator with `events.read` gets the event control read, and
the Frigate write-class tables are in the backup. **How to enable.** Add-on Configuration › `frigate_enabled: true` › save › restart
the add-on; then add the recorder in Settings.

### Android APK bundled in the add-on image
**Added.** The sign-in page's Android download offer can serve a signed APK bundled in the add-on image (`auth/app-download/file`,
with version, size and SHA-256). **Nothing is shown until a signed APK is staged** (`scripts/stage_apk.py`, see
`docs/release/RELEASE_PACKAGE_V1.md`); the 2.2.1 image carries no APK. An administrator's external https address still wins.
**How to enable.** A release that stages a signed APK enables it; otherwise use the Android download address in Settings.

### Mobile apps contract v2 (CR-027)
**Added.** Device registration returns `server_id` and `relay_url`; relay registration is idempotent (a known phone gets the same
relay token and is not rate-limited on repeats); a server id belongs to the first server key that claims it; one relay token per phone;
cross-site refusals carry a machine-readable reason. Contract: `docs/api/mobile-presence-contract.md`. **Not deployed:** the relay
Worker (owner step; it needs `RELAY_TOKEN_SECRET`). **How to enable.** Nothing in the add-on; the phone apps adopt v2 in their next build.

### Guide pages and soak tooling
**Added.** Hebrew user-guide pages for Frigate, the second factor, the generator and wall mode, plus updates with screenshots
(`docs/user-guide/he/`); a read-only soak sampler and Hebrew analyzer for T068 (`scripts/soak/README_HE.md`).

### Known limits
Unchanged from 2.2.0: the first supervised write of each Frigate write class on a real Frigate, a Frigate viewer account, clip export
and HLS time anchors are still open; PTZ stays behind `PTZ_RELEASED = False`; no signed Android build is staged; the push relay is not
deployed.

## עברית - 2.2.1: תיקוני אבטחה ל־2.2.0, תיקון שער השחרור, אפשרות Frigate בתוסף, APK בתוך התוסף, חוזה v2 לנייד

**אחרי ההתקנה:** אין מיגרציה (הרצף מסתיים ב־`0067`). רכיב החיבור נשאר 0.7.0. טוענים מחדש את אפליקציית הרשת פעם אחת. 680 נתיבי API
(678 ועוד 2). הגדרה חדשה `security.second_factor_bearer` (ברירת מחדל `enforce`); אפשרות תוסף חדשה `frigate_enabled` (ברירת מחדל `false`).

### תיקוני אבטחה (סקירת 2.2.0)
**חשוב.** האימות הדו-שלבי הרשותי (TOTP) ומדיניות `admins` חלים עכשיו גם על **כניסות מבוססות אסימון** (לקוח שנכנס עם אסימון גישה של
Home Assistant במקום עם הפעלת הדפדפן), ב־HTTP ובחיבור ה־WebSocket החי. **ב־2.2.0 היה עקיפה במסלול הזה:** התקנה שהפעילה את האימות
הדו-שלבי ב־2.2.0 צריכה להתייחס אליו כחלש עד שהיא מריצה 2.2.1. משתמשים בלי גורם שני לא מושפעים. `security.second_factor_bearer` =
`enforce` (ברירת מחדל); `off` מחזירה את התנהגות 2.2.0 ומתעדת כל דילוג (לא מומלץ).
**עוד תוקן.** הפעלת הגורם השני מסיימת את שאר הכניסות המרוחקות של המשתמש, ואיפוס בידי מנהל מסיים את כניסות המשתמש המאופס; מנהל לא
מאפס את הגורם של עצמו, ומנהל רשום מאשר איפוס בקוד שלו; ייצוא DXF וחבילת התוכנית כוללים רק עוגנים שהמבקש רשאי לראות; לייבוא חבילה
יש מגבלות גודל ומבנה, ייבוא אחד בכל פעם וקצב למשתמש, וחבילה זרה או במפתח שהוחלף דורשת אישור אמון כבר בתצוגה המקדימה; כללי הכרזה
בודקים בכל ריצה את הרשאת מי ששמר אותם, תגיות מוסרות מהטקסט וההמתנה חלה לכל רמקול; מזהי אירועי Frigate ומפתחות מצלמה נבדקים לפני
השימוש; שורות ההתקנה הכלליות ביומן השינויים של Frigate מוצגות רק למנהלי המקליט; נתיב הורדת האפליקציה הציבורי מוגבל בקצב לכל כתובת.
**איך מפעילים.** אין צורך (פעיל כברירת מחדל). כשהגורם השני נדרש, משתמשי לקוחות מבוססי אסימון צריכים לקוח שיודע לשלוח את הקוד.

### תיקון שער השחרור ובסיסי השוואה חזותית
**תוקן.** השער מריץ שוב לבד כל בדיקה שנכשלה; התוצאה הותאמה לפי קובץ ושורה, ולכן בבדיקה בתוך לולאה (כמה עיצובים או מסכים על אותה
שורה) בדיקה אחות שעברה הסתירה כשלון אמיתי כ"לא יציב". עכשיו ההתאמה לפי שם הבדיקה. בסיסי ההשוואה החזותית של לינוקס שהתגלו כך נוצרו
מחדש אחרי שני שינויי פריסה מכוונים (שבע תמונות). הבדיקות הלא יציבות משער 2.2.0 אובחנו ותוקנו; שתי בדיקות Frigate שהיו תלויות בתאריך
נקבעו לשעון הנתונים שלהן.

### בחירת Frigate דרך אפשרות התוסף
**נוסף.** אפשרות התוסף `frigate_enabled` (**כבויה כברירת מחדל**): כשהיא דולקת, סוג המקליט Frigate זמין לבחירה בהגדרות (קודם רק משתנה
הסביבה `SW_FRIGATE=1`). מחלקות הכתיבה נשארות כבויות לכל מקליט. עוד: דגל השמירה ותווית המשנה בפרטי הסקירה, קריאת שליטה באירוע למפעיל
עם `events.read`, וטבלאות מחלקות הכתיבה בגיבוי. **איך מפעילים.** תצורת התוסף › `frigate_enabled: true` › שמירה › הפעלה מחדש; אחר
כך מוסיפים את המקליט בהגדרות.

### APK של Android בתוך התוסף
**נוסף.** הצעת ההורדה במסך הכניסה יכולה להגיש APK חתום שמצורף לתמונת התוסף (`auth/app-download/file`, עם גרסה, גודל ו־SHA-256).
**שום דבר לא מוצג עד ש־APK חתום מוכנס** (`scripts/stage_apk.py`); בתמונה של 2.2.1 אין APK. כתובת https חיצונית של מנהל עדיין גוברת.
**איך מפעילים.** שחרור שמכניס APK חתום מפעיל זאת; אחרת משתמשים בכתובת ההורדה בהגדרות.

### חוזה v2 לאפליקציות הנייד (CR-027)
**נוסף.** רישום מכשיר מחזיר `server_id` ו־`relay_url`; רישום בממסר אידמפוטנטי (טלפון מוכר מקבל אותו אסימון ואינו מוגבל בקצב בחזרה);
מזהה שרת שייך למפתח הראשון שטוען לו; אסימון ממסר אחד לטלפון; סירוב בין-אתרים עם סיבה קריאה למכונה. **לא נפרס:** ה־Worker של
הממסר (צעד של הבעלים, צריך `RELAY_TOKEN_SECRET`). **איך מפעילים.** אין צורך בתוסף; האפליקציות מאמצות את v2 בגרסה הבאה.

### דפי מדריך וכלי soak
**נוסף.** דפי מדריך בעברית ל־Frigate, אימות דו-שלבי, גנרטור ומצב קיר ועדכונים עם צילומי מסך (`docs/user-guide/he/`); כלי דגימת soak
לקריאה בלבד ומנתח בעברית (`scripts/soak/README_HE.md`).

### מגבלות ידועות
כמו ב־2.2.0: הכתיבה הראשונה בפיקוח של כל מחלקת כתיבה מול Frigate אמיתי, חשבון צופה, ייצוא קטע ועוגני זמן HLS עדיין פתוחים; PTZ חסום
ב־`PTZ_RELEASED = False`; אין בנייה חתומה של Android; ממסר ההתראות לא נפרס.
