## Behaviour after installing (CHANGELOG head)
- Every access-control screen keeps the embedded WisKey panel until an administrator switches that screen to "Arx"
  (`access.ui.overview / events / people / stations`, all default `wiskey`).
- **Behaviour change:** reading people and the entry log through Arx needs `access.people.read` / `access.events.read`. A
  viewer (and an editor: neither role gains them) no longer reads people or events through the old reads
  (`/intercom/people`, `/intercom/people/{id}`, `/intercom/events` go through the filter) - nor through the native screens,
  whose tabs are not offered to them. Inside the embedded panel WisKey's own permissions decide, unchanged. Custom roles do
  not gain the new permissions. The frontend no longer calls the old people / events reads (`getIntercomEvents`,
  `getIntercomPeople`, `getIntercomPerson` in `api/intercom.ts` have no caller after S7 / S8); the routes stay, filtered
  (the person editor uses its own `/intercom/people/{id}/editor` route, unchanged).
- An installation that had already switched "אנשים" / "פעילות" / "מרכז הכניסה" to Arx shows the rebuilt screens; the native
  overview no longer shows recent activity, a last access per station, total users or pending sync (S1, D-006).
- Site and system administrators see the new Settings tab "בקרת כניסה" (`access.admin.read` at any scope); it reads the
  integration once a minute while open (server-side caches 30-60 s), never polls a device.
