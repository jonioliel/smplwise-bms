# SmplWise Arx 2.4.9 - Release notes / הערות שחרור

Source of truth for the text below: smplwise_vms/CHANGELOG.md (section 2.4.9, bilingual per item).

## 2.4.9 (pilot) — Access control in Arx, stage 1 completed: the door path (door rule, door map, station-scoped authority), people and card writes, WhatsApp messages, door schedules, live video and talk from a station, parity report and display settings - all off by default and built against fakes only
**After installing:** **three database migrations, applied automatically at start**: 0076 (messages: `intercom_messages`, `intercom_message_optout`), 0077 (station scope: the binding scope type `access_control_station`, station placement, door grant bindings) and 0078 (the door map); the sequence is now 0001..0078. **No bridge change** (0.8.0 stays; the bridge 0.8.1 is NOT part of this release, so the trusted door path is unavailable - see "owner decisions"). No new add-on option. Reload the installed web app once. **One step for the system administrator, once:** open Settings › אינטרקום › "שיוך דלתות" and apply the suggestions (or map each door by hand) - a WisKey door that is not mapped is refused ("הדלת לא מוגדרת לפתיחה") where it used to go through. **Everything new is off by default and does not switch by itself:** the schedules screen (`access.ui.schedules`, default the embedded panel), live video and talk (`access.station_media`, default `off`), WhatsApp messages (the master switch in Settings › "בקרת כניסה" › "הודעות", default off), the people and card write actions (they live in the native people screen, which stays behind `access.ui.people`), and the trusted door path (`doors.trusted_path`, off and not selectable); the editor block (`doors.editor_block`) is `blocked`. **Nothing here was run against a real WisKey, station, door, bridge, phone or Home Assistant: every check ran against fakes; live behaviour is checked in a later lab stage (slice S14) and is NOT_RUN.** **No test executes a physical door action.** The screens say "sent" with the time - never "opened" - for every physical action. **New permissions:** "access.pin.generate", "access.people.message", and "access.call" (catalogue only until now), which now gates answering / rejecting / hanging up a call, announcements and talk from a station - held by operators, site administrators and system administrators; a new built-in role "door_opener" ("פותח דלתות") = viewing + opening doors only. **Behaviour changes** (all listed below under "Behaviour changes"): the editors refuse new indirect door steps, template and universal entities count as possible doors where a WisKey door exists, wall and kiosk accounts never open doors, station-scope bindings carry door roles only, the person editor's server routes moved onto the station chain, generating a PIN needs the new permission, and calls / announcements need "access.call" instead of "access.release".
- **עברית:** אחרי ההתקנה: **שלוש מיגרציות מסד נתונים, שרצות אוטומטית בהפעלה**: 0076 (הודעות), 0077 (הרשאה לפי תחנה: סוג תחום חדש לשיוכים, מיקום תחנות, שיוכי הרשאת דלת) ו־0078 (שיוך דלתות); הרצף עכשיו 0001..0078. **אין שינוי בגשר** (נשאר 0.8.0; הגשר 0.8.1 לא כלול בגרסה הזו, ולכן הנתיב המהימן לפתיחת דלת לא זמין - ראו "החלטות הבעלים"). אין אפשרות תוסף חדשה. טוענים מחדש את אפליקציית הרשת פעם אחת. **צעד אחד למנהל המערכת, פעם אחת:** בהגדרות › אינטרקום › "שיוך דלתות" מאשרים את ההצעות (או משייכים כל דלת ידנית) - דלת של האינטרקום שלא שויכה נדחית ("הדלת לא מוגדרת לפתיחה"), בעוד שקודם היא עברה. **כל מה שחדש כבוי כברירת מחדל ולא מתחלף מעצמו:** מסך לוחות הזמנים (`access.ui.schedules`, ברירת מחדל הלוח המוטמע), וידאו חי ודיבור (`access.station_media`, ברירת מחדל כבוי), הודעות WhatsApp (המתג הראשי בהגדרות › "בקרת כניסה" › "הודעות", כבוי), פעולות הכתיבה באנשים ובכרטיסים (הן במסך האנשים של Arx, שנשאר מאחורי `access.ui.people`), והנתיב המהימן לפתיחת דלת (`doors.trusted_path`, כבוי ואי אפשר לבחור בו); חסימת העורכים (`doors.editor_block`) במצב חסום. **שום דבר מכאן לא הורץ מול WisKey, תחנה, דלת, גשר, טלפון או Home Assistant אמיתיים: כל הבדיקות רצו מול תחליפים; ההתנהגות החיה תיבדק בשלב מעבדה מאוחר יותר ועדיין לא הורצה.** **אף בדיקה לא מבצעת פעולת דלת פיזית.** בכל פעולה פיזית המסך אומר "נשלח" עם השעה - לעולם לא "נפתח". **הרשאות חדשות:** "access.pin.generate", "access.people.message", וההרשאה "access.call" (שעד עכשיו הייתה רק ברשימה), שקובעת מעכשיו מענה, דחייה וניתוק של שיחה, הכרזות ודיבור מתחנה - למפעילים, מנהלי אתר ומנהלי מערכת; תפקיד מובנה חדש "פותח דלתות" = צפייה ופתיחת דלתות בלבד. **שינויי התנהגות** (בפירוט למטה, תחת "שינויי התנהגות"): העורכים דוחים צעדי דלת עקיפים חדשים, ישויות תבנית וישויות אוניברסליות נחשבות לדלת אפשרית במקום שיש בו דלת של האינטרקום, חשבונות מסך קיר וקיוסק לעולם לא פותחים דלתות, שיוכי הרשאה לפי תחנה נושאים תפקידי דלת בלבד, נתיבי השרת של עורך האדם עברו להרשאה לפי תחנה, יצירת קוד PIN דורשת הרשאה חדשה, ושיחות והכרזות דורשות את "access.call" במקום "access.release".

### Owner decisions of 2026-10-12 applied in this release - החלטות הבעלים מ־2026-10-12

(2) The WisKey freeze is lifted; **Arx's own roles and permissions are the only authority** for actions Arx starts (no WisKey re-authentication, second factor or dual approval is added by Arx). (3) **DC / DW / PG approved:** DC (the trusted door caller, which also needs WisKey's contract appendix W1 before it can be enabled), DW (the write-protection rules: an explicit `sync_now`, "sent" and "waiting for confirmation" for an unknown result, never "done") and PG (generating a PIN: an interactive person, a dedicated permission, the value never stored). (4) WhatsApp: approved templates **and** free text, administrators edit the templates, the free-text box never inserts a PIN or any credential by itself, every send audited, sending one template to several people in stage 1. (5) Live video and talk are stage 1; talk is covered by the call permission. (6) **The trusted door path stays OFF / unavailable** until the bridge 0.8.1 is released and WisKey delivers its door consumer (W1); until then a door opens only through today's station release, with the person recorded in Arx's audit.

### The door path: one door rule, door map, station-scoped authority (CR-033) - נתיב הדלת: כלל אחד לדלת, שיוך דלתות והרשאה לפי תחנה
- **English - what was added:** a WisKey door (a lock of the intercom platforms, or a row of the door map) now opens from the devices tile, the map and home cards, the WisKey screen and the notification link **only through one rule**: "access.release" on the station's chain, or "door.unlock" on the lock entity; a deny on either wins; kiosk and wall-display accounts, viewers, unidentified and inactive users never open. "ha.entity.control" is no longer needed for a WisKey door. A new built-in role **"door_opener" ("פותח דלתות")** = "access.read" + "access.release" (not delegable by default); Settings › הרשאות gains the card "פתיחת דלתות" (user and group switches, custom-role switches; every switch says what else the door role grants: the entry log and the people directory of the intercom screen; calls and announcements need "access.call" since this release). A new binding scope type **"access_control_station"** (bindings wizard, station picker, station placement under a site or building in Settings › אינטרקום): a station binding grants nothing above or beside itself. The **door map** (Settings › אינטרקום › "שיוך דלתות") ties each WisKey lock to one station relay explicitly (a single-relay suggestion or by hand; never by name or unique id). "lock.lock" is never sent to a WisKey lock, "lock all" skips WisKey doors ("לא רלוונטי"), and a tile row of a door stays "sent" / pending until the door path writes its outcome (a status poll never turns it "confirmed"). Twelve new routes (door map, station placement, door grants card, door settings, status read, door-path inventory) - read-only or `system.configure` / `rbac.roles.manage`, confirmed and audited.
- **English - the door path is guarded, not switched on:** the transport flag `doors.trusted_path` is `off` and cannot be selected (no bridge version is accepted yet); a WisKey door is never sent through the bridge's generic `execute`, in any mode - the add-on refuses such a command before sending it (`409 wiskey_door_execute_blocked`, "not sent"). The editors (automations, scripts, scenes in typed and code mode, scene capture, the schedule editor) refuse on save a NEW step that reaches a WisKey door directly or indirectly (lock groups, device actions, called scripts, scene members, template entities) - `doors.editor_block` is `blocked` and "allowed" is not selectable. Arx-started runs of an item that reaches a WisKey door (automation run, script run, scene apply, schedule "run now", tile and map-card actions on scripts, scenes, buttons, lock groups and template entities) are refused, and so is enabling such an automation or schedule (also in a bulk enable); disabling is always allowed. Placing a WisKey lock on a map needs "door.unlock" for it (or role administration).
- **English - how to enable:** nothing to switch on. After installing, the system administrator applies the door-map suggestions once (Settings › אינטרקום › "שיוך דלתות"), then gives people the door role (Settings › הרשאות › "פתיחת דלתות") or "access.release" on the station / "door.unlock" on the lock. Rollback: remove the grants; the door map and station placement are data only.
- **עברית - מה נוסף:** דלת של האינטרקום (מנעול בפלטפורמות האינטרקום, או שורה בשיוך הדלתות) נפתחת מעכשיו מאריח ההתקנים, מכרטיסי המפה והבית, ממסך האינטרקום ומקישור ההתראה **רק בכלל אחד**: "access.release" בשרשרת של התחנה, או "door.unlock" על המנעול; הרחקה באחד מהם גוברת; חשבונות קיוסק ומסך קיר, צופים, משתמשים לא מזוהים ולא פעילים לעולם לא פותחים. "ha.entity.control" כבר לא נדרשת לדלת של האינטרקום. תפקיד מובנה חדש **"פותח דלתות"** = "access.read" + "access.release" (ללא האצלה כברירת מחדל); בהגדרות › הרשאות נוסף הכרטיס "פתיחת דלתות" (מתגי משתמש וקבוצה, מתגי תפקידים מותאמים; כל מתג אומר מה עוד תפקיד הדלת נותן: יומן הכניסות ורשימת האנשים של מסך האינטרקום; שיחות והכרזות דורשות מהגרסה הזו את "access.call"). סוג תחום חדש לשיוכים, **"תחנת בקרת כניסה"** (אשף השיוכים, בורר תחנות, מיקום תחנה תחת אתר או בניין בהגדרות › אינטרקום): שיוך לתחנה לא נותן דבר מעבר לתחנה עצמה. **שיוך הדלתות** (הגדרות › אינטרקום › "שיוך דלתות") קושר כל מנעול של האינטרקום לממסר אחד של תחנה במפורש (הצעה לממסר יחיד או ידנית; לעולם לא לפי שם או מזהה). הפקודה "נעילה" לא נשלחת לעולם למנעול של האינטרקום, "נעל הכול" מדלג על דלתות כאלה ("לא רלוונטי"), ושורת אריח של דלת נשארת "נשלח" / ממתינה עד שנתיב הדלת כותב את התוצאה (בדיקת מצב לעולם לא הופכת אותה ל"אושר"). שנים־עשר נתיבי שרת חדשים (שיוך דלתות, מיקום תחנה, כרטיס שיוכי הדלת, הגדרות דלתות, קריאת מצב, מצאי נתיב הדלת) - קריאה בלבד או לפי הרשאת הגדרת מערכת / ניהול תפקידים, באישור מפורש וביומן.
- **עברית - הנתיב שמור, לא מופעל:** מתג ההעברה `doors.trusted_path` כבוי ואי אפשר לבחור בו (עוד אין גרסת גשר שמתקבלת); דלת של האינטרקום לא נשלחת לעולם דרך הפקודה הכללית של הגשר, בשום מצב - התוסף דוחה פקודה כזו לפני השליחה (`409 wiskey_door_execute_blocked`, "לא נשלח"). העורכים (אוטומציות, סקריפטים, סצנות בעורך ובקוד, לכידת סצנה, עורך לוחות הזמנים) דוחים בשמירה צעד **חדש** שמגיע לדלת של האינטרקום ישירות או בעקיפין (קבוצות מנעולים, פעולות התקן, סקריפטים שנקראים, חברי סצנה, ישויות תבנית) - `doors.editor_block` במצב חסום ואי אפשר לבחור "מותר". הרצות ש־Arx מתחיל של פריט שמגיע לדלת של האינטרקום (הרצת אוטומציה, הרצת סקריפט, הפעלת סצנה, "הרץ עכשיו" בלוח זמנים, פעולות אריח וכרטיס מפה על סקריפטים, סצנות, כפתורים, קבוצות מנעולים וישויות תבנית) נדחות, וגם הפעלה של אוטומציה או לוח זמנים כאלה (גם בהפעלה קבוצתית); כיבוי מותר תמיד. הצבת מנעול של האינטרקום על מפה דורשת "door.unlock" עליו (או ניהול תפקידים).
- **עברית - איך מפעילים:** אין מה להפעיל. אחרי ההתקנה מנהל המערכת מאשר פעם אחת את הצעות שיוך הדלתות (הגדרות › אינטרקום › "שיוך דלתות"), ואז נותן לאנשים את תפקיד פותח הדלתות (הגדרות › הרשאות › "פתיחת דלתות") או "access.release" על התחנה / "door.unlock" על המנעול. החזרה לאחור: מסירים את ההרשאות; שיוך הדלתות ומיקום התחנות הם נתונים בלבד.

### Door schedules in Arx, view only (CR-036 S9) - לוחות זמנים לדלתות ב־Arx, לצפייה בלבד
- **English - what was added:** the native screen "לוחות זמנים" (`#/wiskey/schedules`), stage 1, view only. Per door (of the stations the caller may see with their technical part): the hold-open program as a week grid (Sunday first), its state (active / paused / being removed / error / saved draft / unknown), the execution word of the last command ("מוחזק פתוח · התחנה אישרה קבלה" - never "open"), the weekly lines, the specific dates, when it was last checked in the station's zone and the public-code pill (set / not set / unknown - presence only, never a value). A table across all doors (from 820 px); on a phone a door chip opens a sheet. For installation-wide holders of "access.stations.read": the schedule library (name, version, hours, holidays, "proposed for <stations>") and the deployment proposals, which always say "לא הוחל על התחנה" - nothing is applied. ### Behaviour changes - שינויי התנהגות
- **English:** (1) **Editors refuse indirect door steps:** on save, a NEW step that reaches a WisKey door through a lock group, device action, called script or automation, scene member or template entity is refused (`doors.editor_block` = `blocked`); a save that only keeps what was already there is allowed. (2) **Template and universal entities count as possible doors where a WisKey door exists:** any service on such an entity is judged as a possible door - tile and map-card actions, Arx-started runs and bulk actions are refused or leave them out (an availability cost on installations with many template entities; where no WisKey door exists nothing is judged). (3) **Wall-display and kiosk accounts never open doors** (`wall_account`). (4) **Station-scope bindings carry door roles only:** an ALLOW binding at the new station scope accepts only roles made of "access.read", "access.release" and the per-station access permissions the screens evaluate ("access.stations.read", "access.events.read", "access.events.export", "access.people.read", "access.people.sensitive", "access.people.manage", "access.admin.read", "access.cards.capture", and - owner decision of 2026-10-13 - "access.pin.generate", "access.people.message", "access.call"); deny bindings stay possible. (5) **Site administrators and the station chain:** a site-scoped site administrator now passes the entry gate of the person editor and is then held to the person's stations - the station chain, not the installation, is the scope. (6) The person editor's server routes (editor context, person, PIN generation, create, update, delete, card capture) moved from the installation-wide gate to the station chain; **generating a PIN needs the new "access.pin.generate"**, so a holder of "access.people.manage" who is neither site nor system administrator loses PIN generation until it is granted. (7) An unmapped WisKey lock is refused until the door map has it. (8) "lock.lock" is never sent to a WisKey lock; "lock all" skips WisKey doors; scheduled lock jobs on them are listed as never working. (9) Arx-started runs of an item that reaches a WisKey door, and enabling such an item, are refused with a plain message ("... פתיחת דלתות מאוטומציה עדיין לא נתמכת"; on enable also "אפשר לכבות אותו"); disabling stays allowed. (10) A door's tile row never turns "confirmed" by a poll - it stays pending and becomes "unknown" after the confirmation window. (11) Placing a WisKey lock on a map needs "door.unlock" for it (or role administration). (12) The WhatsApp dialog of 2.4.8 ("not active" - a user interface over a fake) now has a real send path behind the master switch, which is off. (13) **Calls and announcements move to "access.call"** (owner decision 2026-10-13): answering, rejecting and hanging up a call, announcements and the TTS engine list need "access.call" on the station (operators, site and system administrators hold it by default - operators gain these actions); "access.release" alone - the door role "door_opener" or a custom role with the door grant only - no longer answers calls or announces: add "access.call" to such a custom role where needed.
