# 2.7.2 - header dropdown placement: layout fixes and a real sweep

Branch `pilot/DD-LAYOUT272` (based on `pilot/TKGATEFIX9`). Setting `ui.dd_place` (1-4, installation default plus personal
override). **The default stays 1** (own row above the title); nothing changes for an installation that never touched the setting.
Placements 2-4 apply only from 1100 px; below that every placement draws as the own row.

## How the shell decides now (`shell/sw-app.ts` `fitDd`, `shell/dd-place-fit.ts`)

- Runs after every render and every 1.2 s while a screen loads, wide screens only, placements 2-4 only.
- Reads the screen's header through the shadow roots: the first `<h1>` (glyph box) and every visible control of the top rows (buttons,
  links, fields, selectors, tab rows, headings). Subtrees below the chips' band are skipped, so the walk stays short on long pages.
- Collision safety net, now against every control (not only the title) and the corner: if a chip still overlaps something (or leaves the
  viewport) for 0.9 s, the route falls back to placement 1 and `data-dd-fallback="collision"` is set. A swept screen that falls back by
  collision fails the sweep; the safety net itself has its own test.

## Tests

- `frontend/tests/layout-dd-place.spec.ts`: 5 screens (WisKey center, tickets list, settings / tickets, devices area, multimedia players)
  x placements 1-4 x desktop 1440 / tablet 1024 / phone 390, each on a mocked backend with `ui.tabs_mode = dropdown` merged into the
  mock's settings, so the chips are guaranteed; a missing chip or title fails. DOM-measured: no overlap between a chip and the title,
  any top-row control or the corner; inside the viewport; no horizontal overflow; RTL position per placement (2 next to the corner,
  3 directly after the title or the controls that follow it, 4 at the start edge); the effective placement and `data-dd-fallback`.
  Plus: the declared table matches the shell, a personal placement overrides the installation default, the collision safety net, and
  a negative test that the assertions throw when no chips are drawn.
- Needs the Vite dev server (the players harness imports `/src`): see the header of the spec.
