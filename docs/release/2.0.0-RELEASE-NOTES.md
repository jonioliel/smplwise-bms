# SmplWise Arx 2.0.0 - Release notes / הערות שחרור

Source of truth for the text below: smplwise_vms/CHANGELOG.md.

## 2.0.0 (pilot) — Recorder health monitoring; playback stall detection and automatic resume; the floor filter of the multimedia pages as the shared (capsule-capable) dropdown; friendly integration names

**After installing:** no database migration (the last one stays `0055_multi_recorder`), the bridge integration stays **0.6.2**, no
platform restart is needed. Reload the installed web app once. The version jumps from 0.1.163 to 2.0.0 (there is no 0.1.164); the
upgrade path is the usual add-on update.

### Recorder health monitoring (CR-026) - הגדרות › בריאות ועבודות

**What was added.** Every ready, enabled recorder is checked in the background (default once a minute), **read-only**: the monitor
sends device reads only and never writes to a recorder.

| What is checked | Recorders | New alert source |
|---|---|---|
| Is it answering | all vendors | `recorder.unreachable` (critical, managers, email; announced after 2 minutes) |
| How fast it answers | all vendors | `recorder.slow` (info, inbox only; above 1,500 ms for 5 minutes) |
| Disk state (read-only, locked, unformatted, error, no disk) and disk alarms | Provision-ISR | `recorder.disk` |
| Disk-fill forecast (free space trend over 48 h) | Provision-ISR | `recorder.disk_space` - **off by default** |
| Recording per camera | Provision-ISR | `recorder.recording` - by default only faults the recorder itself reports |
| Clock drift against the system clock | Provision-ISR | `recorder.clock` (above 60 s for 10 minutes) |
| Pinned HTTPS certificate expiry | Provision-ISR over pinned HTTPS | `recorder.certificate` (30 days before; critical once expired) |

A disconnected camera stays the existing "camera unavailable" alert (`camera.offline`), now noticed within a minute and resolved
within a minute of reconnecting.

**Defaults (owner decisions of 2026-10-05).**
- Recording: only recording faults the recorder reports are alerts. "A camera stopped recording" is judged only on recorders you mark
  as **recording continuously** - a per-recorder choice, **off** for every recorder (many recorders record on motion only).
- Disk-fill forecast: **off** (`disk_fill_days` = 0). A recorder that overwrites its oldest recordings is always full; that is not a
  fault by itself.
- Hikvision recorders get reachability and latency now; their disk / recording / clock detail comes after Provision-ISR.

**Rules against noise.** A condition must hold before it is announced (the policy's hold); numeric thresholds have a band (latency
off below 70 %, clock drift off below half, disk fill off above 1.5x); a recovery is announced only after 2 minutes of being clear;
a part that could not be read keeps its open alerts open and opens none; one root cause, one alert (a disconnected camera is not
also "not recording"; the primary recorder's "not answering" is folded into the existing recorder-offline alert).

**Bug fixed.** The system health report grid overflowed a 320 px phone.

**API.** `GET /api/v1/recorder-health` (recorder readers), `POST /api/v1/recorder-health/check` (system.configure, at most every
15 s), `GET|PUT /api/v1/recorder-health/settings` (system.configure; audited as `recorder_health.settings`). 531 routes in total.

### The floor filter of the multimedia pages is the shared dropdown; friendly integration names

- **Floor filter.** The "כל הקומות" menu of the players and screens pages is now the shared dropdown (the same component, style -
  including capsule - size, ring and panel width as every other dropdown of the multimedia group), with an icon and a count per floor
  and a divider after "הכל". The hand-built menu is gone; nothing else on those pages changed.
- **Friendly integration names.** הגדרות › מולטימדיה shows "Sonos", "Google Cast (Chromecast)", "Samsung (טלוויזיה)", "LG webOS
  (טלוויזיה)" and so on instead of the raw platform id - in the list cell, the filter chips, grouping, sorting and device connections.
  The raw id stays in the hover text and in the search; an unknown id is shown as it is.
- Every remaining hand-built menu was reviewed and the reason it stays is recorded in `docs/changes/DD6-CAPSULE-CONVERSION.md`
  (the notification centre's source filter stays as it is by owner decision).

### Recordings: stall detection and automatic resume (every recorder vendor) - הקלטות

**What was added.** When the recording source stops (a network drop, a recorder stall), the playback screen no longer keeps "playing" a
frozen picture in silence:
- no media progress for **5 s** while it should be playing (or a lost connection) shows **"מתחבר מחדש"** on the picture at once;
- after a 2 s grace period (in case the media server recovers by itself) it resumes from the frozen position, the same way as a seek
  (a new generation of the same session; the old stream is deleted - only `smplwise_pb_*` names);
- failed attempts back off (3 s, then 6 s; an attempt with no progress within 20 s has failed); after **3** attempts the picture says
  **"הניגון נעצר"** with **"נסה שוב"**, and the session is released so nothing keeps pulling from the recorder;
- a synchronized multi-camera group resumes as a whole (all members or none);
- pause, scrubbing, slow motion and a slow first start are never a stall; a permission or quota refusal is never retried; the end of
  the range still continues to the next segment. The diagnostics line shows the attempts.
Works the same for Hikvision and Provision-ISR (it watches the player's media clock, not the vendor).

**Settings / API.** Two new installation settings in `GET|PATCH /api/v1/settings`: `playback.stall_s` (2-30, default 5) and
`playback.auto_resume_attempts` (0-5, default 3; 0 = detect and stop without an automatic attempt). No new route (531 routes).

### How to turn it on and use it (English)
1. Install the update and reload the web app. Nothing else is required: recorder health monitoring starts on its own.
2. See the recorders: הגדרות › בריאות ועבודות › "מקליטים" - one card per recorder (connection, disks, recording, cameras, clock,
   certificate; a part the vendor does not report is not shown) and "בדוק עכשיו" for an immediate check.
3. Settings (system administrators): the same screen › "ספי התראה למקליטים":
   - **continuous recording** - tap the chip of each recorder that records all the time (off for all by default); then "not recording
     for N minutes" (`recording_gap_min`, default 30) is alerted for its connected, enabled cameras;
   - **disk-fill forecast** - set "days" above 0 to be told when the disks will fill within that many days (default 0 = off);
   - clock drift (60 s), latency (1,500 ms), certificate days (30), clear period (120 s), check interval (60 s).
4. Who is told and how: הגדרות › התראות - the seven new sources are ordinary notification policies (severity, channels, recipients,
   hold can be changed there).
5. Capsule floor filter: nothing to switch on; it follows the multimedia group's dropdown style. To see the capsule: הגדרות ›
   לשוניות › "סגנון תפריט נפתח" → **קפסולה** (the group in "תפריטים נפתחים" or "משולב" mode in "תצוגת לשוניות").
6. Friendly integration names: nothing to switch on (הגדרות › מולטימדיה).
7. Playback stall detection: **on by default**. To tune it: הגדרות › כללי › וידאו ומדיה → "זיהוי תקיעה בניגון (שניות)" (default 5)
   and "ניסיונות חיבור מחדש אוטומטיים" (default 3; 0 = only detect and stop) → "שמור".

### Known limits
- Playback stall detection was tested with a mocked backend and a stubbed media clock; the recovery time after a **real** network drop
  on a real recorder is not measured yet. The defaults come from the measured first-frame times (7.7 s warm, 18.6 s cold) and the
  measured 8.6 s resume.
- Domus skin, dark: the "נסה שוב" button of the stopped-playback picture has low contrast. It comes from the skin's primary button
  colour, which other screens share; it is left for the skin work, not changed here.
- Recorder health was tested against a fake Provision device for every alert, and with one live **read-only** pass on a real
  Provision-ISR recorder (answering, disks, recording, cameras, clock, certificate all read; nothing written). No alert was provoked on a
  real device.
- Hikvision recorders: reachability and latency only.
- Readings are kept in memory; after a restart the forecast history starts again (open alerts are stored and stay open).

## עברית — 2.0.0: ניטור בריאות המקליטים; זיהוי תקיעה בניגון וחידוש אוטומטי; סינון הקומות בדפי המולטימדיה כתפריט הנפתח המשותף (גם בסגנון קפסולה); שמות ידידותיים לאינטגרציות

**אחרי ההתקנה:** אין מיגרציה (האחרונה נשארת `0055_multi_recorder`), רכיב החיבור נשאר **0.6.2**, אין צורך להפעיל מחדש את
התשתית. טוענים מחדש את אפליקציית הרשת פעם אחת. הגרסה קופצת מ־0.1.163 ל־2.0.0 (אין 0.1.164); העדכון רגיל.

### ניטור בריאות המקליטים - הגדרות › בריאות ועבודות

**מה נוסף.** כל מקליט פעיל ומוכן נבדק ברקע (ברירת מחדל: פעם בדקה), **בקריאה בלבד** - לא נכתב דבר למקליט.

| מה נבדק | מקליטים | מקור התראה חדש |
|---|---|---|
| האם המקליט עונה | כל היצרנים | `recorder.unreachable` (קריטי, למנהלים, גם בדוא"ל; אחרי 2 דקות) |
| מהירות התגובה | כל היצרנים | `recorder.slow` (מידע, בתיבה בלבד; מעל 1,500 מ"ש במשך 5 דקות) |
| מצב הדיסקים (לקריאה בלבד, נעול, לא מאותחל, תקלה, אין דיסק) והתרעות דיסק | Provision-ISR | `recorder.disk` |
| תחזית מילוי הדיסק (מגמת המקום הפנוי ב־48 שעות) | Provision-ISR | `recorder.disk_space` - **כבוי כברירת מחדל** |
| הקלטה לכל מצלמה | Provision-ISR | `recorder.recording` - כברירת מחדל רק תקלות שהמקליט עצמו מדווח |
| סטיית שעון מול שעון המערכת | Provision-ISR | `recorder.clock` (מעל 60 שניות במשך 10 דקות) |
| תוקף תעודת ה־HTTPS הנעוצה | Provision-ISR ב־HTTPS נעוץ | `recorder.certificate` (30 יום לפני; קריטי כשפג) |

מצלמה מנותקת נשארת ההתראה הקיימת "מצלמה לא זמינה" (`camera.offline`), ועכשיו מזוהה תוך דקה ונסגרת תוך דקה מהחיבור מחדש.

**ברירות מחדל (החלטות הבעלים מ־5.10).**
- הקלטה: רק תקלות הקלטה שהמקליט מדווח הן התראה. "מצלמה הפסיקה להקליט" נבדק רק במקליטים שסומנו **הקלטה רציפה** - בחירה לכל
  מקליט, **כבויה** בכולם (מקליטים רבים מקליטים בתנועה בלבד).
- תחזית מילוי דיסק: **כבויה** (0 ימים). מקליט שדורס הקלטות ישנות תמיד מלא, וזו לא תקלה בפני עצמה.
- מקליטי Hikvision מקבלים כרגע בדיקת תקשורת וזמן תגובה; פירוט דיסקים, הקלטה ושעון יגיע אחרי Provision-ISR.

**נגד הצפת התראות.** מצב חייב להימשך לפני הודעה; לספים מספריים יש טווח ביטחון; הודעת חזרה רק אחרי 2 דקות תקינות; חלק שלא נקרא
לא סוגר התראה פתוחה ולא פותח חדשה; סיבה אחת - התראה אחת.

**תיקון.** רשת כרטיסי בריאות המערכת גלשה מרוחב טלפון של 320 פיקסלים.

### סינון הקומות בדפי המולטימדיה כתפריט הנפתח המשותף; שמות ידידותיים לאינטגרציות
- **סינון הקומות** בדפי הנגנים והמסכים הוא עכשיו התפריט הנפתח המשותף (אותו רכיב, אותו סגנון כולל קפסולה, גודל, עובי טבעת ורוחב
  לוח כמו כל תפריט נפתח בקבוצת המולטימדיה), עם סמל ומספר לכל קומה וקו מפריד אחרי "הכל". התפריט הבנוי ידנית הוסר; שום דבר אחר לא השתנה.
- **שמות ידידותיים לאינטגרציות** בהגדרות › מולטימדיה: "Sonos", "Google Cast (Chromecast)", "Samsung (טלוויזיה)", "LG webOS (טלוויזיה)"
  וכו' במקום המזהה הגולמי - בתא הרשימה, בכפתורי הסינון, בקיבוץ, במיון ובחיבורי ההתקן. המזהה הגולמי נשאר בטקסט הריחוף ובחיפוש.

### הקלטות: זיהוי תקיעה בניגון וחידוש אוטומטי (לכל סוגי המקליטים)
כשמקור ההקלטה נעצר (ניתוק רשת, תקיעה במקליט) מסך ההקלטות כבר לא ממשיך "לנגן" תמונה קפואה בשקט:
- אחרי **5 שניות** בלי התקדמות (או ניתוק חיבור) מופיע על התמונה **"מתחבר מחדש"**;
- אחרי 2 שניות נוספות הנגן ממשיך אוטומטית מאותה נקודה, באותו מנגנון של קפיצה בציר הזמן (הזרם הקודם נמחק);
- ניסיון שנכשל ממתין 3 ואז 6 שניות; אחרי **3** ניסיונות מופיע **"הניגון נעצר"** עם **"נסה שוב"**, והסשן משוחרר כדי שלא ימשיך למשוך
  מהמקליט;
- ניגון מסונכרן של כמה מצלמות ממשיך כקבוצה אחת - כולן או אף אחת;
- השהיה, גרירה בציר, הילוך איטי ופתיחה איטית אינם תקיעה; חסימת הרשאה או מכסה לא מנוסות שוב. שורת האבחון מציגה את הניסיונות.
עובד אותו דבר ב־Hikvision וב־Provision-ISR.

**הגדרות.** שתי הגדרות חדשות: "זיהוי תקיעה בניגון (שניות)" (2-30, ברירת מחדל 5) ו"ניסיונות חיבור מחדש אוטומטיים" (0-5, ברירת מחדל 3;
0 = רק זיהוי ועצירה).

### איך מפעילים (עברית)
1. מתקינים את העדכון וטוענים מחדש את אפליקציית הרשת. אין צורך בשום דבר נוסף: ניטור המקליטים מתחיל לבד.
2. צפייה: הגדרות › בריאות ועבודות › "מקליטים" - כרטיס לכל מקליט (חיבור, דיסקים, הקלטה, מצלמות, שעון, תעודה) וכפתור "בדוק עכשיו".
3. הגדרות (מנהל מערכת): באותו מסך › "ספי התראה למקליטים":
   - **הקלטה רציפה** - מסמנים את כפתור כל מקליט שמקליט כל הזמן (כבוי בכולם כברירת מחדל); אז "לא מקליט N דקות" (ברירת מחדל 30)
     יתריע על המצלמות המחוברות שלו;
   - **תחזית מילוי דיסק** - מגדירים "ימים" מעל 0 כדי לקבל התראה כשהדיסקים יתמלאו בתוך מספר הימים הזה (0 = כבוי);
   - סטיית שעון (60 שניות), זמן תגובה (1,500 מ"ש), ימים לתוקף תעודה (30), זמן תקינות לפני חזרה (120 שניות), מרווח בדיקה (60 שניות).
4. מי מקבל ואיך: הגדרות › התראות - שבעת המקורות החדשים הם מדיניות התראה רגילה (חומרה, ערוצים, נמענים, המתנה).
5. סינון קומות בקפסולה: אין מה להפעיל; הוא הולך לפי סגנון התפריט הנפתח של קבוצת המולטימדיה. לקפסולה: הגדרות › לשוניות ›
   "סגנון תפריט נפתח" ← **קפסולה** (הקבוצה במצב "תפריטים נפתחים" או "משולב" ב"תצוגת לשוניות").
6. שמות ידידותיים: אין מה להפעיל (הגדרות › מולטימדיה).
7. זיהוי תקיעה בניגון: **פעיל כברירת מחדל**. לכוונון: הגדרות › כללי › וידאו ומדיה ← "זיהוי תקיעה בניגון (שניות)" ו"ניסיונות חיבור
   מחדש אוטומטיים" ← "שמור".

### מגבלות
- זיהוי התקיעה נבדק מול שרת מדומה ושעון מדיה מדומה; זמן ההתאוששות אחרי ניתוק רשת **אמיתי** מול מקליט אמיתי עדיין לא נמדד.
- סקין Domus כהה: לכפתור "נסה שוב" בתמונת "הניגון נעצר" יש ניגודיות נמוכה. זה בא מצבע הכפתור הראשי של הסקין, שמשותף למסכים אחרים;
  נשאר לעבודת הסקינים ולא שונה כאן.
- ניטור המקליטים נבדק מול מכשיר Provision מדומה לכל התראה, ובבדיקה חיה אחת **בקריאה בלבד** מול מקליט Provision-ISR אמיתי (כל החלקים
  נקראו, דבר לא נכתב). לא הופעלה התראה מול מכשיר אמיתי.
- מקליטי Hikvision: בדיקת תקשורת וזמן תגובה בלבד.
- הקריאות נשמרות בזיכרון; אחרי הפעלה מחדש היסטוריית התחזית מתחילה מחדש (התראות פתוחות נשמרות ונשארות פתוחות).
