## 2.12.0 (pilot) — Bridge-key rotation gets its own permission and pauses remote door opening while it runs; the Arx side of WhatsApp template send is built and shipped OFF (nothing calls it). Nothing new is switched on.
**After installing:** no database migration (still 0001..0145), no bridge change (stays 0.9.5), no new route (API inventory unchanged at 1196). One new permission `bridge.key.rotate` exists (system administrators only). Nothing needs to be switched on or off.
- **עברית:** אחרי ההתקנה: אין מיגרציה חדשה של מסד הנתונים (נשאר 0001..0145), אין שינוי בגשר (נשאר 0.9.5), אין נתיב API חדש. נוספה הרשאה אחת, `bridge.key.rotate`, למנהלי מערכת בלבד. אין מה להפעיל או לכבות.

### What was changed - מה השתנה
- **English:** New system permission `bridge.key.rotate` (HMACACT2-295): starting a bridge-key rotation and resuming a stuck one now need it. It is held by the system administrator role only, is sensitive, cannot be delegated, cannot be added to a custom role, and still asks for the local second factor. The general "system settings" permission alone is no longer enough.
- **עברית:** הרשאת מערכת חדשה `bridge.key.rotate` (HMACACT2-295): התחלת החלפת מפתח הגשר והמשכה של החלפה תקועה דורשות אותה. היא שמורה לתפקיד מנהל מערכת בלבד, רגישה, לא ניתנת להאצלה, לא ניתן להוסיף אותה לתפקיד מותאם, והיא עדיין דורשת גורם שני מקומי. הרשאת "הגדרות מערכת" הכללית לבדה כבר לא מספיקה.
- **English:** Remote door opening pauses during a bridge-key rotation (HMACACT2-295): while a rotation is unfinished (or waits for repair) and the rotation switch is on, new trusted door calls (door open, door status, capture-lease messages) are refused with 503 `bridge_key_rotating` and "not sent" in the audit, or held in the lease queue and retried; nothing is dropped silently and no command is signed while the key set may be half switched. Turning the rotation switch off lifts the pause. This matters only during a key rotation (minutes); at every other time doors behave exactly as before.
- **עברית:** פתיחת דלתות מרחוק מושהית בזמן החלפת מפתח הגשר (HMACACT2-295): כל עוד החלפה לא הסתיימה (או ממתינה לתיקון) ומתג ההחלפה דלוק, קריאות דלת חדשות (פתיחה, מצב דלת, הודעות חכירת צילום) נדחות עם 503 `bridge_key_rotating` ו"לא נשלח" ביומן, או מוחזקות בתור החכירות ומנוסות שוב; שום דבר לא נזרק בשקט ושום פקודה לא נחתמת בזמן שסט המפתחות עשוי להיות באמצע מעבר. כיבוי מתג ההחלפה מבטל את ההשהיה. זה רלוונטי רק בזמן החלפת מפתח (דקות); בכל זמן אחר הדלתות מתנהגות בדיוק כמו קודם.
- **English:** WhatsApp template send, Arx side (W11TPL-295), shipped OFF and not called by anything: a template registry (references only, never bodies), the switch `messaging.template_send` (default OFF), admission rules (consent, slots, pacing budget, window), a request/answer model where an unclear answer is "unknown" and never retried, and a transport that is unwired in production. The permit `TEMPLATE_SEND_SUPPORTED` stays False, so even with the switch on nothing is sent. No route, screen or WisKey call uses it yet; it waits for WisKey to define the send command.
- **עברית:** שליחת תבנית WhatsApp, צד Arx (W11TPL-295), נשלחת כבויה ושום דבר לא קורא לה: רישום תבניות (הפניות בלבד, אף פעם לא גוף ההודעה), המתג `messaging.template_send` (ברירת מחדל כבוי), כללי קבלה (הסכמה, משבצות, תקציב קצב, חלון), מודל בקשה/תשובה שבו תשובה לא ברורה היא "לא ידוע" ואינה מנוסה שוב, ותעבורה שאינה מחוברת בייצור. ההיתר `TEMPLATE_SEND_SUPPORTED` נשאר False, ולכן גם כשהמתג דלוק לא נשלח דבר. אין נתיב, מסך או קריאת WisKey שמשתמשים בזה עדיין; זה ממתין שיוגדר ב-WisKey פקודת השליחה.

### Bugs fixed - באגים שתוקנו
- **English:** No user-visible bug is fixed in this release. The door pause closes a gap: before it, a door command could be signed while the bridge key was half switched during a rotation.
- **עברית:** אין בגרסה הזו תיקון באג שהמשתמש רואה. ההשהיה של הדלתות סוגרת פער: קודם פקודת דלת יכלה להיחתם בזמן שמפתח הגשר היה באמצע מעבר בהחלפה.

### What is OFF by default and how to enable - מה כבוי כברירת מחדל ואיך מפעילים
- **English:** Template send is OFF and cannot be enabled from the product: the switch `messaging.template_send` defaults to OFF and the permit is False in the build; enabling needs a later release that flips the permit together with a WisKey command. The bridge-key rotation switch `bridge.key_rotation` is unchanged (default off; the door pause applies only when it is on and a rotation is running). To rotate the key, a system administrator uses the "מפתח הגשר" card in Settings; other roles no longer can. Everything that was OFF in 2.11.0 and 2.11.1 stays OFF.
- **עברית:** שליחת תבנית כבויה ואי אפשר להפעיל אותה מהמוצר: המתג `messaging.template_send` כבוי כברירת מחדל וההיתר False בבילד; הפעלה דורשת גרסה מאוחרת יותר שהופכת את ההיתר יחד עם פקודת WisKey. מתג החלפת המפתח `bridge.key_rotation` לא השתנה (כבוי כברירת מחדל; ההשהיה חלה רק כשהוא דלוק וההחלפה רצה). להחלפת מפתח, מנהל מערכת משתמש בכרטיס "מפתח הגשר" בהגדרות; תפקידים אחרים כבר לא יכולים. כל מה שהיה כבוי ב-2.11.0 וב-2.11.1 נשאר כבוי.
