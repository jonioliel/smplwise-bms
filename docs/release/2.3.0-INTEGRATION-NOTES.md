## Conflicts and how they were resolved
- `services/frigate_control_svc.py::revert` (NN5-F2b vs sec-info-followups I2): I2 claims the change row (compare-and-set to
  `reverted`) before any Frigate write and gives the claim back on a stale / not-reversible / failed undo; F2b added the code
  `frigate_object_not_arx` to the re-raised codes, kept the trailing `UPDATE ... status = 'reverted'` and marks the first supervised
  write of native kinds. Resolution: the I2 claim stays the only status change (the trailing UPDATE is dropped, the claim already set
  it), `frigate_object_not_arx` joins the codes that release the claim and re-raise, and `native.mark_first_write` runs after the log
  row for native kinds. Both behaviours kept.
- Migration-list tests (`test_migrations.py`, `test_notify_core.py`, `test_media_api.py`, `test_media_players_api.py`): each branch
  appended only its own number (`..., 67, 69` / `..., 67, 70`). Resolved to the union `..., 66, 67, 68, 69, 70` with the notes of all
  three. No other test asserts a migration list (grep of `migrate() ==`).
- `.gitignore` (M074-gate vs apk-in-addon from 2.2.1): both blocks kept (APK / signing exclusions and `frontend/visual-out/`).
- `scripts/gate/release_gate.py` / `selftest_gate.py` (M074-gate was cut before the 2.2.1 retry-matching fix): git merged without a
  conflict; verified after the merge that the retry is still keyed by `(file, line, title)` and the `param_fail` self-test case is
  present, and that the visual step is ON by default as a WARNING (`GATE_VISUAL` unset = `warn`; `--visual-block`, `--no-visual`),
  exactly as the branch defines it. The run-smart-fixture change (gate reads `fixture_specs.json`) merged in beside it.
- `contracts/API_INVENTORY.md`: health-process-stats and TFA2 had hand-edited rows; regenerated on the runner with
  `scripts/api_inventory.py` on the merged tree (version 2.3.0): 699 routes = 680 (2.2.1) + 2 second-factor overrides + 17 Frigate F2b.
- Role catalogs: only NN5-F2b changed them (`analytics.exports`, `analytics.cases` in `roles.json` and
  `contracts/examples/role-catalog.design.json`, identical lists; labels in `routers/access.py`). No other branch touched them.
