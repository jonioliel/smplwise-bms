## Gate 1 - integ/200 @ 42a56ec2 (before the playback merge): FAIL, two causes, both fixed
Tier L, started 2026-10-05 01:42 UTC, finished after 61 min. Counts: backend 5127 passed / 0 failed (the `test_multi_nvr` flake
above did not recur); preview 4870 passed / 1 failed; dev 580 passed / 2 failed; pixel 16, fixture 15, tsc, build, release_check
green. Count-drop check ok in every category against the refreshed baseline (ratios 0.997-1.005).

1. **Real regression, from `pilot/ui-small-0164`** - `layout-bubble-screens.spec.ts:166` "players and screens" (full and lite),
   both runs and the retry alone: `[target] button.chip "קומות: כל הקומות (16)" - 144x32 < 44` on the players and screens pages at
   320 px (bubble skin, touch dial 44). The hand-built `.floorbtn` it replaced was in the bubble skin's target list
   (`media-glass.ts` `mediaBubbleKnobs`: min-block-size = touch dial, 44 px at <= 1100 px); `sw-dropdown`'s chip is 32 px with a 44 px
   `::after` hit area, which the guard does not count (it measures the box). The branch's own `layout-media-floor-dropdown` spec had
   accepted the 32 px chip by design, but the bubble guard is the skin's rule, so the guard stays as it is and the page was fixed:
   **`022cb811`** adds `sw-dropdown[data-floor-menu]` to both bubble target lists; the dropdown host is an inline flex box, so the
   chip stretches to the minimum in every dropdown style and size. The component is unchanged (other pages' dropdowns are not affected).
2. **Pre-existing test race, not from this release** - `unit-plan-3d-quality.spec.ts:265` "the thumbnail strip" on the **mobile**
   project only (`thumbnailCount` expected 2, received 0), also alone. The same spec on `origin/main` (0.1.163) failed 1 of 3 repeats
   on mobile on the runner; no 2.0.0 branch touches the 3D view; no clock dependence. Cause: the spec's `set()` hands over a new
   thumbnail description, the cache empties at once and refills in the next animation frame, and the spec read the count once right
   after the buttons appeared. **`7f4aaa1a`** polls the count (`expect.poll`); what is asserted is unchanged (exactly the two listed
   levels end up cached). Not a whitelist and not a softer check.
