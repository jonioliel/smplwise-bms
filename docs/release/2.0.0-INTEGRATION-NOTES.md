## Conflict resolutions

The branch was built on an earlier `pilot/provision-wiring` and merged its head `c4497123`; everything from that base is already in
0.1.163, so only the branch's own 9 commits came in.
- `smplwise_vms/CHANGELOG.md`: the branch still had the pre-release `## Unreleased` entry whose next heading was
  `### Multi-NVR - one system, several recorders`, while main has the released `## 0.1.163 (pilot)` entry with
  `### Several recorders in one system (CR-024)` over the same text. Kept the branch's CR-026 section as the new `## Unreleased`
  entry on top, dropped its stale multi-NVR heading, and kept the released 0.1.163 entry exactly as released below it.
- `contracts/API_INVENTORY.md`: header line only (0.1.163 / 527 routes vs the branch's 0.1.161 / 526). Regenerated with
  `scripts/api_inventory.py`: **531 routes** (527 + the four `/recorder-health` routes).
- Auto-merged and checked by hand: `docs/changes/CR-025-PROVISION-ISR.md`, `frontend/src/screens/system-diagnostics.ts`,
  `smplwise_vms/backend/smplwise/main.py` (router + poller start), `services/recorders/provision_isr.py` (`read_health`,
  `certificate_facts`, `clock_drift`, `peer_certificate.not_after` next to 0.1.163's request-connection pinning).
- **Migrations:** the branch adds none (checked: no file under `smplwise_vms/backend/smplwise/migrations` in the diff); thresholds
  are one JSON value in `settings`. Sequence stays 0001..0055, last `0055_multi_recorder`.
- `tests/conftest.py`: `SW_RECORDER_HEALTH=0` so no poller thread runs in tests (tests call `probe` / `poll_once` / `tick`).

### 2. ui-small-0164 (433ed1d5, built from 0.1.162)
- `smplwise_vms/CHANGELOG.md`: the branch put "## Unreleased (UI, small items)" and its Hebrew twin above the 0.1.162 entry. They
  became the subsection "Floor filter as the shared dropdown; friendly integration names" of the single 2.0.0 entry, after the recorder

- Frontend files (`multimedia-players.ts`, `multimedia-screens.ts`, `media-page.ts`, `media-glass.ts`, `media-admin-list*.ts`) merged

### 3. playback-stall-detection - not merged
`origin/pilot/playback-stall-detection` appeared on origin during this integration with a single commit `4c139de1`
"feat(playback): stall-watch state machine and its two settings (WIP)": the state machine (`frontend/src/api/playback-stall.ts`),
its unit spec, two new settings keys in `routers/settings.py` and a settings test. It is explicitly marked work in progress, is not
yet wired into the playback screen and has no changelog or notes. Merging it would ship two settings with no screen and no behaviour,
so it was left for the next release; the release notes say it is not in 2.0.0.
