## 2.19.0 (pilot) — Phone-app WebView session and device attestation (both off), offline field work (server half), critical-sound alerts, vendor arrival and physical-entry service steps, WisKey station listening and live-stream cleanup
**After installing:** three database migrations are added (0174, 0175, 0176); they only add tables and one column, and the previous version ignores them. Nothing is switched on by this version: every new feature is off by default. WisKey, push-relay and hardware-attestation work was tested against test doubles only.
- **עברית:** אחרי ההתקנה: נוספות שלוש מיגרציות (0174, 0175, 0176); הן רק מוסיפות טבלאות ועמודה אחת, והגרסה הקודמת מתעלמת מהן. שום דבר לא מופעל על ידי הגרסה הזאת: כל יכולת חדשה כבויה כברירת מחדל. עבודה מול WisKey, ממסר ההתראות ואימות חומרת המכשיר נבדקה מול דמויות בלבד.

### What was added - מה נוסף
- **English:** Phone-app WebView session through a one-time code (SESSIONEXCH2-295): the app gets a short-lived single-use code and the WebView redeems it. Setting `security.app_session_exchange`, off.
- **עברית:** כניסת WebView של אפליקציית הטלפון באמצעות קוד חד-פעמי: האפליקציה מקבלת קוד קצר וחד-פעמי וה-WebView מממש אותו. הגדרה `security.app_session_exchange`, כבויה.
- **English:** Device hardware attestation for the app's device key (ATTEST232-295, Android Key Attestation and iOS App Attest). Only the verdict is stored. Off.
- **עברית:** אימות חומרה של מפתח המכשיר באפליקציה (Android Key Attestation ו-iOS App Attest). נשמרת רק התוצאה. כבוי.
- **English:** Offline field work, server half (OFFLINE110-295): the technician's work bundle, device lock and wipe, replay and manager review of offline changes, the day-list receipt, and signed QR / NFC round points. Off.
- **עברית:** עבודת שטח ללא חיבור, צד השרת: חבילת עבודה לטכנאי, נעילה ומחיקה של מכשיר, שחזור וסקירת מנהל של שינויים שנעשו בלי חיבור, אישור קבלת רשימת היום, ונקודות סיבוב עם תגי QR / NFC חתומים. כבוי.
- **English:** Critical-sound alerts: the push relay and the server carry `critical_alert` and a resolved tone for the safety event types an administrator picks; per-type switch in Settings. Off.
- **עברית:** התראות קוליות קריטיות: ממסר ההתראות והשרת מעבירים סימון התראה קריטית וצליל סגירה לסוגי אירועי הבטיחות שמנהל בוחר; מתג לכל סוג בהגדרות. כבוי.
- **English:** Service requests: "physical entry required" after assignment with a vendor notice on cancel (PHYSENTRY070-295, off); a vendor "I have arrived" card on the visits flow; a readiness score chip in Settings.
- **עברית:** קריאות שירות: "נדרשת כניסה פיזית" אחרי השיוך והודעה לספק בביטול (כבוי); כרטיס "הגעתי" לספק בזרימת הביקורים; שבב ציון מוכנות בהגדרות.
- **English:** WisKey (test doubles only): listening to a station (WKAUDIN-295), removal of a leased station stream from go2rtc when the last viewer leaves (WKLIVE-295), an explicit new OPEN attempt after an UNKNOWN emergency OPEN (WKOPENUNK-295), and an on-device schedule test (KAVDEVTEST-295).
- **עברית:** WisKey (דמויות בלבד): האזנה לעמדה, הסרת זרם עמדה מושכר מ-go2rtc כשהצופה האחרון יוצא, ניסיון OPEN חדש ומפורש אחרי OPEN חירום שהסתיים ב-UNKNOWN, ובדיקת לוחות זמנים על המכשיר.
- **English:** Change records (documentation only): free-text request intake, reading vendor PDFs and images, voice announcements, visitor pre-registration with a temporary door code.
- **עברית:** מסמכי שינוי (תיעוד בלבד): קליטת בקשות בטקסט חופשי, קריאת PDF ותמונות של ספקים, הכרזות קוליות, רישום מוקדם של מבקרים עם קוד דלת זמני.

### Fixed - תוקן
- **English:** Four fix-before-enable findings of the 2.16.0 security review (SEC217); a sign-out that releases the device key now notifies the user; service-management entry-address redirects wait for the saved settings.
- **עברית:** ארבעה ממצאים מסקירת האבטחה של 2.16.0 שיש לתקן לפני הפעלה; יציאה מהחשבון ששוחררת בה מפתח המכשיר מודיעה עכשיו למשתמש; הפניות כתובת הכניסה של ניהול השירות ממתינות להגדרות השמורות.
- **English:** The remote download route for the app file registered one OpenAPI operation id twice (GET and HEAD together); it is now a GET plus a hidden HEAD. Behaviour is unchanged.
- **עברית:** נתיב ההורדה של קובץ האפליקציה בערוץ המרוחק רשם את אותו מזהה פעולה ב-OpenAPI פעמיים (GET ו-HEAD יחד); עכשיו הוא GET בתוספת HEAD מוסתר. ההתנהגות לא השתנתה.
