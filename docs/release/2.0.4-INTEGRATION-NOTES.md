## Conflicts and how they were resolved

- **Merge 1, the `GetSupportedAPIs` overlap (NN2A in 2.0.3 vs NN2B).** Both branches added the call, its parser and its fake-device
  answer. One implementation is kept: NN2B's `supported_apis()` on the adapter (cached per device, `SUPPORT_TTL_S`, cleared by
  `clear_auth_cache()`) is the one used by the encoding write gate and by NN2A's `alarm_server_support()` / `configure_push`. Removed:
  NN2A's uncached duplicate method, the second `parse_supported_apis` in `provision_isr_xml.py` (git merged both without a conflict, so
  the later definition would have silently won), and NN2B's duplicate `_GetSupportedAPIs` and `supported_apis` attribute in
  `tests/fixtures/fake_provision.py`. `READ_COMMANDS` keeps one `GetSupportedAPIs` line with both comments.
  `scripts/provision_nvr_write.py`: both docstrings kept. `docs/changes/CR-025-PROVISION-ISR.md`: sections 6.6.1 (NN2A) and 6.7 (NN2B)
  both kept. `tests/test_provision_nvr_write_script.py`: both test groups kept.
- **Merge 1, test-only consequences (`fd25189e`).** NN2A's `world` fixture lists `["GetAlarmServerConfig", "SetAlarmServerConfig"]` as
  the device's APIs; under NN2B's gate a v2 list without `SetVideoStreamConfig` means `write_api_missing`, so the nine encoding tests use
  a new `v1world` fixture (no `GetSupportedAPIs` answer, the v1 firmware the encoding write targets).
  `test_provision_push_addon.py::test_configure_push_follows_the_device_form` clears the (now cached) support answer after changing the
  fake's answer. No product code changed for this.
- **Merge 2, `frontend/src/screens/live-wall.ts`:** LV1 moved the column buttons into a `sw-dropdown` (the "עמודות" row is gone); 2.0.3
  added the "חזרה למפה" link to the picked-cameras note. Both kept: the note with the link, no columns row. LV1's base had the old
  `ui.dd_phone` default `sheet`; main's `list` stays (`settings.py`, `dd_style.py` checked).
- **Merge 3:** the four migration-list tests (`test_media_api.py`, `test_media_players_api.py`, `test_migrations.py`,
  `test_notify_core.py`): main `..., 57, 58, 59]`, CAST1 `..., 57, 60]`. Union `..., 57, 58, 59, 60]`, comments name 0060. The CAST1
  migration keeps its number 0060 (0057-0059 are in main). `contracts/API_INVENTORY.md`: main's side, regenerated in the release commit.
- **Merge 4:** `sw-app.ts`, `nav.ts` and `ha.ts` were touched by both sides but merged without a conflict; `tsc` is part of the gate.

## Cast is off
Option `cast_relay` is `false` by default, port 18092 maps to nothing, every screen is "not allowed" until an administrator switches it
on. The first physical cast test is after this release, by `docs/operations/CAST_FIRST_PHYSICAL_TEST_RUNBOOK.md`; nothing in the
integration or the gate contacts a real screen, camera, NVR, go2rtc or Home Assistant.
