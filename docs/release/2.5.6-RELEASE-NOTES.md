**After installing:** **no database migration** (the sequence stays 0001..0084, contiguous). **No bridge change** (0.8.0). **No new add-on option.** Reload the installed web app once; the vendor page reloads itself on the next link opening. The module stays OFF by default and nothing changes for an installation that has not switched it on. **Fakes and fixtures only: nothing here sent a real message or contacted a device.**
- **עברית:** אחרי ההתקנה: **אין מיגרציה של מסד הנתונים** (הרצף נשאר 0001..0084 ללא פערים). **אין שינוי בגשר** (0.8.0). **אין אפשרות תוסף חדשה.** יש לרענן את היישום המותקן פעם אחת; דף הספק נטען מחדש בפתיחת הקישור הבאה. המודול נשאר כבוי כברירת מחדל ושום דבר לא משתנה בהתקנה שלא הפעילה אותו. **רק דמויות ופיקסצ'רים: דבר מכל זה לא שלח הודעה אמיתית ולא פנה להתקן.**

### What was changed - מה השתנה
- **English:** "Waiting for a part" is now a sub-state of "In progress", not a step in the flow; vendors can set it themselves. Details: the status strip of the detail shows six steps (New, Assigned, Accepted, In progress, Done, Closed); a handled item that waits for a part keeps "In progress" active with a small label "Waiting for a part" under it, and cards, the table and the device tab read "In progress · Waiting for a part". A button under the strip ("Mark: waiting for a part" / "Back to in progress") sets and clears the state through the existing status route; the table's status menu no longer lists it as a status (leaving it reads "Back to in progress"). The "In progress" filter and the state-strip counts still include it; the board sections, the SLA "stuck" dues and the stored status value `waiting_part` are unchanged. The vendor page shows three steps (Accepted, In progress, Done) and a toggle under "In progress" with which the vendor marks or clears the part wait himself, in Hebrew, English, Arabic and Russian (Arabic and Russian: pending native review). It uses the existing status action: the public routes, the listener allow-list and the closed set of values are unchanged.
- **עברית:** 'ממתין לחלק' הוא כעת מצב משנה של 'בטיפול' ולא שלב בזרימה; הספק יכול לסמן אותו בעצמו. פרטים: פס הסטטוס בפרטים מציג שישה שלבים (חדש, שויך, התקבל, בטיפול, הסתיים, סגור); פריט שממתין לחלק נשאר ב'בטיפול' הפעיל עם תווית קטנה 'ממתין לחלק' מתחתיו, והכרטיסים, הטבלה ולשונית ההתקן מציגים 'בטיפול · ממתין לחלק'. כפתור מתחת לפס ('סמן: ממתין לחלק' / 'חזרה לטיפול') מסמן ומנקה את המצב דרך נתיב הסטטוס הקיים; תפריט הסטטוס בטבלה אינו מציע אותו עוד כסטטוס נפרד (היציאה ממנו נקראת 'חזרה לטיפול'). המסנן 'בטיפול' וספירות פס המצבים ממשיכים לכלול אותו; מקטעי הלוח, מועדי ה'תקוע' של ה-SLA וערך הסטטוס השמור `waiting_part` לא השתנו. דף הספק מציג שלושה שלבים (התקבל, בטיפול, בוצע) ומתג מתחת ל'בטיפול' שבעזרתו הספק מסמן או מנקה בעצמו את ההמתנה לחלק, בעברית, אנגלית, ערבית ורוסית (ערבית ורוסית: לבדיקה). המתג משתמש בפעולת הסטטוס הקיימת: הנתיבים הציבוריים, רשימת ההיתרים של המאזין וקבוצת הערכים הסגורה לא השתנו.

### How to use - איך משתמשים
- **English:** Nothing to switch on: open Service management, an item being handled, and use the button under the status strip. Rollback: revert the release; no data format changed (the stored status stays `waiting_part`).
- **עברית:** אין מה להפעיל: פותחים את ניהול השירות, פריט בטיפול, ומשתמשים בכפתור מתחת לפס הסטטוס. החזרה לאחור: החזרת הגרסה; שום פורמט נתונים לא השתנה (הסטטוס השמור נשאר `waiting_part`).
