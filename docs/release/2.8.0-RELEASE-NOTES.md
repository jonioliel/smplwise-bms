## 2.8.0 (pilot) — The full elevators module (designed screen, home widget, history, alerts off by default), manager-overview summary route, "needs review" privacy report, reject-and-delete for pending technicians, technician privacy notice n2
**After installing:** **two automatic database migrations** (0119: elevator state history, notification memory and the elevator alert settings - all new and empty; 0120: two partial indexes for the manager overview, no table and no data change; the sequence is 0001..0120, contiguous). No bridge change (still 0.9.2; no Home Assistant restart needed for this version). **Add-on options:** no new option; the six deprecated, empty secret options are still declared - leave them empty. Reload the installed web app once. Elevator alerts are OFF until a system administrator turns them on; nothing else needs a switch.
- **עברית:** אחרי ההתקנה: **שתי מיגרציות אוטומטיות של מסד הנתונים** (0119: היסטוריית מצבי מעליות, זיכרון התראות והגדרות התראות המעליות - כולן חדשות וריקות; 0120: שני אינדקסים חלקיים לסקירת המנהל, בלי טבלה ובלי שינוי בנתונים; הרצף הוא 0001..0120, רציף). אין שינוי בגשר (עדיין 0.9.2; אין צורך להפעיל מחדש את Home Assistant בגרסה הזו). **אפשרויות התוסף:** אין אפשרות חדשה; שש אפשרויות הסוד הישנות והריקות עדיין מוגדרות - יש להשאיר אותן ריקות. יש לטעון מחדש פעם אחת את אפליקציית הרשת המותקנת. התראות המעליות כבויות עד שמנהל מערכת מפעיל אותן; שום דבר אחר לא דורש מתג.

### What was changed - מה השתנה
- **English:** Elevators, the designed Infrastructure screen: a KPI row (all / waiting or in operation / fault / out of service / fire service), one card per elevator with a door icon in the state colour, a solid state badge, a light per linked sensor (with a spoken / tooltip text), a 24-hour state bar with a text summary and "how long ago". Out of service has its own strong orange with a striped edge (a square dot, not only a colour); fire service is crimson and pulses (stops under reduced motion). No direction is shown anywhere (the installation has no up / down sensors); the settings dialog offers waiting / fault / fire service / shutdown. Managers get "new elevator" and an add card. View only - nothing is ever sent to an elevator.
- **עברית:** מעליות, מסך התשתיות המעוצב: שורת מדדים (הכל / ממתינה או פעילה / תקלה / בהשבתה / פיקוד כבאים), כרטיס לכל מעלית עם אייקון דלת בצבע המצב, תג מצב מלא, נורית לכל חיישן מקושר (עם טקסט מוקרא / רמז), פס מצבים של 24 שעות עם סיכום טקסט ו"לפני כמה זמן". להשבתה צבע כתום חזק משלה עם שוליים מפוספסים (נקודה מרובעת, לא רק צבע); פיקוד כבאים בצבע ארגמן ומהבהב (נעצר כשמבוקשת תנועה מופחתת). שום כיוון לא מוצג בשום מקום (אין במתקן חיישני עלייה / ירידה); חלון ההגדרות מציע ממתינה / תקלה / פיקוד כבאים / השבתה. למנהלים יש "מעלית חדשה" וכרטיס הוספה. צפייה בלבד - שום דבר לא נשלח למעלית.
- **English:** Elevators, the home widget: a separate home widget that replaces the 2.7.x small tiles in the summary row. The owner chooses HOW it is shown - ONE combined card for all elevators, one card per elevator, or both - WHICH elevators are left out, and whether all states or only the alerting ones are listed. Place and size (small / medium / large) come from the home edit mode like every widget; Settings › Infrastructure › Elevators › "on the home screen" sets the installation default; a user with "personalize my screen" may keep his own mode and hide more elevators (added to the installation's list). The widget exists only when the viewer sees at least one elevator; a tap opens Infrastructure › Elevators.
- **עברית:** מעליות, ווידג׳ט מסך הבית: ווידג׳ט נפרד במסך הבית שמחליף את האריחים הקטנים של 2.7.x בשורת הסיכום. הבעלים בוחר איך הוא מוצג - כרטיס משולב אחד לכל המעליות, כרטיס לכל מעלית, או שניהם - אילו מעליות להשאיר בחוץ, והאם להציג את כל המצבים או רק מצבי התראה. מיקום וגודל (קטן / בינוני / גדול) נקבעים במצב עריכת מסך הבית כמו כל ווידג׳ט; הגדרות › תשתיות › מעליות › "תצוגה במסך הראשי" קובע את ברירת המחדל של המתקן; משתמש עם "התאמת המסך שלי" יכול לשמור מצב משלו ולהסתיר מעליות נוספות (מתווספות לרשימת המתקן). הווידג׳ט קיים רק כשהצופה רואה לפחות מעלית אחת; לחיצה פותחת את תשתיות › מעליות.
- **English:** Elevators, history and alerts: a read-only background check every 15 seconds records each state change (8 days are kept; "unknown" while the connection to the home platform is down or the elevator is disabled) for the 24-hour bar. Notifications for fire service (critical), fault (alert) and shutdown (info) are built with recipients chosen per state (roles, named users, groups - nothing selected = nobody, and only people who may see that state's own sensor) and channels per state (notification centre always; browser push and the phone app on request; never e-mail or WhatsApp). **They are OFF by default:** a master switch and a switch per state. Turning on notifies only new transitions, never a condition that already held; turning off closes the open elevator notifications of those states at once (resolution "elevator alerts were turned off").
- **עברית:** מעליות, היסטוריה והתראות: בדיקת רקע לקריאה בלבד כל 15 שניות רושמת כל שינוי מצב (נשמרים 8 ימים; "לא ידוע" כשהחיבור למערכת הבית מנותק או שהמעלית מושבתת בהגדרות) לטובת פס 24 השעות. נבנו התראות לפיקוד כבאים (קריטית), תקלה (התראה) והשבתה (מידע) עם נמענים לכל מצב (תפקידים, משתמשים בשם, קבוצות - בלי בחירה = אף אחד, ורק מי שמורשה לראות את החיישן של אותו מצב) וערוצים לכל מצב (מרכז ההתראות תמיד; התראת דפדפן ואפליקציית הטלפון לפי בחירה; לעולם לא דוא"ל או WhatsApp). **הן כבויות כברירת מחדל:** מתג ראשי ומתג לכל מצב. הפעלה מתריעה רק על מעברים חדשים, לעולם לא על מצב שכבר התקיים; כיבוי סוגר מיד את התראות המעליות הפתוחות של אותם מצבים (סיבת סגירה "התראות המעליות כובו").
- **English:** Manager overview, phase 2 (server only): a new summary route `GET /api/v1/tickets/dashboard` for the board's managers - throughput per handler (today / 7 / 30 days: done, closed, returned, median time to done), the last 14 days opened / closed, what waits for THIS manager's decision (quotes, payment demands, RFQ awards he may give the second approval to; amounts only with the cost permission), open RFQs by stage, and a department comparison for a manager of all departments. Every ticket and request passes the usual visibility rules; a department filter the caller does not manage is an audited refusal. No screen change yet (the cards come in phase 3).
- **עברית:** סקירת מנהל, שלב 2 (שרת בלבד): נתיב סיכום חדש `GET /api/v1/tickets/dashboard` למנהלי הלוח - תפוקה לכל מטפל (היום / 7 / 30 ימים: בוצעו, נסגרו, הוחזרו, זמן חציוני עד ביצוע), 14 הימים האחרונים נפתחו / נסגרו, מה ממתין להחלטה של המנהל הזה (הצעות מחיר, דרישות תשלום, בחירות בבקשות הצעות מחיר שהוא רשאי לתת להן אישור שני; סכומים רק עם הרשאת העלויות), בקשות הצעות מחיר פתוחות לפי שלב, והשוואה בין מחלקות למנהל של כל המחלקות. כל קריאה וכל בקשה עוברות את כללי הנראות הרגילים; סינון למחלקה שהמבקש לא מנהל נדחה ונרשם בביקורת. עדיין אין שינוי במסך (הכרטיסים יגיעו בשלב 3).
- **English:** "Needs review" privacy report: "Handlers and vendors" gains a fourth segment "needs review" for directory editors (tickets.configure): technicians a vendor added that nobody accepted for longer than 30 days, and people Arx knows for door access with no live grant and no activity for 12 months (both thresholds editable by a system administrator). Row actions behind a confirmation: "reject and delete" for a pending technician and "delete now" for an idle person. Deletion is in Arx only - nothing is ever sent to the door system; a row linked to the door system says so, and removing the person there stays a separate manual step. A yearly reminder in January (only when the report is not empty, a count and a link, never a name) goes to the notification managers in the app.
- **עברית:** דוח פרטיות "דורש בחינה": במסך "מטפלים וספקים" נוסף מקטע רביעי "דורש בחינה" לעורכי המדריך (tickets.configure): טכנאים שספק הוסיף ואף אחד לא אישר יותר מ-30 יום, ואנשים ש-Arx מכיר לגישה לדלתות בלי הרשאה פעילה ובלי פעילות 12 חודשים (שני הספים ניתנים לעריכה על ידי מנהל מערכת). פעולות בשורה, אחרי אישור: "דחייה ומחיקה" לטכנאי ממתין ו"מחיקה עכשיו" לאדם לא פעיל. המחיקה היא ב-Arx בלבד - שום דבר לא נשלח למערכת הדלתות; שורה שמקושרת למערכת הדלתות מציינת זאת, והסרת האדם שם נשארת צעד ידני נפרד. תזכורת שנתית בינואר (רק כשהדוח לא ריק, מספר וקישור, לעולם לא שם) נשלחת באפליקציה למנהלי ההתראות.
- **English:** Reject and delete a pending technician: new `POST /api/v1/access-grants/pending-contacts/{id}/reject` (the same authority as accepting): erases the name and phone the vendor typed, ends the open requested grant (reason "refused") and records the rejection, audited without personal data. Refused for an accepted, already rejected or unknown technician (404) and when a door-system link or a decided grant exists (409).
- **עברית:** דחייה ומחיקה של טכנאי ממתין: נתיב חדש `POST /api/v1/access-grants/pending-contacts/{id}/reject` (אותה סמכות כמו אישור): מוחק את השם והטלפון שהספק הקליד, מסיים את בקשת ההרשאה הפתוחה (סיבה "נדחה") ורושם את הדחייה, עם רישום ביקורת בלי מידע אישי. נדחה לטכנאי שכבר אושר, כבר נדחה או לא מוכר (404) וכשקיים קישור למערכת הדלתות או הרשאה שכבר הוחלטה (409).
- **English:** Technician privacy notice, version n2 (the technician-access feature itself stays locked): the notice in Hebrew, English, Arabic and Russian, written in the third person, and the vendor attests that he told the technician (a notice, not a consent); Arabic and Russian technicians get their code message in their language instead of English. A stale page that still posts version n1 is refused and must reload the view; the notice audit records whom it was acknowledged for. The wording is an interim text and needs the owner's sign-off before go-live.
- **עברית:** הודעת פרטיות לטכנאים, גרסה n2 (תכונת גישת הטכנאים עצמה נשארת נעולה): ההודעה בעברית, אנגלית, ערבית ורוסית, בגוף שלישי, והספק מאשר שהוא מסר אותה לטכנאי (הודעה, לא הסכמה); טכנאים דוברי ערבית ורוסית מקבלים את הודעת הקוד בשפתם במקום באנגלית. דף ישן שעדיין שולח גרסה n1 נדחה וצריך לטעון מחדש את התצוגה; רישום הביקורת של ההודעה מציין עבור מי היא אושרה. הנוסח זמני ודורש אישור של הבעלים לפני הפעלה.

### Changes that apply without a switch - שינויים שחלים בלי מתג
- **English:** On an installation with elevators, the home screen shows the new elevators widget (combined card, medium size) instead of the 2.7.x small tiles, and the Infrastructure screen has the new design; the history recording starts by itself (read-only). The manager-overview route, the reject route and the "needs review" segment are available to their permission holders. The yearly reminder is part of the notification catalogue (in-app only, no push).
- **עברית:** במתקן עם מעליות מסך הבית מציג את ווידג׳ט המעליות החדש (כרטיס משולב, גודל בינוני) במקום האריחים הקטנים של 2.7.x, ומסך התשתיות בעיצוב החדש; רישום ההיסטוריה מתחיל מעצמו (קריאה בלבד). נתיב סקירת המנהל, נתיב הדחייה ומקטע "דורש בחינה" זמינים לבעלי ההרשאות שלהם. התזכורת השנתית היא חלק מקטלוג ההתראות (באפליקציה בלבד, בלי התראת דחיפה).

### What is OFF by default and how to enable - מה כבוי כברירת מחדל ואיך מפעילים
- **English:** Elevator alerts: Settings › Infrastructure › Elevators › "Elevator alerts" (system administrator): turn on the master switch "send elevator alerts", then the switch of each state (fire service / fault / shutdown), choose its recipients (roles, users, groups) and its channels, and save. The elevators widget can be switched off or changed in Settings › Infrastructure › Elevators › "on the home screen" or in the home edit mode. The technician-access feature (with the n2 notice) stays locked; every 2.7.3 switch keeps its state.
- **עברית:** התראות מעליות: הגדרות › תשתיות › מעליות › "התראות מעליות" (מנהל מערכת): מפעילים את המתג הראשי "שליחת התראות מעליות", אחר כך את המתג של כל מצב (פיקוד כבאים / תקלה / השבתה), בוחרים נמענים (תפקידים, משתמשים, קבוצות) וערוצים, ושומרים. אפשר לכבות או לשנות את ווידג׳ט המעליות בהגדרות › תשתיות › מעליות › "תצוגה במסך הראשי" או במצב עריכת מסך הבית. תכונת גישת הטכנאים (עם הודעה n2) נשארת נעולה; כל מתג של 2.7.3 שומר על מצבו.

### How to use - איך משתמשים
- **English:** Needs review: Tickets › Handlers and vendors › "needs review" (tickets.configure); thresholds in the card on the same segment (system.configure): `directory.review_pending_days` (default 30, 7-365) and `directory.review_idle_months` (default 12, 1-60). Manager overview: `GET /api/v1/tickets/dashboard` (optional `department_id`, `period` = today / 7d / 30d), for API clients until the phase 3 screen. Rollback: install 2.7.3 again; migrations 0119 / 0120 only add new tables and indexes, 2.7.3 ignores them.
- **עברית:** דורש בחינה: קריאות › מטפלים וספקים › "דורש בחינה" (tickets.configure); הספים בכרטיס באותו מקטע (system.configure): `directory.review_pending_days` (ברירת מחדל 30, 7-365) ו-`directory.review_idle_months` (ברירת מחדל 12, 1-60). סקירת מנהל: `GET /api/v1/tickets/dashboard` (לא חובה: `department_id`, `period` = today / 7d / 30d), ללקוחות API עד מסך שלב 3. חזרה לאחור: מתקינים שוב את 2.7.3; מיגרציות 0119 / 0120 רק מוסיפות טבלאות ואינדקסים חדשים, ו-2.7.3 מתעלמת מהם.

### Known limits - מגבלות ידועות
- **English:** Elevators: no floor display and no history range longer than 24 hours on screen (8 days are kept); the last state before an add-on stop spans the outage until the first check after the start. Manager overview: no screen yet, the 20,000-ticket speed run was not done. Needs review: the Arabic and Russian texts need a native review. Technician notice n2: owner sign-off pending. The WisKey door-system work is not in this release.
- **עברית:** מעליות: אין תצוגת קומה ואין טווח היסטוריה ארוך מ-24 שעות במסך (נשמרים 8 ימים); המצב האחרון לפני עצירת התוסף נמשך על פני ההפסקה עד הבדיקה הראשונה אחרי ההפעלה. סקירת מנהל: עדיין אין מסך, בדיקת המהירות עם 20,000 קריאות לא בוצעה. דורש בחינה: הטקסטים בערבית וברוסית צריכים בדיקה של דובר שפת אם. הודעת טכנאים n2: ממתינה לאישור הבעלים. העבודה על מערכת הדלתות WisKey לא כלולה בגרסה הזו.
