# SmplWise Arx 0.1.161 - Release notes / הערות שחרור

Source of truth for the text below: smplwise_vms/CHANGELOG.md.

## 0.1.161 (pilot) — Correcting an electricity price; the device name of every meter sensor; the camera stream editor saves after a codec change
No restart of the platform is needed (the bridge integration stays 0.6.0). **No database migration in this release** (the last one stays `0054_electricity_billing`). Reload the installed web app once.
### Correcting a price - הגדרות › תשתיות › מחירים ומע״מ
- A new price on the date of an existing price no longer fails with "כבר קיים מחיר מאותו תאריך": it replaces that price after one confirmation that states what changes (old price ← new price). The editor's version list has a "תיקון" button per version to correct its price, whether it includes VAT and its start date.
- A bill that was already issued never changes: when an issued bill used the price, the corrected price starts the day after the last issued period (the confirmation says so: "החשבונות שכבר הופקו לא ישתנו"); when a later price leaves no room, the correction is refused with a short reason.
- Drafts, the forecast and later periods use the corrected price: existing draft bills in the corrected range are recomputed automatically (the confirmation says how many; one audit row per draft; a draft that fails to recompute is reported and does not undo the correction). Issued, sent, paid and cancelled bills are never touched.
- Every correction is audited (who, when, old and new value; `energy.tariff.version.correct`). Permission `energy.manage`.
### Electricity: the device of every meter sensor
- The "הוספת מונה" picker, the meters table/cards/phone list, the meter card header and the account wizard (step 1) show the device each sensor belongs to (the device name as set in the system, else the device's own name) in bold, with the sensor's own name under it when it differs. Many sensors are simply called "Energy"; they are now told apart. A sensor without a device shows only its name. The picker search (and the search inside the wizard) also matches the device name.
- The meters API (`GET /energy/candidates`, `GET /energy/meters`, `GET /energy/meters/{id}`) adds `device_id`, `device_name` and `entity_name`; `name` is unchanged.
### Fix - the camera stream editor (מערכת › אבטחה › מצלמות)
- Changing the codec (for example H.265 → H.264) and pressing "שמור" did nothing: the screen read the server's answer for the new codec's options wrongly, so the editor lost its lists and Save failed silently. The editor now reads the answer correctly, and Save always answers: either the confirmation opens or a short Hebrew line says why not (codec lists still loading, lists could not be read, a value the new codec does not offer, nothing changed, an unexpected error). Save stays off while the new codec's lists load or when they could not be read.
- The server checks a codec change against the NEW codec's lists before any write to the recorder: a kept profile or resolution that the new codec does not offer is refused (422 `value_not_allowed` with the field, the codec and the allowed values, and a Hebrew message), and the editor shows that line.
### How to turn it on and use it (English)
1. Install the update; nothing to migrate; reload the installed web app once.
2. Price correction: הגדרות › תשתיות › מחירים ומע״מ → open the price → "תיקון" on the version (or save a new price on the same date) → read the one confirmation → confirm. Holders of `energy.manage` see it; nothing to turn on.
3. Device names: nothing to turn on; תשתיות › מוני חשמל › מונים and "הוספת מונה" show them by themselves.
4. Stream editor: מערכת › אבטחה › מצלמות → a camera → edit the stream → change the codec → "שמור" → confirm (holders of `nvr.configure`, as before).
### Known limits
- **Nothing in this release was run against a real system:** every test used fakes (fake recorder, fake meters, mocked screens). The codec change H.265 → H.264 was verified on the fake recorder only; the first real codec change on the lab recorder should be watched.
- A price correction recomputes DRAFT bills only; it never re-opens an issued bill (issue a correction bill by hand when one is needed).
- The device name comes from the infrastructure's device registry; a sensor without a device shows only its own name.

## עברית — 0.1.161: תיקון מחיר חשמל; שם המכשיר לכל חיישן מונה; עורך הזרם של המצלמה שומר אחרי החלפת קידוד
השחרור אינו מחייב הפעלה מחדש של תשתית המערכת (הגשר נשאר 0.6.0). **אין מיגרציה של בסיס הנתונים בשחרור הזה** (האחרונה נשארת `0054_electricity_billing`). יש לטעון מחדש את אפליקציית הרשת המותקנת פעם אחת.
### תיקון מחיר - הגדרות › תשתיות › מחירים ומע״מ
- מחיר חדש בתאריך של מחיר קיים כבר לא נכשל עם "כבר קיים מחיר מאותו תאריך": הוא מחליף את המחיר הקיים אחרי אישור אחד שאומר מה משתנה (המחיר הישן ← המחיר החדש). ברשימת הגרסאות בעורך יש כפתור "תיקון" לכל גרסה: מחיר, כולל או לפני מע״מ, ותאריך התחלה.
- חיוב שכבר הופק לעולם לא משתנה: אם חיוב שהופק השתמש במחיר, המחיר המתוקן חל מהיום שאחרי התקופה האחרונה שהופקה (האישור אומר זאת: "החשבונות שכבר הופקו לא ישתנו"); כשמחיר מאוחר יותר לא משאיר מקום, התיקון נדחה עם סיבה קצרה.
- טיוטות, התחזית והתקופות הבאות משתמשות במחיר המתוקן: טיוטות קיימות בטווח המתוקן מחושבות מחדש אוטומטית (האישור אומר כמה; שורת ביקורת לכל טיוטה; טיוטה שנכשלה מדווחת ולא מבטלת את התיקון). חיובים שהופקו, נשלחו, שולמו או בוטלו לא משתנים.
- כל תיקון נרשם ביומן הביקורת (מי, מתי, הערך הישן והחדש). הרשאה: `energy.manage`.
### מוני חשמל: המכשיר של כל חיישן
- בבורר "הוספת מונה", בטבלת המונים (גם בכרטיסים וברשימה בטלפון), בכותרת כרטיס המונה ובשלב 1 של אשף החשבון מוצג עכשיו המכשיר שאליו שייך החיישן (שם המכשיר כפי שהוגדר במערכת, אחרת שם המכשיר עצמו) בבולט, ומתחתיו שם החיישן כשהוא שונה. חיישנים רבים נקראים פשוט "Energy" - עכשיו אפשר להבחין ביניהם. חיישן בלי מכשיר מציג רק את שמו. החיפוש בבורר (ובאשף) מוצא גם לפי שם המכשיר.
### תיקון - עורך הזרם של המצלמה (מערכת › אבטחה › מצלמות)
- החלפת קידוד (למשל H.265 ← H.264) ולחיצה על "שמור" לא עשו כלום: המסך קרא לא נכון את תשובת השרת עם אפשרויות הקידוד החדש, העורך איבד את הרשימות והשמירה נכשלה בשקט. עכשיו התשובה נקראת נכון, ו"שמור" תמיד עונה: נפתח אישור, או שורה קצרה אומרת למה לא (רשימות הקידוד עדיין נטענות, לא ניתן לקרוא את הרשימות, ערך שהקידוד החדש לא מציע, אין שינוי, שגיאה לא צפויה). "שמור" כבוי בזמן שרשימות הקידוד החדש נטענות או כשלא ניתן היה לקרוא אותן.
- השרת בודק החלפת קידוד מול הרשימות של הקידוד החדש לפני כל כתיבה למקליט: פרופיל או רזולוציה שנשארו ושהקידוד החדש לא מציע נדחים עם הודעה בעברית, והעורך מציג אותה.
- **איך מפעילים:** מתקינים את העדכון; אין מיגרציה; טוענים מחדש את אפליקציית הרשת פעם אחת. תיקון מחיר: הגדרות › תשתיות › מחירים ומע״מ ← פותחים את המחיר ← "תיקון" בגרסה (או שומרים מחיר חדש באותו תאריך) ← קוראים את האישור ומאשרים (למחזיקי `energy.manage`; אין מה להפעיל). שמות מכשירים: אין מה להפעיל, הם מוצגים במונים וב"הוספת מונה". עורך הזרם: מערכת › אבטחה › מצלמות ← מצלמה ← עריכת הזרם ← החלפת קידוד ← "שמור" ← אישור (למחזיקי `nvr.configure`, כמו קודם).
- **מגבלות:** **שום דבר בשחרור הזה לא הורץ מול מערכת אמיתית:** כל הבדיקות השתמשו בדמה (מקליט מדומה, מונים מדומים, מסכים עם שרת מדומה). החלפת הקידוד H.265 ← H.264 נבדקה רק על המקליט המדומה; כדאי לעקוב אחרי החלפת הקידוד האמיתית הראשונה במקליט המעבדה. תיקון מחיר מחשב מחדש רק טיוטות; חיוב שהופק לא נפתח מחדש (חיוב תיקון מפיקים ידנית כשצריך). שם המכשיר מגיע מרישום המכשירים של תשתית המערכת; חיישן בלי מכשיר מציג רק את שמו.
