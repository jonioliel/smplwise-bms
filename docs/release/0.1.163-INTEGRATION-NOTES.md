### 5. Integration fix: bridge 0.6.2 (found here, not a merge conflict)
0.1.162 shipped bridge **0.6.1** with the first schedule allow-list. `pilot/schedules-followup` extended the allow-list (sirens,
media players, number / select) while keeping **0.6.1**, because it assumed 0.6.1 was unreleased. `bridge_install` copies the
bridge into Home Assistant only when the version differs, so an installation upgraded from 0.1.162 would never receive the new
allow-list and the bridge would refuse sirens / players / numbers / selects. Fix:
- both bridge copies: `manifest.json`, `const.VERSION` and the card's `VERSION` -> `0.6.2`;
- `services/schedule_policy.py`: `FOLLOWUP_BRIDGE = "0.6.2"`, `FOLLOWUP_BRIDGE_SERVICES`, `bridge_needed(service)`; the two gates
  (`schedule_model.py`, `schedule_view.py`) use it, so a 0.6.1 installation gets `bridge_too_old_for_action` with the restart hint;
- tests: version assertions moved to 0.6.2; new `test_the_released_bridge_0_6_1_refuses_the_follow_up_services_with_the_update_hint`.
