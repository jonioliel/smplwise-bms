## Switches and defaults (what is live without a switch)

- Elevators: the new Infrastructure screen and the home widget (only where the viewer sees at least one elevator; the 2.7.x KPI-row tiles are
  gone), the history evaluator (read-only; env `SW_ELEVATORS=0` stops it). **Elevator alerts are OFF** (master and every state); the evaluator
  also asks the elevator settings, so the generic notification matrix cannot start them. New routes `GET/PUT /infra/elevators/alerts`.
- New settings: `directory.review_pending_days` (30, 7-365), `directory.review_idle_months` (12, 1-60); the home widget `elevators`
  (`mode` combined / cards / both, `hidden` <= 50 ids, `filter` all / alerts), personal `home.personal.widgets.elevators`.
- New notification sources: `elevator.fire_service` / `elevator.fault` / `elevator.out_of_service` (catalogue default enabled false, push false,
  rule `elevator`), `privacy.needs_review` (managers, in-app, no push, January only when non-empty).
- New routes (API inventory 1050 -> 1056): `GET /tickets/dashboard`, `GET /tickets/contacts-review`, `POST /tickets/contacts-review/{id}/delete`,
  `POST /access-grants/pending-contacts/{id}/reject`, `GET` and `PUT /infra/elevators/alerts`.
- No new permission. `access_grants.GO_LIVE_PERMITTED` and `EXTENDED_GO_LIVE_PERMITTED` stay False.

## Open risks

1. The elevators evaluator is a new background thread (read-only, one IMMEDIATE transaction per 15 s tick, like the generator runner).
2. The home screen of an installation with elevators changes without a switch (widget instead of the KPI-row tiles) - owner-requested.
3. The manager-overview route is new SQL over the whole ticket history; its speed at 20,000 tickets is NOT_RUN (30 s cache, partial indexes).
4. "Delete now" erases a directory person; it re-checks the rule and "no live grant" in one write transaction and never calls the door system.
