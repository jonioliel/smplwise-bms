# SmplWise Arx 2.4.1 - Release notes / הערות שחרור

Source of truth for the text below: smplwise_vms/CHANGELOG.md (section 2.4.1, bilingual per item).

## 2.4.1 (pilot) - minor: bridge 0.8.0, Frigate zone editor and schema-driven camera settings, plan anchor references follow the reader's camera scope
**After installing:** **one database migration, 0072** (rebuilds the Frigate write-policy table so it admits the new write class `config`; every row is copied; the sequence is 0001..0070 and 0072, number 0071 is reserved). **The bridge is now 0.8.0: update it on the live Home Assistant and RESTART Home Assistant** (a custom integration loads only at start-up; the add-on copies the integration on start, HACS users update there). Until then the equipment-card actions of 2.4.0 (valve, vacuum pause, water heater) answer `service_not_allowed`, and System health › "bridge" shows a warning asking for the update. Reload the installed web app once. Nothing new is switched on by itself: the Frigate write class `config` is OFF by default.
- **עברית:** אחרי ההתקנה: **מיגרציה אחת, 0072** (בונה מחדש את טבלת מדיניות הכתיבה של Frigate כך שתכיר את מחלקת הכתיבה החדשה `config`; כל השורות מועתקות; הרצף הוא 0001..0070 ו־0072, המספר 0071 שמור). **הגשר הוא עכשיו 0.8.0: מעדכנים אותו ב־Home Assistant החי ו*מפעילים מחדש את Home Assistant*** (אינטגרציה מותאמת נטענת רק בעלייה; התוסף מעתיק את האינטגרציה בעלייה, משתמשי HACS מעדכנים שם). עד אז פעולות כרטיסי הציוד של 2.4.0 (שסתום, השהיית שואב, מחמם מים) עונות `service_not_allowed`, ובריאות המערכת › "גשר" מציגה אזהרה שמבקשת עדכון. טוענים מחדש את אפליקציית הרשת פעם אחת. דבר לא מופעל מעצמו: מחלקת הכתיבה `config` של Frigate כבויה כברירת מחדל.

### Bridge 0.8.0 - גשר 0.8.0
- **English - what changed:** the bridge integration moves from 0.7.0 to 0.8.0; no new service and no new setting. The service allow-list pairs added in 2.4.0 without a version bump (`valve.open_valve`, `valve.close_valve`, `vacuum.pause`, `water_heater.turn_on`, `water_heater.turn_off`) are now carried by a version the add-on can require (`ha_bridge.BRIDGE_EQUIPMENT_REQUIRED`); the health report warns the administrator while the installed bridge is older. Both bridge copies are byte-identical (checked by `scripts/release_check.py`). Upgrade and rollback: `docs/release/BRIDGE-0.8.0-NOTES.md`.
- **עברית - מה השתנה:** אינטגרציית הגשר עוברת מ־0.7.0 ל־0.8.0; אין שירות חדש ואין הגדרה חדשה. זוגות רשימת השירותים שנוספו ב־2.4.0 בלי העלאת גרסה נישאים עכשיו בגרסה שהתוסף יכול לדרוש (`ha_bridge.BRIDGE_EQUIPMENT_REQUIRED`); דוח הבריאות מזהיר את המנהל כל עוד הגשר המותקן ישן יותר. שני עותקי הגשר זהים בבייטים (נבדק ב־`scripts/release_check.py`). שדרוג וחזרה אחורה: `docs/release/BRIDGE-0.8.0-NOTES.md`.
- **English - how to use:** after the add-on update restart Home Assistant, then Settings › Devices & services › SMPLWISE Bridge must show 0.8.0 and the system-health "bridge" check turns green.
- **עברית - איך משתמשים:** אחרי עדכון התוסף מפעילים מחדש את Home Assistant; הגדרות › מכשירים ושירותים › SMPLWISE Bridge מציג 0.8.0 ובדיקת "גשר" בבריאות המערכת ירוקה.

### Frigate zone editor and schema-driven camera settings (FRGS) - עורך אזורים והגדרות מצלמה לפי סכמה ב־Frigate
- **English - what was added:** Settings › Frigate recorder › "Changes in Frigate" › tab "Zones and settings": pick a camera, see its still with the detection zones over it, add / drag / delete points (mouse, touch, pen, arrow keys), set name, objects, inertia and loitering time, and change nine curated camera settings (detect fps, motion threshold / contour area / lightning threshold, tracked objects, snapshot retention, alert and detection retention days, review alert labels) drawn from a schema, with "back to default" per field. New API: `GET /frigate/{rid}/config/schema` (with an optional check against the instance's own schema), `GET .../cameras/{cid}/config`, `PUT .../config/zones/{name}`, `POST .../config/zones/{name}/delete`, `PUT .../config/settings/{section}`. Writes use the existing F2 model: new write class **`config`** (OFF by default, migration 0072), explicit confirmation on every save, the first write of each kind only under administrator supervision, read-back, a change-log row and undo. The only Frigate call is `PUT /api/config/set` (never `config/save`, never a restart). The stage is never mirrored in RTL. Hebrew in `he.ts`, English in `frigate-en.ts`.
- **English - limits / not verified:** the `PUT /api/config/set` wire shape and whether Frigate applies each change without a restart are NOT verified on a real Frigate (a change that cannot be read back is recorded as `unverified`); motion and object masks, global sections, restart, inserting a point between two points and editing zones Frigate keeps in a shape Arx cannot parse (shown read-only) are not built. This changes the earlier rule "never `/api/config/set`" of CR-029 for the one class `config` (recorded in CR-029 section 13). Runbook: `docs/operations/FRIGATE_SUPERVISED_VERIFICATION_HE.md`.
- **English - how to use:** Settings › Frigate recorder › switch the class `config` on (administrator) › "Changes in Frigate" › "Zones and settings".
- **עברית - מה נוסף:** הגדרות › מקליט Frigate › "שינויים ב־Frigate" › לשונית "אזורים והגדרות": בוחרים מצלמה, רואים את התמונה שלה עם אזורי הזיהוי מעליה, מוסיפים / גוררים / מוחקים נקודות (עכבר, מגע, עט, מקשי חיצים), קובעים שם, אובייקטים, אינרציה וזמן שהייה, ומשנים תשע הגדרות מצלמה נבחרות (fps זיהוי, סף תנועה / שטח קווי מתאר / סף ברק, אובייקטים במעקב, שמירת תמונות, ימי שמירה להתראות ולזיהויים, תוויות להתראות סקירה) המצוירות מתוך סכמה, עם "חזרה לברירת מחדל" לכל שדה. API חדש: `GET /frigate/{rid}/config/schema` (עם בדיקה אופציונלית מול הסכמה של המופע), `GET .../cameras/{cid}/config`, `PUT .../config/zones/{name}`, `POST .../config/zones/{name}/delete`, `PUT .../config/settings/{section}`. הכתיבה לפי מודל F2 הקיים: מחלקת כתיבה חדשה **`config`** (כבויה כברירת מחדל, מיגרציה 0072), אישור מפורש בכל שמירה, הכתיבה הראשונה מכל סוג רק בפיקוח מנהל, קריאה חוזרת, שורה ביומן שינויים וביטול. הקריאה היחידה ל־Frigate היא `PUT /api/config/set` (אף פעם לא `config/save` ולא הפעלה מחדש). הבמה אינה מתהפכת ב־RTL. עברית ב־`he.ts`, אנגלית ב־`frigate-en.ts`.
- **עברית - מגבלות / לא אומת:** צורת הקריאה `PUT /api/config/set` והאם Frigate מחיל כל שינוי בלי הפעלה מחדש לא אומתו על Frigate אמיתי (שינוי שאי אפשר לקרוא חזרה נרשם כ־`unverified`); לא נבנו מסכות תנועה ואובייקט, מקטעים גלובליים, הפעלה מחדש, הוספת נקודה בין שתי נקודות ועריכת אזורים ש־Frigate שומר בצורה ש־Arx לא מפענחת (מוצגים לקריאה בלבד). זה משנה את הכלל הקודם "אף פעם `/api/config/set`" ב־CR-029 עבור המחלקה `config` בלבד (נרשם ב־CR-029 סעיף 13). מדריך: `docs/operations/FRIGATE_SUPERVISED_VERIFICATION_HE.md`.
- **עברית - איך משתמשים:** הגדרות › מקליט Frigate › הפעלת המחלקה `config` (מנהל) › "שינויים ב־Frigate" › "אזורים והגדרות".

### Plan anchor references follow the reader's camera scope (PLNS) - הפניות עוגנים בתוכנית עוקבות אחר היקף המצלמות של הקורא
- **English - what changed:** where a plan structure document names an anchor (`objects[].anchor_ref`, `openings[].anchor_ref`, glass panel `anchor_ref`), a reader who may not see that camera or entity now gets `null` for the reference (the item, position and rotation stay) in geometry reads (draft, published, `?at=`), SVG / PNG / DXF exports and the signed package. An installation-wide reader is untouched. Saving by a scoped editor gives the hidden reference back from the stored document; a NEW reference to a hidden anchor is refused on the editor routes (`422 anchor_hidden`) and dropped, with a warning, on package import. Stored documents, hashes and migrations are unchanged; the published-read ETag differs only when something is withheld.
- **English - limits:** a withheld body does not follow its anchor on that reader's map; the import dialog has no text for the new `anchor_hidden` warning yet (the API returns it).
- **עברית - מה השתנה:** כשמסמך מבנה של תוכנית מפנה לעוגן (`objects[].anchor_ref`, `openings[].anchor_ref`, `anchor_ref` של לוח זכוכית), קורא שאינו רשאי לראות את המצלמה או הישות מקבל עכשיו `null` בהפניה (הפריט, המיקום והסיבוב נשארים) בקריאות גיאומטריה (טיוטה, מפורסם, `?at=`), בייצוא SVG / PNG / DXF ובחבילה החתומה. קורא בהיקף כל ההתקנה לא מושפע. שמירה בידי עורך מוגבל מחזירה את ההפניה הנסתרת מהמסמך השמור; הפניה חדשה לעוגן נסתר נדחית בנתיבי העורך (`422 anchor_hidden`) ומושמטת, עם אזהרה, בייבוא חבילה. מסמכים שמורים, גיבובים ומיגרציות לא השתנו; ה־ETag של הקריאה המפורסמת שונה רק כשמשהו מוסתר.
- **עברית - מגבלות:** גוף מוסתר לא עוקב אחר העוגן שלו במפת אותו קורא; בדיאלוג הייבוא אין עדיין טקסט לאזהרה `anchor_hidden` (ה־API מחזיר אותה).

### Verification only (VER1) - בדיקות בלבד
- **English:** new end-to-end and fixture specs for the equipment cards (UI route, allow-list, signed bridge call, old-bridge rollback, permissions, native `water_heater`, phone / RTL layout) and for the window-wall entity link (validator, 2D / 3D state, exports, package, import, diff). No product change.
- **עברית:** מפרטי בדיקה חדשים מקצה לקצה לכרטיסי הציוד (נתיב ממשק, רשימת מותרים, קריאת גשר חתומה, גלגול חזרה בגשר ישן, הרשאות, `water_heater` מקורי, פריסת טלפון / RTL) ולקישור ישות של קיר חלונות (מאמת, מצב דו/תלת-ממד, ייצוא, חבילה, ייבוא, השוואה). בלי שינוי במוצר.

### Known gaps - פערים ידועים
- **English:** Frigate motion / object masks and global sections are not built; the `/api/config/set` wire shape is unverified on a real Frigate; curved walls (WALL-curved) and the SEC3 block counter are not part of this release unless listed above.
- **עברית:** מסכות תנועה / אובייקט ומקטעים גלובליים ב־Frigate לא נבנו; צורת הקריאה `/api/config/set` לא אומתה על Frigate אמיתי; קירות מעוקלים (WALL-curved) ומונה החסימות SEC3 אינם בגרסה זו אלא אם צוינו למעלה.
