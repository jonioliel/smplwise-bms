## Integration fixes (on integ/291, before the release prep)

1. **Vendor RFQ page chunk budget:** a local `build:public` of `integ/291` measured `rfq-page` + `rfq-files` at 20,519 B gzip, 39 B over
   the 20 KB cap. The growth is the RFQSYS "System" label (four languages) and its thread style. **The cap is raised to 21 KB** in
   `unit-public-ticket.spec.ts` and `evidence-public-ui5.spec.ts`; headroom 985 B. Other public chunks (same build): ticket page
   62,884 B (cap 63,488 B, headroom 604 B), rfq-terms 2,764, rfq-upload 4,047, portal 8,386, portal-more 5,067, consent 3,527,
   claim-prefill 2,377 - all inside their caps. The Windows build output was discarded (bundles are built on the runner).
2. **Token lint (public bundle):** RFQSYS used `var(--sw-border, currentColor)`; the public-bundle lint refuses a literal fallback.
   The fallback is dropped (`--sw-border` is declared for every theme); same colour.

3. **TKRULES migration renumber** (`02fd041f7`): `0122_ticket_rule_fires.sql` -> `0123_ticket_rule_fires.sql`; the references in
   `services/tickets/store_rules.py`, `tests/test_tickets_visibility.py` and `docs/changes/CR-038-TKRULES-NOTES.md` follow.
4. **Token lint (service module)** (`47b99dd6c`): `tickets/settings-rules.ts` (TKRULES) and `tickets/work-calendar-card.ts` (SLACAL)
   used five `var(--sw-x, fallback)` reads of declared tokens; the fallbacks are dropped.
5. **Digest template for `ticket.question`** (`daec9970d`): TKNOTIFMATRIX was cut before ASKNOTE-290, so its `notify_bridge.TEMPLATES`
   (used to send held events at once when a digest fails) lacked the 2.9.0 `ticket.question` source that its own `MATRIX_SOURCES`
   includes. Added; `test_tickets_notify_matrix::test_source_catalogue` caught it.
6. **Ticket SQL in the store** (`ced52d2ec`): SLACAL's `sla.refresh_all_open` read the open ticket ids with its own `SELECT ... FROM
   tickets`; `test_tickets_visibility::test_ticket_sql_lives_in_the_store` refuses ticket SQL outside the store modules. The same query is
   now `store.all_open_ticket_ids`.
