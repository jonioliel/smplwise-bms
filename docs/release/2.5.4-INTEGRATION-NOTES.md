## Content
- `links.validate_public_base_url` accepts `https://<dns-name>` plus at most ONE path segment `^/[a-z][a-z0-9-]{1,31}$` (a trailing `/` is dropped); every other rule
  (https, no IP literal, port 443 only, no query / fragment / userinfo, reserved names) is unchanged. It returns the base including the prefix.
- `links.public_url / handler_url / redeem_url`: with prefix P the URL is `{host}{P}/<x>` (`{host}{P}/#<token>`, `{host}{P}/r/<rid>`) instead of `{host}/t/<x>`; without a
  prefix the output is identical to 2.5.3. The token stays in the fragment. All builders (WhatsApp, e-mail redeem, copy-link, templates) go through these functions.
- `address_probe`: the probe GETs `{P}/healthz` (or `/t/healthz`); a 404 returns `wrong_answer` with `code: not_routed` -> the card says the address is not routed to the handler page.
- The public LISTENER (public_http.py, public_app.py, ROUTES, port 18093) is untouched; Cloudflare rewrites `/support/*` -> `/t/*`. The page bundle still loads its assets and
  calls its API under absolute `/t/...` paths, so the tunnel route `^/t(/.*)?$` is required in addition to the rewrite (documented). The page reads an e-mail redeem path
  under the prefix (`/support/r/<rid>`) as well as `/t/r/<rid>` (state.ts RID_RE). After the token is read, the address bar becomes `/t/` as before.
- UI card "דף המטפלים": placeholder `https://ecc.smplwise.com/support`, a note about the optional single prefix, a sample vendor link; remote read-only behaviour unchanged.
- Docs: user guide section 7 (optional prefix, Cloudflare Rewrite rule, tunnel route and ORDER) and DOCS.md. Rewrite-before-tunnel ordering is UNVERIFIED until the owner's
  address probe passes.
- No migration (last 0084), no new add-on option, API inventory unchanged (version line only).

- `tickets-delete-dialog` hides itself after a successful delete (`done`) and emits `ticket-deleted` + `delete-close` whatever the host does; a 404 on a delete of an id this session just deleted is success;

  ROOT CAUSE NOT REPRODUCED: the mock flow already closed the dialog; the fix makes the dialog independent of the host's event handling. The evidence spec now asserts the dialog is gone and the toast shows.
