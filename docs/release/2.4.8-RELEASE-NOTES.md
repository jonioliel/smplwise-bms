# SmplWise Arx 2.4.8 - Release notes / הערות שחרור

Source of truth for the text below: smplwise_vms/CHANGELOG.md (section 2.4.8, bilingual per item).

## 2.4.8 (pilot) — Access control in Arx, stage 1: native stations and doors, people and entry-log screens behind the per-screen switch (off by default), the Settings page "בקרת כניסה", new access-control permissions, typed reads, the separate background channel
**After installing:** **no database migration** (the sequence stays 0001..0075). **No bridge change** (0.8.0 stays; no restart of the system infrastructure is needed). Reload the installed web app once. A new optional add-on option `wiskey_background_token` (empty by default; see "background channel" below). **The access-control screens do not switch by themselves:** every screen of the access-control area keeps showing the embedded WisKey panel until an administrator switches that one screen to "Arx" (Settings › General › "מתגי מסכי כניסה"; the new stations screen's switch `access.ui.stations` defaults to the embedded panel like the others). **Behaviour change:** reading the people directory and the entry log through Arx now needs the new permissions "access.people.read" / "access.events.read" (the built-in operator, site administrator and system administrator roles have them; **viewer and editor do not**, and custom roles keep exactly the permissions they list). An installation that had already switched "אנשים" or "פעילות" to Arx shows the rebuilt screens, and their tabs are offered only to holders of the new permission; a viewer sees "המסך הזה אינו זמין לך" there. The embedded panel is unchanged (WisKey's own permissions decide inside it). Site and system administrators get a new Settings tab "בקרת כניסה" (read only, except its policy switches). Nothing here was run against a real WisKey: every check ran against fakes; live behaviour is checked in a later stage.
- **עברית:** אחרי ההתקנה: **אין מיגרציה** (הרצף נשאר 0001..0075). **אין שינוי בגשר** (נשאר 0.8.0; אין צורך להפעיל מחדש את תשתית המערכת). טוענים מחדש את אפליקציית הרשת פעם אחת. אפשרות תוסף חדשה ולא חובה `wiskey_background_token` (ריקה כברירת מחדל; ראו "ערוץ הרקע" למטה). **מסכי בקרת הכניסה לא מתחלפים מעצמם:** כל מסך באזור בקרת הכניסה ממשיך להציג את לוח WisKey המוטמע עד שמנהל מעביר את המסך הזה בלבד ל־"Arx" (הגדרות › כללי › "מתגי מסכי כניסה"; גם הבורר של מסך התחנות החדש, `access.ui.stations`, מתחיל במוטמע כמו האחרים). **שינוי התנהגות:** קריאת רשימת האנשים ויומן הכניסות דרך Arx דורשת עכשיו את ההרשאות החדשות "access.people.read" / "access.events.read" (לתפקידים המובנים מפעיל, מנהל אתר ומנהל מערכת יש אותן; **לצופה ולעורך אין**, ותפקידים מותאמים שומרים בדיוק את ההרשאות שרשומות בהם). במערכת שכבר העבירה את "אנשים" או "פעילות" ל־Arx מוצגים המסכים החדשים, והלשוניות שלהם מוצעות רק למי שמחזיק בהרשאה החדשה; צופה רואה שם "המסך הזה אינו זמין לך". הלוח המוטמע לא השתנה (בתוכו ההרשאות של WisKey עצמו קובעות). מנהלי אתר ומנהלי מערכת מקבלים לשונית הגדרות חדשה "בקרת כניסה" (קריאה בלבד, חוץ ממתגי המדיניות שלה). שום דבר כאן לא הורץ מול WisKey אמיתי: כל הבדיקות רצו מול תחליפים; ההתנהגות החיה נבדקת בשלב מאוחר יותר.

### Stations and doors in Arx (CR-036 S6) - תחנות ודלתות ב־Arx
- **English - what was added:** a native screen "תחנות ודלתות" for the access-control area's devices tab: every station as a card, a list or a table (the table gives up columns on narrower windows instead of hiding the door buttons; no table under 820 px), filters (all / online / needs attention / in a call), search, a place tree (on a phone a sheet), a strip for an active call and the connection badge (live / last update / not connected). A station's drawer shows a still, the place, when it was last seen, the call, the doors, announcing, and - for holders of "access.stations.read" - the technical part (sync, model, firmware, relays, clock, last error where allowed) and the door settings as view only (hold-open programs; whether a public code is configured, never its value). An incoming call shows a hint on the card without the caller's name. When the connection drops the last known copy stays readable and every physical control is withdrawn.
- **English - door release, calls and announcements:** they still use the existing paths and the existing permission ("access.release", installation-wide) until the writes stage: one confirmation sends exactly one request, never retried, and the screen says "sent" with the time - never "opened"; an unknown outcome is amber ("check on site before sending again") and the relay stays held as long as the server says. Answer / decline / hang up need two taps (the first arms for 4 seconds). The talk button opens the classic (embedded) panel for that visit (`?classic=1`), it changes no setting. Announcing goes to one station, a place or all stations the operator sees, one request per station, a failure at one never repeats or stops the rest.
- **English - how to enable:** Settings › General › "מתגי מסכי כניסה" › the row "תחנות ודלתות" › "Arx" (setting `access.ui.stations`, default "WisKey (מוטמע)" - choosing it again is the rollback). Four new administrator settings shape the screen only: `access.call_hint` (everyone | call - who sees the incoming-call hint), `access.talk_button` (classic | hidden), `access.announce_scope` (scope | station), `access.announce_phrases` (the quick phrases, one per line, up to 8). They have no Settings row yet and are changed through `PATCH /settings` (system administrators; audited).
- **עברית - מה נוסף:** מסך Arx בשם "תחנות ודלתות" ללשונית ההתקנים של אזור בקרת הכניסה: כל תחנה ככרטיס, ברשימה או בטבלה (הטבלה מוותרת על עמודות בחלון צר במקום להסתיר את כפתורי הדלת; מתחת ל־820 פיקסלים אין טבלה), מסננים (הכול / מחוברות / דורשות תשומת לב / בשיחה), חיפוש, עץ מקומות (בטלפון גיליון), פס לשיחה פעילה ותג החיבור (חי / עדכון אחרון / לא מחובר). מגירת התחנה מציגה תמונת מצב, מקום, מתי נראתה לאחרונה, את השיחה, הדלתות, ההכרזה, ולמחזיקי "access.stations.read" - את החלק הטכני (סנכרון, דגם, קושחה, ממסרים, שעון, שגיאה אחרונה כשמותר) ואת הגדרות הדלת לצפייה בלבד (תוכניות החזקה פתוחה; האם מוגדר קוד ציבורי, לעולם לא הערך). שיחה נכנסת מציגה רמז בכרטיס בלי שם המתקשר. כשהחיבור נופל, העותק האחרון נשאר קריא וכל בקרה פיזית יורדת מהמסך.
- **עברית - פתיחת דלת, שיחות והכרזות:** עדיין עוברות בנתיבים הקיימים ובהרשאה הקיימת ("access.release", בכל ההתקנה) עד שלב הכתיבות: אישור אחד שולח בקשה אחת בדיוק, בלי ניסיון חוזר, והמסך אומר "נשלח" עם השעה - לעולם לא "נפתח"; תוצאה לא ידועה מוצגת בכתום ("בדקו במקום לפני שליחה נוספת") והממסר נשאר תפוס כל עוד השרת אומר. מענה / דחייה / ניתוק דורשים שתי נגיעות (הראשונה דורכת ל־4 שניות). כפתור הדיבור פותח את הלוח הקלאסי (המוטמע) לביקור הזה (`?classic=1`) ולא משנה שום הגדרה. הכרזה נשלחת לתחנה אחת, למקום או לכל התחנות שהמפעיל רואה, בקשה אחת לכל תחנה, וכישלון באחת לא חוזר ולא עוצר את השאר.
- **עברית - איך מפעילים:** הגדרות › כללי › "מתגי מסכי כניסה" › השורה "תחנות ודלתות" › "Arx" (ההגדרה `access.ui.stations`, ברירת מחדל "WisKey (מוטמע)" - בחירה חוזרת בה היא החזרה לאחור). ארבע הגדרות מנהל חדשות מעצבות את המסך בלבד: `access.call_hint` (everyone | call - מי רואה את רמז השיחה הנכנסת), `access.talk_button` (classic | hidden), `access.announce_scope` (scope | station), `access.announce_phrases` (המשפטים המהירים, אחד בשורה, עד 8). עדיין אין להן שורה בהגדרות, ומשנים אותן דרך `PATCH /settings` (מנהלי מערכת; נרשם ביומן).

### People in Arx (CR-036 S7) - אנשים ב־Arx
- **English - what was added:** the native "אנשים" screen is rebuilt on the new typed reads: search (name, and the employee number where you may see it), filters by station, group, rights and state (active / inactive / expired / upcoming / archived), sort, "load more" paging that keeps its place, cards / list / table (the table from 1000 px), selection. A person's page (a drawer) shows details, validity and timing, access per station with its sync state (error texts only for administrators or when the policy allows), groups, and - for holders of "access.people.sensitive" - the phone, the credential kinds (has a PIN, how many cards; never a number, a mask or the PIN) and the photo, fetched only on "הצג תמונה" (each view is audited). "עריכה" and "הוספת אדם" open the existing person editor unchanged. The employee number is a normal column unless the administrator marks it sensitive.
- **English - WhatsApp messages: not active.** The message dialog exists only as a user interface over a fake: there is no send path in this release (no server route, nothing calls WisKey's messaging), and on a real system the dialog is never offered because the server does not report messaging as available. It is shown only in the demo preview and in the tests.
- **English - how to enable:** Settings › General › "מתגי מסכי כניסה" › the row "אנשים" › "Arx" (`access.ui.people`, default the embedded panel). The tab is then offered only to holders of "access.people.read".
- **עברית - מה נוסף:** מסך "אנשים" של Arx נבנה מחדש על הקריאות המסודרות החדשות: חיפוש (שם, ומספר עובד כשמותר לראות אותו), מסננים לפי תחנה, קבוצה, הרשאות ומצב (פעיל / לא פעיל / פג תוקף / עתידי / בארכיון), מיון, "טען עוד" ששומר על המקום, כרטיסים / רשימה / טבלה (הטבלה מ־1000 פיקסלים), בחירה מרובה. דף האדם (מגירה) מציג פרטים, תוקף ושעות, גישה לכל תחנה עם מצב הסנכרון (טקסט השגיאה רק למנהלים או כשהמדיניות מתירה), קבוצות, ולמחזיקי "access.people.sensitive" - טלפון, סוגי האמצעים (יש קוד, כמה כרטיסים; לעולם לא מספר, מסכה או הקוד עצמו) ותמונה שנטענת רק ב־"הצג תמונה" (כל צפייה נרשמת ביומן). "עריכה" ו"הוספת אדם" פותחים את עורך האדם הקיים ללא שינוי. מספר העובד הוא עמודה רגילה אלא אם המנהל סימן אותו כרגיש.
- **עברית - הודעות WhatsApp: לא פעיל.** חלון ההודעה קיים רק כממשק מעל תחליף: אין בגרסה הזו דרך לשלוח (אין נתיב בשרת, שום דבר לא פונה להודעות של WisKey), ובמערכת אמיתית החלון לא מוצע לעולם כי השרת לא מדווח שההודעות זמינות. הוא מופיע רק בתצוגת ההדגמה ובבדיקות.
- **עברית - איך מפעילים:** הגדרות › כללי › "מתגי מסכי כניסה" › השורה "אנשים" › "Arx" (`access.ui.people`, ברירת מחדל הלוח המוטמע). הלשונית מוצעת אז רק למחזיקי "access.people.read".

### The entry log in Arx (CR-036 S8) - יומן הכניסות ב־Arx
- **English - what was added:** the native "פעילות" screen is rebuilt on the typed reads: periods are days of the station's clock zone (a wall time that a daylight-saving change repeats or skips is refused, never guessed), filters (station, result, authentication, door, period, a person search), grouping, a drawer per entry that says how the identity and the time were established, and the entry's picture - fetched once per opened row, only when the entry has one, each view audited by default. New entries: with one page shown the list refreshes, with more pages you keep your place and are offered a refresh. Export to CSV for holders of "access.events.export" (a person who does not see every station picks one); print of the rows on screen. A failed reload keeps the rows and marks them with the time they were read. A link like `#/wiskey/events?station=<id>&result=denied` opens the screen filtered.
- **English - how to enable:** Settings › General › "מתגי מסכי כניסה" › the row "פעילות" › "Arx" (`access.ui.events`, default the embedded panel). The tab is then offered only to holders of "access.events.read".
- **עברית - מה נוסף:** מסך "פעילות" של Arx נבנה מחדש על הקריאות המסודרות: תקופות הן ימים לפי אזור הזמן של שעון התחנה (שעה שמעבר שעון קיץ / חורף חוזר עליה או מדלג עליה נדחית, ולא מנוחשת), מסננים (תחנה, תוצאה, אמצעי זיהוי, דלת, תקופה, חיפוש אדם), קיבוץ, מגירה לכל כניסה שאומרת איך נקבעו הזהות והזמן, ותמונת הכניסה - נטענת פעם אחת לכל שורה שנפתחת, רק כשיש לכניסה תמונה, וכל צפייה נרשמת ביומן כברירת מחדל. כניסות חדשות: כשמוצג עמוד אחד הרשימה מתרעננת, כשמוצגים כמה עמודים נשארים במקום ומקבלים הצעה לרענן. ייצוא ל־CSV למחזיקי "access.events.export" (מי שלא רואה את כל התחנות בוחר אחת); הדפסה של השורות שעל המסך. טעינה חוזרת שנכשלה משאירה את השורות ומסמנת מתי נקראו. קישור כמו `#/wiskey/events?station=<id>&result=denied` פותח את המסך מסונן.
- **עברית - איך מפעילים:** הגדרות › כללי › "מתגי מסכי כניסה" › השורה "פעילות" › "Arx" (`access.ui.events`, ברירת מחדל הלוח המוטמע). הלשונית מוצעת אז רק למחזיקי "access.events.read".

### Settings › "בקרת כניסה": status, intercom log, groups, policy (CR-036 S10) - הגדרות › "בקרת כניסה": מצב, יומן האינטרקום, קבוצות, מדיניות
- **English - what was added:** a new Settings tab "בקרת כניסה" (after "חיבורים") for holders of "access.admin.read" (site and system administrators), in four parts: "מצב מערכת" (stations online, sync counts, alerts with their muted reason, conflicts for installation-wide administrators, and a station card with health and a seven-day strip in the station's own days), "יומן האינטרקום" (what was done in the intercom's own window - the names of the changed fields, never their values; Arx's own actions stay in Arx's audit), "קבוצות ושדות" (each group's stations as names, the field definitions where allowed) and "מדיניות". The page only reads, once a minute while it is visible; it never asks a device to refresh and offers no acknowledge, mute, resolve or export. Each card stands alone: a failed read keeps the last good one marked "not current", a refused one disappears. The settings search finds it ("בקרת כניסה", "אינטרקום", "סנכרון", "התרעות").
- **English - the policy part:** four administrator switches decided by the owner's answers of 2026-10-12, saved at once and audited: "תיעוד צפייה בתמונת אירוע" (`access.event_portrait_audit`, on), "תמונת אירוע כפרט רגיש" (`access.event_portrait_sensitive`, off), "מספר עובד כפרט רגיש" (`access.employee_no_sensitive`, off), "שגיאות סנכרון לכולם" (`access.sync_errors_everyone`, off). A value the server cannot read is shown as the safe choice it acts on.
- **English - how to use:** Settings › "בקרת כניסה" (the policy part needs the system configuration permission).
- **עברית - מה נוסף:** לשונית הגדרות חדשה "בקרת כניסה" (אחרי "חיבורים") למחזיקי "access.admin.read" (מנהלי אתר ומנהלי מערכת), בארבעה חלקים: "מצב מערכת" (תחנות מחוברות, ספירות סנכרון, התרעות עם סיבת ההשתקה, התנגשויות למנהלים של כל ההתקנה, וכרטיס תחנה עם בריאות ופס של שבעה ימים לפי הימים של התחנה), "יומן האינטרקום" (מה נעשה בחלון של האינטרקום עצמו - שמות השדות שהשתנו, לעולם לא הערכים; הפעולות של Arx נשארות ביומן של Arx), "קבוצות ושדות" (התחנות של כל קבוצה בשמות, הגדרות השדות כשמותר) ו"מדיניות". הדף רק קורא, פעם בדקה כשהוא גלוי; הוא לא מבקש מהתקן להתרענן ולא מציע אישור, השתקה, פתרון או ייצוא. כל כרטיס עומד בפני עצמו: קריאה שנכשלה משאירה את האחרונה הטובה מסומנת "לא עדכני", קריאה שנדחתה נעלמת. חיפוש ההגדרות מוצא אותו ("בקרת כניסה", "אינטרקום", "סנכרון", "התרעות").
- **עברית - חלק המדיניות:** ארבעה מתגי מנהל שנקבעו בתשובות הבעלים מ־2026-10-12, נשמרים מיד ונרשמים ביומן: "תיעוד צפייה בתמונת אירוע" (`access.event_portrait_audit`, מופעל), "תמונת אירוע כפרט רגיש" (`access.event_portrait_sensitive`, כבוי), "מספר עובד כפרט רגיש" (`access.employee_no_sensitive`, כבוי), "שגיאות סנכרון לכולם" (`access.sync_errors_everyone`, כבוי). ערך שהשרת לא מצליח לקרוא מוצג כבחירה הבטוחה שלפיה הוא פועל.
- **עברית - איך משתמשים:** הגדרות › "בקרת כניסה" (חלק המדיניות דורש הרשאת הגדרת מערכת).

### Access-control permissions, typed reads and the background channel (CR-036 S0, S1, S3, S4) - הרשאות בקרת כניסה, קריאות מסודרות וערוץ הרקע
- **English - what was added:** ten new permissions in the roles screen, labelled in Hebrew: "access.stations.read", "access.events.read", "access.events.export", "access.people.read", "access.people.sensitive", "access.admin.read", and four that are catalogue entries only until the writes stage ("access.call", "access.schedules.manage", "access.stations.manage", "access.groups.manage"). One server-side filter decides what every access-control read returns: what a caller may not see is left out (never greyed), a single read of something hidden answers exactly like a missing one, totals are given only to callers who see everything, and a search or sort on a field the caller cannot see is never handed to the intercom. 25 read-only routes `GET /api/v1/access-control/...` serve the new screens; the browser never talks to WisKey. The older reads `/intercom/events`, `/intercom/people`, `/intercom/people/{id}` go through the same filter. The station overview's background copy no longer holds the last person who passed each station; the native "מרכז הכניסה" therefore no longer shows "recent activity", a last access per station, total users or pending sync.
- **English - background channel:** WisKey reads now use separate channels with their own allow-lists (people / events reads apart from the writes); a new diagnostics card in Settings › General › "מתגי מסכי כניסה" ("WisKey רואה את Arx כ־", system administrators) shows which identity WisKey sees for each. The new add-on option `wiskey_background_token` takes the long-lived token of a dedicated non-administrator user the owner creates for the background channel; empty = the channel shares the add-on's own identity, as before, and the card says so. Door, call, announcement, people and card-reader writes keep the add-on's own user.
- **English - how to enable:** nothing to switch on for the permissions (they come with the built-in roles; add them to a custom role in Settings › "משתמשים והרשאות" › "תפקידים"). The background token is optional: add-on configuration › `wiskey_background_token`.
- **עברית - מה נוסף:** עשר הרשאות חדשות במסך התפקידים, עם תוויות בעברית: "access.stations.read", "access.events.read", "access.events.export", "access.people.read", "access.people.sensitive", "access.admin.read", וארבע שהן רק רשומות בקטלוג עד שלב הכתיבות ("access.call", "access.schedules.manage", "access.stations.manage", "access.groups.manage"). מסנן אחד בשרת קובע מה כל קריאת בקרת כניסה מחזירה: מה שאסור למבקש לראות לא נשלח (ולא מוצג באפור), קריאה בודדת של דבר מוסתר עונה בדיוק כמו דבר שלא קיים, סיכומים ניתנים רק למי שרואה הכול, וחיפוש או מיון לפי שדה שהמבקש לא רואה לא מועבר לאינטרקום. 25 נתיבי קריאה `GET /api/v1/access-control/...` משרתים את המסכים החדשים; הדפדפן לא פונה ל־WisKey לעולם. הקריאות הישנות `/intercom/events`, `/intercom/people`, `/intercom/people/{id}` עוברות באותו מסנן. העותק ברקע של סקירת התחנות כבר לא מחזיק את האדם האחרון שעבר בכל תחנה; לכן "מרכז הכניסה" של Arx כבר לא מציג "פעילות אחרונה", כניסה אחרונה לכל תחנה, סך המשתמשים או ממתינים לסנכרון.
- **עברית - ערוץ הרקע:** הקריאות מ־WisKey עוברות עכשיו בערוצים נפרדים עם רשימות היתר משלהם (קריאות אנשים / אירועים בנפרד מהכתיבות); כרטיס אבחון חדש בהגדרות › כללי › "מתגי מסכי כניסה" ("WisKey רואה את Arx כ־", מנהלי מערכת) מראה איזו זהות WisKey רואה בכל אחד. אפשרות התוסף החדשה `wiskey_background_token` מקבלת טוקן ארוך־טווח של משתמש ייעודי שאינו מנהל, שהבעלים יוצר לערוץ הרקע; ריקה = הערוץ משתמש בזהות של התוסף עצמו, כמו קודם, והכרטיס אומר זאת. כתיבות של דלת, שיחה, הכרזה, אנשים וקורא כרטיסים ממשיכות עם המשתמש של התוסף.
- **עברית - איך מפעילים:** אין מה להפעיל בהרשאות (הן מגיעות עם התפקידים המובנים; לתפקיד מותאם מוסיפים אותן בהגדרות › "משתמשים והרשאות" › "תפקידים"). טוקן הרקע לא חובה: הגדרות התוסף › `wiskey_background_token`.
