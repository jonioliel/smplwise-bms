## Behaviour changes

- `X-Correlation-Id` (SX-17, all requests): a client value is used only when it is exactly one header value of 8-64 characters from `[A-Za-z0-9_-]`; otherwise the server generates a fresh id. A malformed or repeated client value is no longer reflected into the `X-Correlation-Id` response header, an error body, an audit row or a log. The FastAPI middleware and the body-size refusal share `smplwise/correlation_id.py`.
- While `security.app_session_exchange` is on (it is off by default):
  - the redeem requires exactly one `X-Correlation-Id` of 12-32 hex characters (`marker_missing` otherwise) and refuses a browser holding another user's live Arx session (`session_present`); both refusals spend the code and are audited; the 303 answers are unchanged;
  - `POST /presence/devices` from an app WebView session answers `403 sign_in_not_anchorable` (audited);
  - unknown / expired codes are audited (`code_unknown`, `code_expired`); a cross-site / same-site redeem refusal is audited (`cross_site`).
- Frontend (only inside the phone-app shell): the page calls `ArxApp.signedOut({reason})` with `user` | `expired` | `unknown`; an older shell without the argument keeps working.
