# SmplWise Arx 2.19.0 - Release notes

Status: release candidate on `release/2190`. Version metadata is bumped to 2.19.0 and `contracts/API_INVENTORY.md` is regenerated. The final gate has not been run on this head and no tag exists; the receipt below is filled in by the lead.

## Migrations

This version adds exactly three migrations on top of 2.18.0, whose last migration is `0173_notice_board_token_sealed.sql`:

| Number | File | Feature | Switch |
|---|---|---|---|
| 0174 | `0174_app_web_sessions.sql` | WebView session through a one-time code (SESSIONEXCH2-295) | `security.app_session_exchange`, default off |
| 0175 | `0175_offline_field.sql` | Offline field work, server half (OFFLINE110-295 slice 1) | feature switch, default off |
| 0176 | `0176_app_refresh_attestation.sql` | Device hardware attestation verdicts (ATTEST232-295) | default off |

The chain 0001..0176 is contiguous with no duplicate numbers. All three migrations are additive (new tables or one nullable column); the previous version ignores them, so rollback is "run the previous add-on version". Inside the SQL header comments of 0175 and 0176 an older provisional number is still mentioned ("0172", "0160"); this is comment text only, the file names are authoritative.

## Contents

Nothing below is switched on by installing this version; every new behaviour is behind a default-off setting unless stated otherwise. Anything touching WisKey, push relays, mobile hardware attestation or door hardware was tested against test doubles only.

### Phone app and sign-in
- WebView session through a one-time code (SESSIONEXCH2-295, migration 0174): the native app obtains a short-lived single-use code and the WebView redeems it with a top-level navigation. Off by default (`security.app_session_exchange`).
- Device hardware attestation (ATTEST232-295, migration 0176): a server-side verifier layer for the app-refresh device key (Android Key Attestation, iOS App Attest). Verdict only is stored, never the chain. Default off.
- A user is notified when their own sign-out releases the device key (APPREFRESH3-295, owner Q312).
- Security review fixes (SEC217): the four fix-before-enable findings of the 2.16.0 security review.
- Fix: a latent duplicate OpenAPI operation id for `GET/HEAD auth/app-download/file` (see "Fixed").

### Offline field work (server half)
- OFFLINE110-295 slice 1 (migration 0175): the technician's work bundle, device lock and wipe, replay of offline changes with their outcome, manager review of held changes, the day-list receipt, and round points whose signed QR / NFC tags are verified on the server. Default off.

### Critical-sound alerts
- CRITSOUND (relay + server + settings): the push relay accepts `critical_alert` and `resolved_tone`; the server sends them for the safety event types an administrator chooses; the Settings switch is per type. Default off. The wire contract for the mobile teams is in `CRITSOUND-SPEC.md`.

### Service requests and vendors
- PHYSENTRY070-295: "physical entry required" after assignment, and a vendor notice on cancel. Default off.
- Vendor "I have arrived" card on the existing visits flow (VENDORARRIVAL126B; supersedes the parallel VENDORARRIVAL126 backend).
- READY96: a score chip on the "readiness" settings entry.
- SERVICEIA3-295: entry-address redirects of service management wait for the saved settings (`ui.tabs`), with a regression test.

### WisKey (fakes only, nothing run against a real WisKey, station or go2rtc)
- WKAUDIN-295: listening to a station - the Arx receiver, session, speaker, meter and mute over a synthetic downlink.
- WKLIVE-295: the leased WisKey station stream is removed from go2rtc when its last viewer leaves, and old leases are swept.
- WKOPENUNK-295: an explicit new OPEN attempt for a door whose emergency OPEN ended UNKNOWN (administrator, door name typed, one at a time, audited).
- WKCAPWIRE-295: WisKey's three delivered synthetic vectors are consumed in CI.
- KAVDEVTEST-295: on-device test for schedules (plan route with allow-listed actions only; the plan never sends; one-time list confirmation; one run at a time).

### Documentation only (no behaviour)
- Change records: CR-INTAKE99 (free-text request intake and a requester page without an account), CR-OCR119 (reading vendor PDFs and images), CR-VOICE143 (voice announcements), CR-VISITOR105 (visitor pre-registration with a temporary door code - design only).
- Session-exchange contract drafts and the revision 3 spec (owner decisions 427-432).
- DOCSHOTS053-295: guide screenshots for the temperature report dialog.

### Fixed
- OpenAPI: `GET` and `HEAD` of `auth/app-download/file` were registered as one `api_route`, so both methods shared one operation id and FastAPI printed "Duplicate Operation ID app_download_file_...". The route is now a `GET` (in the schema) plus a `HEAD` (hidden from the schema). Runtime behaviour is unchanged (GET, HEAD, ETag/304, ranges, rate limit); `contracts/API_INVENTORY.md` already skips HEAD, so it does not change. Regression test `test_file_route_has_unique_openapi_operation_ids`.
