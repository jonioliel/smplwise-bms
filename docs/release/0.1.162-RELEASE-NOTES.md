# SmplWise Arx 0.1.162 - Release notes / הערות שחרור

Source of truth for the text below: smplwise_vms/CHANGELOG.md.

## 0.1.162 (pilot) — Schedules: scripts and every action the integration offers; change the encoding of many cameras at once; the capsule dropdown style; compact media settings lists; a friendly name for every meter; music server connection hardening
**After installing, restart the platform once:** the bridge integration moves to **0.6.1** (its schedule allow-list grows; Home Assistant loads it on restart). Until then the new schedule actions are refused with "נדרש עדכון של רכיב החיבור" and everything else works as before. **No database migration in this release** (the last one stays `0054_electricity_billing`); the new settings are created on first use. Reload the installed web app once.
### Schedules: scripts and more actions
- **Scripts are first-class actions:** pick a script by its name and area, fill its variables (the fields the script declares: number, yes / no, a list, text), run it now, copy, split and restore it like any schedule. An alarm script is an ordinary script, with the same rights as running it by hand (an alarm script that disarms needs the disarm permission at that panel, the sensitive-schedules permission and the explicit confirmation).
- A schedule made in the platform that calls a script as its own service is now shown as a script action (name, area, variables), editable; the "content the system does not display fully" mode remains only for content Arx truly cannot model.
- **New actions:** scenes, helpers (on / off, a number, a list option), humidifiers (humidity, mode), vacuums (start, return to base), cover tilt (open / close) and climate swing and humidity.
- **Only what the device really supports:** the action list and the value ranges come from each device's own capabilities (feature bits, modes, options, min / max); an action the device does not report is never offered, and the server refuses it.
- **An action that is no longer valid** (its device was removed or lost the capability) is shown on the card ("פעולה לא תקפה") and in the schedule, "run now" is refused with the reason, a run the platform fires anyway is recorded at once as not confirmed and the administrators are told, and the schedule stays editable so it can be fixed.
- **Alarm safety - disarming is no longer schedulable by default.** A system administrator may allow it in הגדרות › תזמונים › "נטרול אזעקה בתזמונים" by typing "אפשר נטרול"; every change of this setting is audited (`schedules.allow_disarm`). A disarm that needs a code is never schedulable, whatever the setting. An existing disarm schedule is kept as it is (with a warning); copying it is a new disarm.
- **Review: "אשר כתקין".** In the schedules review list a system administrator can mark "תזמון רגיש שנוצר מחוץ למערכת" and "תוכן שהמערכת אינה מציגה במלואו" as fine from our side: the chip becomes a muted "אושר" (with "בטל אישור"), the "needs review" count drops, and the warning returns by itself when the schedule's content changes. The acknowledgement never changes the schedule; both directions are audited (stored in the setting `schedules.acks`).
### Change the encoding of many cameras at once - מערכת › אבטחה › מצלמות › "שינוי קידוד לכמה מצלמות"
- A holder of `nvr.configure` chooses streams (main, sub or both; filters by codec, SVC and WebRTC; "select all"), sets the new values - codec (H.264 / H.265), resolution, frame rate, bitrate mode, bitrate, quality, GOP, SVC, smart codec, each "ללא שינוי" by default - and sees a **preview** before anything is written: per stream before → after, values adjusted to what that camera allows (the closest resolution, a bitrate inside its range, the profile the new codec needs), streams that cannot be changed and why. **One confirmation**, then the same server-side batch as the multi-camera SVC change: one camera at a time, live progress, "עצור", a result list and undo-all.
- Safety: the server re-plans from a fresh reading at the start and refuses when a camera changed since the preview (`stale` / `plan_changed`); every planned value passes the single-stream validation, so an invalid write is never sent; all the protections of the multi-camera change stay (stop at the first failure, the unknown-outcome check after 45 s, a hard deadline per camera, single changes refused while it runs, the permission re-checked before each camera, batch state never in a backup). The two new routes (`POST /api/v1/nvr/encoding-batches/preview`, `POST /api/v1/nvr/encoding-batches`) and the undo of such a batch are refused on the remote channel.
### The capsule dropdown style and a size dial for every dropdown - הגדרות › לשוניות
- **A new dropdown style, capsule (קפסולה), opt-in:** closed, a capsule with a clear blue ring, a soft fill, an icon at the start, a confident label and a small chevron at the other end; open, a floating, rounded, translucent panel with the chosen row tinted, an icon at the start of every row, a **count** at the other end and a thin divider after "הכל". On a phone it opens as the bottom sheet (or the small list). Works in all four looks, light and dark, the ten palettes and the radius / touch / performance dials; keyboard and screen-reader behaviour are unchanged. The area chip of the devices screens and the rooms chips of the multimedia pages supply icons and counts for it.
- **Dropdown size: קטן / רגיל / גדול** for every style (trigger height, font, icon, row height, panel padding); regular is today's size. Touch targets keep 44 px on a phone and on the 44 px desktop dial.
- **Capsule ring thickness** (1 / 1.5 / 2 / 3 px, default 2) and **open-panel width** ("as wide as the button" / 240 / 300 px, default 240; the size dial scales it). The existing style **pill** is now labelled **"כדור מלא"** so it is not confused with the capsule (only the Hebrew label changed; the id `pill` and stored values stay).
- Every new dial works like the style: all groups or per group, installation default (system administrator; `ui.dd_size`, `ui.dd_ring`, `ui.dd_panel` and their `_groups` twins) and a personal choice ("ההעדפה שלי") with a reset button, validated on the server, with a live preview. **Nothing changes until a style or a size is chosen.** Dropdown items accept `icon` and `divider` (a divider is never selectable).
### Settings › Multimedia: compact, filterable lists of screens and of speakers / players
- **Compact rows:** each screen / speaker / player is one dense row (name, type, integration, entity id and device id with a copy key, room, status, approval, connections count); the full form opens under the row on demand. Every field, action, permission and the "approve all" buttons are unchanged.
- **Integration and ids (settings only):** the registry platform of each component and the platform's entity id and device id. API: `GET multimedia/admin/devices` adds `integrations`, `ha_device_id` and `available` to every device (`available` was players-only before).
- **Filters, sort and group:** free text (also matches ids and integration names), integration (multi-select), room, type, approval, availability, with a count and "נקה סינון"; sort by name, type, integration, room, id or status (also from the column headers); group by integration, room or type with collapsible headers and counts.
- **Columns:** a "עמודות" control shows or hides type, integration, entity id, device id, room, floor, status and connections. Defaults are today's, so nothing changes until the user picks; "ברירת מחדל" resets; remembered per user and per list in the browser; not shown on a phone (cards keep every field).
### Electricity: a friendly name for every meter, set when it is added and changeable later
- "הוספת מונה" shows a name field for every picked sensor, pre-filled from the device name (else the sensor name); required, trimmed, at most 120 characters. The meter card has "שינוי שם" (only with `energy.manage`); a revision conflict is explained in Hebrew. The change is audited (`energy.meter.update`, old and new name).
- **Duplicate names are refused** on create and on rename: the server compares the trimmed, case-insensitive name with every meter that is not retired (paused ones count) and answers 409 `meter_name_taken`; the screen says "קיים כבר מונה בשם הזה, לא ניתן להקים שני מונים באותו שם". Duplicates that already exist in the data are left alone and never block other edits.
- The new name appears in pickers, lists, the account wizard and every NEW draft or bill; **bills that were already issued keep the name they were sealed with**. The device and sensor names stay visible as secondary text.
### Music server connection hardening (CR-016 section 18)
- **The music server token is encrypted at rest** (AES-256-GCM, the same key file and store as the NVR connection). No plain file any more; never returned, logged, audited or backed up. On the first start after the update a token kept in a plain file is encrypted, verified and the plain file deleted (if the move fails the file stays, the connection keeps working, and the move is retried at the next start).
- **Server address check:** only a private home-network address; this system's own address, the internet, internal platform addresses and addresses with credentials are refused with a clear message. The connection goes to the checked address and never follows redirects.
- **The connection screen is local only** (not reachable through remote access); the connection test is limited to 5 a minute per user; a hard 10-second budget on every call to the music server, with a clear Hebrew refusal for every state.
- **Recovery / downgrade:** if the encryption key is lost the connection shows "token unreadable" and the token must be entered again (start-up never fails because of it). The older version cannot read the encrypted token; after a downgrade its settings show "not set" until the token is entered again.
### How to turn it on and use it (English)
1. Install the update, **restart the platform once** (bridge 0.6.1), reload the installed web app once. Nothing to migrate.
2. Schedules: הגדרות › תזמונים › "סוגי התקנים מותרים בתזמון" - scripts, scenes, helpers, humidifiers and vacuums are on (an installation that had every class on keeps every class on); switch off what you do not want scheduled. In a schedule's editor "בחירת התקנים" lists the new devices; in the slot panel choose the action and, for a script, fill "משתני הסקריפט". Review: תזמונים › "לבדיקה" → "אשר כתקין" ("בטל אישור" restores it).
3. Scheduled disarming (only if wanted): הגדרות › תזמונים › "נטרול אזעקה בתזמונים" → type "אפשר נטרול" (system administrator). It is off by default.
4. Bulk encoding: sign in as a system administrator → מערכת › אבטחה › מצלמות → "שינוי קידוד לכמה מצלמות" → tick streams → "המשך" → set only what should change → "תצוגה מקדימה" → "החל על N זרמים" → confirm once. "עצור" stops after the current camera; "בטל את מה שנשמר" undoes the batch. No setting to enable.
5. Capsule dropdown: הגדרות › לשוניות › "סגנון תפריט נפתח" → **קפסולה** (all groups or one group; the groups must be in "תפריטים נפתחים" or "משולב" mode in "תצוגת לשוניות"). Size, ring and panel width are in the same card; "ההעדפה שלי" applies to you only.
6. Media lists: הגדרות › מולטימדיה - filters, grouping and "עמודות" are on the toolbar; nothing to enable.
7. Meter names: תשתיות › מוני חשמל › מונים → a meter → "שינוי שם" → save; when adding, edit the pre-filled name before "הוספה".
8. Music connection: nothing to do; check הגדרות › מולטימדיה › חיבור shows the token as set and the state "connected". If the next test refuses the address, enter the server's home-network IP address and port 8095.
### Known limits
- **Nothing in this release was run against a real system:** schedules ran against the fake scheduler and the fake bridge (no real installation, no real alarm); the bulk encoding ran against a fake recorder only - **no real camera was written, and the first real bulk change on the lab recorder is done by the owner**; the real recorder's per-codec capability documents on the lab firmware are still unverified.
- A script's variables of kinds the schedules do not model (device / area pickers, templates) are not offered; a required one makes the script unschedulable with the reason. A script whose content Arx cannot read is treated as sensitive and runs without variables. Not added on purpose: sirens, media players, `number` / `select` entities, notifications.
- The floor chips with their own menu on the multimedia players and screens pages ("כל הקומות") are hand-built menus, not restyled by the dropdown style. Ring widths of 1 and 1.5 px show only on retina screens.
- After a downgrade below 0.1.162 the music token must be entered again.

## עברית — 0.1.162: תזמונים: סקריפטים וכל פעולה שהאינטגרציה מציעה; שינוי קידוד לכמה מצלמות; סגנון "קפסולה" לתפריט נפתח; רשימות מולטימדיה קומפקטיות בהגדרות; שם ידידותי לכל מונה; הקשחת החיבור לשרת המוזיקה
**אחרי ההתקנה יש להפעיל מחדש את תשתית המערכת פעם אחת:** הגשר עולה ל-**0.6.1** (רשימת הפעולות המותרות בתזמונים גדלה; התשתית טוענת אותה בהפעלה מחדש). עד אז הפעולות החדשות בתזמונים נדחות עם "נדרש עדכון של רכיב החיבור" וכל השאר עובד כרגיל. **אין מיגרציה של בסיס הנתונים בשחרור הזה** (האחרונה נשארת `0054_electricity_billing`); ההגדרות החדשות נוצרות בשימוש הראשון. יש לטעון מחדש את אפליקציית הרשת המותקנת פעם אחת.
### תזמונים: סקריפטים ופעולות נוספות
- **סקריפט הוא פעולה מלאה:** בוחרים סקריפט לפי שמו ואזורו, ממלאים את המשתנים שלו (מספר, כן / לא, רשימה, טקסט), מריצים עכשיו, מעתיקים, מפצלים ומשחזרים כמו כל תזמון. סקריפט אזעקה הוא סקריפט רגיל, עם אותן הרשאות כמו הפעלה ידנית (סקריפט שמנטרל אזעקה דורש הרשאת נטרול בלוח הזה, הרשאה לתזמון פעולות רגישות ואישור מפורש).
- תזמון שנוצר בתשתית וקורא לסקריפט כשירות משלו מוצג עכשיו כפעולת סקריפט (שם, אזור, משתנים) וניתן לעריכה; מצב "התזמון כולל תוכן שהמערכת אינה מציגה במלואו" נשאר רק לתוכן שהמערכת באמת אינה יודעת לייצג.
- **פעולות חדשות:** סצנות, מתגי עזר (הפעלה / כיבוי, ערך מספרי, בחירה מרשימה), מכשירי לחות (לחות, מצב), שואבים רובוטיים (התחלת ניקוי, חזרה לעמדה), הטיית תריסים (פתיחה / סגירה), ומצב נדנוד ולחות במזגנים.
- **רק מה שההתקן באמת תומך בו:** רשימת הפעולות וטווחי הערכים נקבעים לפי היכולות שכל התקן מדווח; פעולה שההתקן אינו מדווח לא מוצעת, והשרת דוחה אותה.
- **פעולה שאינה תקפה עוד** (ההתקן הוסר או איבד את היכולת) מסומנת בכרטיס ("פעולה לא תקפה") ובתזמון, "הרץ עכשיו" נדחה עם הסיבה, ריצה שהתשתית מפעילה בכל זאת נרשמת מיד כ"לא אושרה" והמנהלים מקבלים התראה, והתזמון נשאר ניתן לעריכה.
- **בטיחות אזעקה - נטרול אזעקה כבר אינו ניתן לתזמון כברירת מחדל.** מנהל מערכת יכול לאפשר זאת בהגדרות › תזמונים › "נטרול אזעקה בתזמונים" בהקלדת "אפשר נטרול"; כל שינוי של ההגדרה נרשם ביומן. נטרול שדורש קוד לעולם אינו ניתן לתזמון. תזמון נטרול קיים נשמר כפי שהוא (עם אזהרה); העתקה שלו היא נטרול חדש.
- **בדיקה: "אשר כתקין".** ברשימת התזמונים לבדיקה מנהל מערכת יכול לסמן "תזמון רגיש שנוצר מחוץ למערכת" ו"תוכן שהמערכת אינה מציגה במלואו" כתקינים: השבב הופך ל"אושר" שקט (עם "בטל אישור"), מונה "דורשים בדיקה" יורד, והאזהרה חוזרת מעצמה כשתוכן התזמון משתנה. האישור אינו משנה את התזמון; שני הכיוונים נרשמים ביומן.
### שינוי קידוד לכמה מצלמות בבת אחת - מערכת › אבטחה › מצלמות › "שינוי קידוד לכמה מצלמות"
- מחזיק `nvr.configure` בוחר זרמים (ראשי, משני או שניהם; סינון לפי קידוד, SVC ו-WebRTC; "בחר הכל"), קובע את הערכים החדשים - קידוד (H.264 / H.265), רזולוציה, קצב פריימים, סוג קצב, קצב סיביות, איכות, GOP, SVC ו-Smart codec, כל שדה "ללא שינוי" כברירת מחדל - ורואה **תצוגה מקדימה** לפני כל כתיבה: לכל זרם לפני ← אחרי, ערכים שהותאמו למה שהמצלמה מאפשרת, וזרמים שאי אפשר לשנות עם הסיבה. **אישור אחד**, ואז השינוי רץ בשרת מצלמה אחר מצלמה, עם התקדמות חיה, "עצור", רשימת תוצאות וביטול הכול.
- בטיחות: ברגע האישור השרת מתכנן מחדש מקריאה עדכנית ונעצר אם מצלמה השתנתה מאז התצוגה המקדימה; כל ערך עובר את הבדיקה של שינוי בודד; כל ההגנות של השינוי המרובה נשארות (עצירה בשגיאה הראשונה, בדיקת תוצאה לא ידועה אחרי 45 שניות, מגבלת זמן לכל מצלמה, שינויים בודדים נדחים בזמן הריצה, ההרשאה נבדקת לפני כל מצלמה, מצב הסבב לא נכנס לגיבוי). המסלולים החדשים והביטול שלהם חסומים בערוץ הגישה מרחוק.
### סגנון "קפסולה" לתפריט נפתח וחוגת גודל לכל תפריט נפתח - הגדרות › לשוניות
- **סגנון חדש, קפסולה, בבחירה בלבד:** סגור - קפסולה עם טבעת כחולה, מילוי רך, סמל בהתחלה, תווית בולטת וחץ קטן בצד הנגדי; פתוח - לוח צף, מעוגל ושקוף למחצה, השורה הנבחרת צבועה, סמל בתחילת כל שורה, **מספר** בצד השני וקו מפריד אחרי "הכל". בטלפון נפתח כגיליון תחתון (או כרשימה קטנה). עובד בארבעת המראות, בבהיר ובכהה, בעשר הפלטות ובחוגות; המקלדת וקוראי המסך ללא שינוי. כפתור האזורים במסכי ההתקנים וכפתורי החדרים במולטימדיה מספקים לו סמלים ומספרים.
- **גודל התפריט הנפתח: קטן / רגיל / גדול** לכל סגנון; "רגיל" הוא הגודל של היום. אזורי המגע נשארים 44 פיקסלים בטלפון ובחוגת 44.
- **עובי הטבעת** בקפסולה (1 / 1.5 / 2 / 3 פיקסלים, ברירת מחדל 2) ו**רוחב הלוח הפתוח** (ברוחב הכפתור / 240 / 300, ברירת מחדל 240). הסגנון הקיים **pill** נקרא עכשיו **"כדור מלא"** (רק התווית בעברית השתנתה).
- כל החוגות עובדות כמו הסגנון: לכל הקבוצות או לכל קבוצה, ברירת מחדל להתקנה (מנהל מערכת) ובחירה אישית ("ההעדפה שלי") עם כפתור איפוס, אימות בשרת ותצוגה מקדימה חיה. **שום דבר לא משתנה עד שבוחרים סגנון או גודל.**
### הגדרות › מולטימדיה: רשימות קומפקטיות עם סינון למסכים ולנגנים / רמקולים
- **שורות קומפקטיות:** כל מסך / רמקול / נגן הוא שורה אחת (שם, סוג, אינטגרציה, מזהה ישות ומזהה התקן עם כפתור העתקה, חדר, מצב, אישור, מספר חיבורים); הטופס המלא נפתח מתחת לשורה לפי דרישה. כל השדות, הפעולות וההרשאות ללא שינוי.
- **סינון, מיון וקיבוץ:** חיפוש חופשי (גם לפי מזהה ושם אינטגרציה), אינטגרציות (כמה יחד), חדר, סוג, אישור וזמינות, עם מונה ו"נקה סינון"; מיון לפי שם, סוג, אינטגרציה, חדר, מזהה או מצב; קיבוץ לפי אינטגרציה, חדר או סוג עם כותרות מתקפלות.
- **עמודות:** כפתור "עמודות" מציג או מסתיר כל עמודה. ברירת המחדל כמו היום, ולכן שום דבר לא משתנה עד שבוחרים; "ברירת מחדל" מחזיר; הבחירה נשמרת בדפדפן לכל משתמש ולכל רשימה; בטלפון (כרטיסים) הכפתור לא מוצג.
### מוני חשמל: שם ידידותי לכל מונה, בהוספה ובשינוי מאוחר
- בהוספת מונה מופיע שדה שם לכל חיישן שנבחר, ממולא מראש משם המכשיר (אחרת שם החיישן); חובה, בלי רווחים בקצוות, עד 120 תווים. בכרטיס המונה יש "שינוי שם" (רק עם `energy.manage`); התנגשות גרסה מוסברת בעברית. השינוי נרשם ביומן (שם ישן וחדש).
- **שמות כפולים נחסמים** ביצירה ובשינוי שם (בלי רווחים בקצוות, בלי הבחנה בין אותיות גדולות וקטנות, מונה מושהה נספר): "קיים כבר מונה בשם הזה, לא ניתן להקים שני מונים באותו שם". כפילויות שכבר קיימות בנתונים לא נפגעות ולא חוסמות עריכות אחרות.
- השם החדש מופיע בבוררים, ברשימות, באשף החשבון ובכל טיוטה או חיוב חדשים; **חיובים שכבר הונפקו שומרים את השם שבו נחתמו**.
### הקשחת החיבור לשרת המוזיקה
- **האסימון של שרת המוזיקה מוצפן בדיסק** (AES-256-GCM, אותו מפתח ואותו מנגנון של חיבור ה-NVR); לא מוחזר, לא נרשם ביומן ולא נכנס לגיבוי. בהפעלה הראשונה אחרי העדכון אסימון שנשמר בקובץ גלוי מוצפן, נבדק והקובץ הגלוי נמחק (אם המעבר נכשל הקובץ נשאר, החיבור ממשיך לעבוד והניסיון חוזר בהפעלה הבאה).
- **בדיקת כתובת השרת:** רק כתובת פרטית ברשת הביתית; כתובת של המערכת עצמה, האינטרנט, כתובות פנימיות או כתובת עם שם משתמש נדחות בהודעה ברורה; בלי מעקב אחרי הפניות.
- **מסך החיבור מקומי בלבד** (לא נגיש דרך הגישה מרחוק); בדיקת החיבור מוגבלת ל-5 בדקה למשתמש; תקרת זמן של 10 שניות לכל פנייה, עם הודעת סירוב ברורה בעברית לכל מצב.
- **שחזור וחזרה לגרסה קודמת:** אם מפתח ההצפנה אבד, החיבור מציג "אסימון לא קריא" ויש להזין את האסימון שוב (ההפעלה לא נכשלת). גרסה ישנה לא קוראת את האסימון המוצפן ותציג "לא הוגדר" עד להזנה מחדש.
- **איך מפעילים:** מתקינים את העדכון, **מפעילים מחדש את התשתית פעם אחת** (גשר 0.6.1) וטוענים מחדש את אפליקציית הרשת; אין מיגרציה. תזמונים: הגדרות › תזמונים › "סוגי התקנים מותרים בתזמון" (הסוגים החדשים פעילים; מכבים מה שלא רוצים), בעורך התזמון בוחרים פעולה ולסקריפט ממלאים "משתני הסקריפט"; "לבדיקה" ← "אשר כתקין". נטרול מתוזמן (רק אם רוצים; כבוי כברירת מחדל): הגדרות › תזמונים › "נטרול אזעקה בתזמונים" ← "אפשר נטרול" (מנהל מערכת). שינוי קידוד: מערכת › אבטחה › מצלמות ← "שינוי קידוד לכמה מצלמות" ← מסמנים זרמים ← "המשך" ← קובעים רק מה שמשתנה ← "תצוגה מקדימה" ← "החל על N זרמים" ← אישור אחד. קפסולה: הגדרות › לשוניות › "סגנון תפריט נפתח" ← **קפסולה** (הגודל, הטבעת והרוחב באותו כרטיס). רשימות המולטימדיה: הגדרות › מולטימדיה, אין מה להפעיל. שם מונה: תשתיות › מוני חשמל › מונים ← מונה ← "שינוי שם". חיבור המוזיקה: אין מה לעשות; אם הבדיקה הבאה דוחה את הכתובת, מזינים את כתובת ה-IP הביתית של השרת ופורט 8095.
- **מגבלות:** **שום דבר בשחרור הזה לא הורץ מול מערכת אמיתית:** התזמונים נבדקו מול רכיב תזמונים מדומה וגשר מדומה (לא מול התקנה או אזעקה אמיתיות); שינוי הקידוד המרובה נבדק מול מקליט מדומה בלבד - **לא נכתב שום שינוי למצלמה אמיתית, והשינוי המרובה האמיתי הראשון במקליט המעבדה ייעשה על ידי הבעלים**. משתני סקריפט מסוגים שהתזמונים אינם מייצגים אינם מוצעים; לא נוספו בכוונה צופרים, נגני מדיה, ישויות `number` / `select` והתראות. תפריטי "כל הקומות" בדפי המולטימדיה אינם משתנים לפי סגנון התפריט. אחרי חזרה לגרסה ישנה מ-0.1.162 צריך להזין שוב את אסימון המוזיקה.
