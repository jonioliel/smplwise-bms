# SmplWise Arx 2.0.3 - Release notes / הערות שחרור

Source of truth for the text below: smplwise_vms/CHANGELOG.md (section 2.0.3, bilingual per item).

## 2.0.3 (pilot) — Investigation on the map and in the review list; electricity manual readings and calibration; the camera comparison pickers; phone dropdowns open as the small list; fixes

**After installing:** two database migrations run on start, `0058_energy_manual_readings` (manual meter readings, calibrations) and
`0059_event_window_groups` (manual review-window groups and their members); nothing existing is rewritten. The bridge integration stays
**0.6.2**; no platform restart. Reload the installed web app once. **One default changes:** on a phone a dropdown opens as the regular
small list under the field instead of the bottom sheet (saved choices are kept; the sheet stays selectable). Everything else is visible
at once without changing data, or waits for an explicit action. 572 API routes (564 + 8).

### Investigation: adjacent cameras, review spotlights, the route through stairs / elevators (M043 / M047 / M064) - חקירה

**What was added.** (1) **Map:** picking cameras on a floor suggests the cameras next to them (same room, a shared wall, then within a
fifth of the plan) as chips with their relation and "הוסף הכל" - topology only, never an automatic pick or tracking; the picks are kept
in the address and the view per floor, so the wall / synchronized playback opened from the selection offers "חזרה למפה" back to the same
floor, picks, mode and place. (2) **Review spotlights:** every review window is scored by named, explained rules over its raw events
(critical, smart detection, video integrity, door + activity, several cameras, a burst, a long window; lit at 2+; deterministic); a
"זרקור" column and a "זרקורים (n)" filter; the drawer opens on the summary and keeps the raw events behind "N אירועים מקוריים".
**Manual grouping** (split / join / dissolve) is stored beside the events, which are never changed. (3) **Route:** the suggested route
continues through the floor's published stairs / elevators to the cameras next to their twin on the other floor, ranked after the
floor's own cameras; "אשר מסלול לתיק (n)" puts the event and a clip per ticked camera into a new or open case in one click, every note
saying hypothesis, never identification. Migration `0059`.

**Bugs fixed.** None (new capability).

**How to enable.** Install (migration 0059 runs by itself). Map › pick cameras › "מוצע בסמוך". חקירה › אירועים › "זרקור" column /
"זרקורים" chip › open a window › "N אירועים מקוריים" › tick › split / join / dissolve (`events.ack`). An event's route card › tick
suggestions › choose a case › "אשר מסלול לתיק" (`cases.manage`). Cross-floor suggestions need the stairs / elevators drawn and
published on both floors.

### Electricity meters: manual readings and calibration (EL6) - מוני חשמל: קריאה ידנית וכיול

**What was added.** A manual reading of the physical meter (kWh / Wh / MWh, validated: not in the future, not before the meter,
monotonic per counter life, one per instant), always kept with the system's value and the deviation; it fills a reporting gap (open gap:
the bill can reach the period end; closed gap: re-split at the reading, total unchanged), otherwise it is kept for comparison.
Calibration `physical = factor x counter + offset` from local midnight of a date, applied in one place so consumption, time-of-use,
history, the meters screen, billing and the bill PDF agree; the stored series is never rewritten; "by a manual reading" by default
with a suggested factor. Live dry-run previews, undo within 24 hours while no issued bill depends on the item, no calibration before
the last issued bill of the meter, a replacement ends the calibration; bill notes "meter calibrated" / "manual reading". No new
permission (`energy.view` reads, `energy.manage` writes). Migration `0058`; both tables in the backup.

**Bugs fixed.** None (new capability).

**How to enable.** Install (**migration 0058**). תשתיות › מוני חשמל › a meter › "קריאות ידניות וכיול" › "קריאה ידנית" / "כיול".

### Camera comparison pickers: search from 4, dropdown or buttons (CMP2) - בוררי השוואת המצלמות

**What was added.** Synchronized playback's "מצלמות להשוואה" is the same multi-select dropdown as the recordings comparison (up to 4,
the first pick leads, other-recorder cameras disabled unless the experimental setting allows them, offline cameras marked), and its card
shows the four places of a set with snapshots. New dials (installation + personal): the multi-select search from **4** cameras by default
(always / 4 / 8 / never) and the picker as a **dropdown** (default) or **buttons**.

**Bugs fixed.** The 5th pick was silently ignored by the old synchronized-playback chips; one false layout-guard finding.

**How to enable.** Nothing (dropdown, search from 4). To change: הגדרות › לשוניות › "בחירת מצלמות להשוואה" › "תצוגה" / "חיפוש ברשימה".

### Phone dropdowns open as the small list (default change) - תפריט נפתח בטלפון

**What changed.** `ui.dd_phone` defaults to `list` (was `sheet`). Saved installation / personal values are kept; desktop and tablet
unaffected. **How to get the sheet back:** הגדרות › לשוניות › "תפריט נפתח בטלפון" › "גיליון שעולה מלמטה".

### Fixes

- **Shared spaces (SS1):** candidates no longer offer a room already in a share (the plan conversion could adopt a taken room silently);
  un-sharing one of several floors ends the members left on no remaining floor; an outline without corners no longer divides by zero.
- **Integration names (MS3):** the multimedia remote editor's "חיבורים" rows show the friendly integration name (e.g. "Google Cast"),
  the raw id as the tooltip.
- **Provision-ISR alarm-server write (NN2A):** support is read first (`GetSupportedAPIs`; IP cameras yes, NVRs only with the v2 form);
  on a recorder without it (the owner's NVR, firmware 1.4.7, API v1) the write is **refused before anything is sent** (`nvr_not_supported`;
  `scripts/provision_nvr_write.py` exits 2, also in `--dry-run`); the v2 form sends `<switch>true</switch>`; a failed write journals the
  device's status / code / reason. Push stays off by default; no device write was made.

**How to enable.** Nothing.

### Documents (no product change)
CR-029 (Plan Studio 6, realistic 3D: plan and prototype findings) and CR-030 (the wall display for fixed tablets) with the screen
catalogue rows SC31 / SC38. Their mockups and screenshot sets stay on the design branches (`pilot/studio6-plan`,
`pilot/studio6-prototype`, `pilot/wall-display-design`, `pilot/cast-ux-mockups`).

### Known limits
- **Spotlights / route / adjacent cameras:** tested on a throwaway backend with demo floors and events (backend tests + an evidence
  spec at three widths); not yet tried on the owner's plans; cross-floor suggestions depend on published stairs / elevators.
- **Manual readings / calibration:** backend tests (validation, gap fill and exact undo bucket by bucket, billing with calibration, TOU
  additivity) and mocked screens; not tried on the owner's meters.
- **Provision-ISR push:** still off; whether the owner's NVR can take an alarm server needs a v2 firmware (CR-025 6.6.1).
- **Comparison pickers:** mocked screens and specs at three widths and four skins.

### How to turn it on and use it (English)
1. Install the update; migrations 0058 and 0059 run on start; reload the web app once.
2. Phone dropdowns: nothing (the list is the default); sheet: הגדרות › לשוניות › "תפריט נפתח בטלפון".
3. Comparison pickers: nothing; dials in הגדרות › לשוניות › "בחירת מצלמות להשוואה".
4. Manual reading / calibration: תשתיות › מוני חשמל › a meter › "קריאות ידניות וכיול".
5. Adjacent cameras: the floor map › pick cameras › "מוצע בסמוך"; "חזרה למפה" from the wall / playback.
6. Spotlights and grouping: חקירה › אירועים › "זרקורים"; the window drawer › "N אירועים מקוריים".
7. Route into a case: an event's route card › tick › case › "אשר מסלול לתיק".

## עברית — 2.0.3: חקירה במפה וברשימת הסקירה; קריאה ידנית וכיול של מוני חשמל; בוררי השוואת המצלמות; תפריט נפתח בטלפון כרשימה קטנה; תיקונים

**אחרי ההתקנה:** שתי מיגרציות רצות בהפעלה - `0058_energy_manual_readings` (קריאות ידניות של מונים, כיולים) ו־`0059_event_window_groups`
(קיבוצים ידניים של חלונות סקירה); שום דבר קיים לא נכתב מחדש. רכיב החיבור נשאר **0.6.2**; אין צורך להפעיל מחדש את התשתית. טוענים
מחדש את אפליקציית הרשת פעם אחת. **ברירת מחדל אחת משתנה:** בטלפון תפריט נפתח נפתח כרשימה קטנה מתחת לשדה במקום גיליון שעולה מלמטה
(בחירות שמורות נשמרות; הגיליון נשאר זמין לבחירה). כל השאר מוצג מיד בלי לשנות נתונים, או ממתין לפעולה מפורשת.

### חקירה: מצלמות סמוכות, זרקורים בסקירה, מסלול דרך מדרגות / מעליות
**מה נוסף.** (1) **מפה:** בחירת מצלמות בקומה מציעה את המצלמות הסמוכות (אותו חדר, קיר משותף, ואז בטווח חמישית מהתוכנית) כצ'יפים עם
הקשר ו"הוסף הכל" - טופולוגיה בלבד, לעולם לא בחירה אוטומטית או מעקב; הבחירות נשמרות בכתובת והתצוגה לכל קומה, כך שמהקיר / הניגון
המסונכרן "חזרה למפה" מחזירה לאותה קומה, בחירות, מצב ומקום. (2) **זרקורים:** כל חלון סקירה מקבל ניקוד לפי כללים בעלי שם והסבר
(קריטי, זיהוי חכם, תקינות וידאו, דלת + פעילות, כמה מצלמות, פרץ, חלון ארוך; מואר מ־2; דטרמיניסטי); עמודת "זרקור" וסינון "זרקורים (n)";
המגירה נפתחת על הסיכום והאירועים הגולמיים מאחורי "N אירועים מקוריים". **קיבוץ ידני** (פיצול / איחוד / פירוק) נשמר לצד האירועים, שלא
משתנים לעולם. (3) **מסלול:** המסלול המוצע ממשיך דרך המדרגות / המעליות שפורסמו בקומה אל המצלמות שליד התאום בקומה האחרת, אחרי מצלמות
הקומה עצמה; "אשר מסלול לתיק (n)" מכניס את האירוע וקטע לכל מצלמה מסומנת לתיק חדש או פתוח בלחיצה אחת, וכל הערה אומרת השערה, לעולם
לא זיהוי. מיגרציה `0059`.
**באגים שתוקנו.** אין (יכולת חדשה).
**איך מפעילים.** מתקינים (מיגרציה 0059 רצה מעצמה). מפה › בוחרים מצלמות › "מוצע בסמוך". חקירה › אירועים › עמודת "זרקור" / צ'יפ
"זרקורים" › פותחים חלון › "N אירועים מקוריים" › מסמנים › פיצול / איחוד / פירוק (`events.ack`). כרטיס המסלול של אירוע › מסמנים הצעות
› בוחרים תיק › "אשר מסלול לתיק" (`cases.manage`). הצעות בין קומות דורשות מדרגות / מעליות מצוירות ומפורסמות בשתי הקומות.

### מוני חשמל: קריאה ידנית וכיול
**מה נוסף.** קריאה ידנית של המונה הפיזי (קוט"ש / וט"ש / מגה-וט"ש, עם בדיקות: לא בעתיד, לא לפני המונה, עולה בלבד, אחת לכל רגע), נשמרת
תמיד עם ערך המערכת והסטייה; ממלאת פער דיווח (פער פתוח: החיוב מגיע עד סוף התקופה; פער סגור: חלוקה מחדש לפי הקריאה, הסך לא משתנה),
ואחרת נשמרת להשוואה. כיול `פיזי = מקדם x מונה + היסט` מחצות מקומית של תאריך, מוחל במקום אחד כך שהצריכה, התעו"ז, ההיסטוריה, מסך
המונים, החיוב וה־PDF מסכימים; הסדרה השמורה לא נכתבת מחדש; "לפי קריאה ידנית" כברירת מחדל עם מקדם מוצע. תצוגה מקדימה חיה, ביטול תוך
24 שעות כל עוד שום חשבון שהונפק לא תלוי בפריט, אין כיול לפני החשבון האחרון שהונפק, החלפת מונה מסיימת את הכיול; הערות בחשבון "מונה
מכויל" / "קריאה ידנית". אין הרשאה חדשה. מיגרציה `0058`; שתי הטבלאות בגיבוי.
**באגים שתוקנו.** אין (יכולת חדשה).
**איך מפעילים.** מתקינים (**מיגרציה 0058**). תשתיות › מוני חשמל › מונה › "קריאות ידניות וכיול" › "קריאה ידנית" / "כיול".

### בוררי השוואת המצלמות: חיפוש מ־4, תפריט או כפתורים
**מה נוסף.** "מצלמות להשוואה" בניגון המסונכרן הוא אותו תפריט בחירה מרובה כמו ההשוואה בהקלטות (עד 4, הראשונה מובילה, מצלמות של מקליט
אחר מושבתות אלא אם ההגדרה הניסיונית מתירה, מצלמות מנותקות מסומנות), והכרטיס מציג את ארבעת המקומות של הסט עם תמונות. חוגות חדשות
(התקנה + אישי): חיפוש ברשימת בחירה מרובה **מ־4** מצלמות כברירת מחדל (תמיד / 4 / 8 / אף פעם) והבורר כ**תפריט נפתח** (ברירת מחדל) או
**כפתורים**.
**באגים שתוקנו.** בחירה חמישית התעלמה בשקט בצ'יפים הישנים של הניגון המסונכרן; ממצא שווא אחד של בודק הפריסה.
**איך מפעילים.** אין מה להפעיל. לשינוי: הגדרות › לשוניות › "בחירת מצלמות להשוואה" › "תצוגה" / "חיפוש ברשימה".

### תפריט נפתח בטלפון כרשימה קטנה (שינוי ברירת מחדל)
