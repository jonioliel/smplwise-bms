## The owner rename (2026-10-14)
- `naming.DEFAULTS` / `DEFAULT_TICKET_NAMES`: he `{one: "בקשת שירות", many: "בקשות שירות", gender: f, module: "ניהול השירות"}`;
  en / ar / ru keep their item names, `module` = their plural. `module` is optional in the stored document (absent: the default
  module name while the item names are the defaults, else the plural) and editable in Settings › the module › general.
- New tokens `{module}`, `{the_ticket}`, `{the_tickets}`. A Hebrew construct cannot take "ה" in front ("הבקשת שירות"), so the
  article tokens put "ה" before the last word ("בקשת השירות"), or before a single word; every "ה{ticket(s)}" became the token.
  Heuristic limit: a noun + adjective name ("תקלה דחופה") gets the article on the adjective only - recorded in the guide.
- `{module}`: the area, page titles, settings tab / card, the `tickets.*` permission labels and the messaging screen's module heading.
- Lints: backend `tests/test_tickets_naming.py` (the retired words in no module source - comments included -, label, role name,
  default or guide chapter 46; the new defaults never hard-coded) and frontend `tests/unit-tickets-naming.spec.ts` (the same over
  `src/tickets`, the screens, `api/tickets*`, the vendor page and `naming.ts`), each with planted-line checks. Code identifiers, routes
  and permission ids are unchanged. Planning documents (`docs/changes/CR-038-*`) keep their wording (not user-visible).
- The vendor page's "code sent" line now uses the server's `expires_in_s` (code lifetime is a setting since slice 7).
