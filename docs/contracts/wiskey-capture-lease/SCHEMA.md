# wiskey-capture-lease-v1 - the capture lease and its revocation stream (DRAFT)

Status: DRAFT, Arx LEASE-BUILD 2026-10-16 (CR-WISKEY-LEASE-REVOCATION-EVENT slice L0). Design source:
`docs/changes/CR-WISKEY-LEASE-REVOCATION-EVENT.md` (on `origin/pilot/CR-LEASE-REVOKE`). Nothing here is switched on: the Arx route
is behind `access.capture_lease` (default `off`) and cannot be switched on while no bridge offers `smplwise_bridge.lease_event`
(slice L4, pending WisKey's consumer). Owner decisions encoded (2026-10-16): lease 120 s default and cap; any `permission_revision`
bump revokes every live lease without a re-check; heartbeat every 5 s while a lease is live, WisKey destroys after 15 s of
silence; no extra second-factor code at capture start; C03 lookup scope `holder` | `holder_or_audit_readers`.

Files: `lease.schema.json` (closed JSON Schema), `GOLDEN_VECTORS.json` (8 accept + 14 one-defect reject vectors, generated by
`smplwise_vms/backend/tests/lease_contract.py --write`, the reference validator), `NOTE_FOR_WISKEY.md`.

## 1. Transport

The DTO v3 trusted-caller transport, unchanged: the bridge service's data is exactly `{signed_message_json}`; the bridge
verifies stages 1-7 (transport, encoding, parse, schema, binding, signature, time, state/replay) and hands the immutable DTO to
WisKey (stage 8). Signing exactly as `wiskey-trusted-door-v1`: canonical JSON (sort_keys, compact, UTF-8) of the body without
`ts`/`nonce`/`sig`, HMAC-SHA256 with the pairing secret over `"<ts>.<nonce>.<sha256(canonical)>"`, `ts == epoch(issued_at)`,
explicit 32-hex `nonce` (fresh per send), `MAX_MESSAGE_BYTES` 8192.

| Service | Actions | Status |
|---|---|---|
| `smplwise_bridge.lease_event` | `lease_revoke`, `lease_heartbeat`, `lease_stream_reset` | the CR's service name; bridge 0.9.x line, not built (L4) |
| `smplwise_bridge.lease_request` (**PROVISIONAL name**) | `capture_start`, `capture_status`, `capture_confirm`, `capture_cancel` | WisKey's generalized W1 envelope; the service name is WisKey's revised C04 to fix (W?) |

## 2. Envelope and cross-field rules

Wire keys (closed): `protocol` (`wiskey-capture-lease-v1`), `actor {id, display_name}`, `action`, `station`, `params`,
`request_id` (UUIDv4, never reused), `issued_at`, `expires_at`, `ts`, `nonce`, `sig`. Text fields: 1..128 characters, no C0/C1
control (Arx also refuses Unicode format characters before signing).

Rules a JSON Schema cannot state (the reference validator enforces them):
- `ts == epoch(issued_at)`; `0 < expires_at - issued_at <= 15` (`time/lifetime_invalid`).
- `station == "*"` exactly for `lease_heartbeat`, `lease_stream_reset` and `lease_revoke` with `scope: all` (`binding/station_scope_mismatch`).
- `lease_revoke.lease_ref` is a UUID exactly when `scope == "lease"`, else `"*"`.
- `capture_start`: `0 < lease_expires_at - lease_issued_at <= 120` (schema/bad_value) and `lease_issued_at <= issued_at < lease_expires_at` (`binding/lease_window`).
- the action names its service (`binding/action_service_mismatch`).

Actor: the Arx principal for `capture_*` and for `lease_revoke` with scope `lease` / `actor` (`display_name` = the id: no person
name on the revocation wire); the installation id for scope `station` / `all`, the heartbeat and the stream reset.

## 3. Messages

| `action` | `params` (all required, closed) | Meaning |
|---|---|---|
| `lease_revoke` | `stream_id` (32 hex), `sequence` (>= 1), `scope` (lease \| actor \| station \| all), `lease_ref`, `permission_revision`, `reason` (closed enum, schema), `revoked_at` | the named lease(s) lost their authority: destroy the session and the collected card, no confirm |
| `lease_heartbeat` | `stream_id`, `sequence` (the LAST sequence sent, never a new one), `live_leases` (<= 8 UUIDs), `permission_revision` | liveness while >= 1 lease is live; grants nothing, never extends a lease |
| `lease_stream_reset` | `stream_id` (the new one), `previous_stream_id` (32 hex or `*`), `sequence` = 1, `reason` (startup \| repair \| restore \| key_rotation) | destroy every lease of any earlier stream; the new stream starts at 1 |
| `capture_start` | `lease` = {`lease_ref`, `lease_issued_at`, `lease_expires_at`, `binding_revision` (text or null - WisKey's, W?), `person_ref`, `person_revision`, `permission_revision`, `receiver {reader_id 0..8}`, `stream_id`, `sequence_at_issue`, `lease_actions` (exactly the four)} | start one collection under this lease. Never an address, serial, MAC, card value, hash or length |
| `capture_status` / `capture_cancel` | `lease_ref`, `session_id` (`*` when the start's outcome was unknown) | read / end the session |
| `capture_confirm` | `lease_ref`, `session_id`, `label` (0..64) | add the collected card; decided at the host's confirm barrier |

Ordering (CR 1.3): one stream per installation, sequence monotonic, persisted by Arx, incremented in the same transaction that
marks the ledger rows revoked. Host keeps `(stream_id, last_sequence, last_params_sha256)`:
`sequence == last + 1` -> apply; `== last`, same params -> `duplicate`; `== last`, different params -> `conflict` (destroy all);
`< last` -> `stale` (the named lease destroyed anyway); `> last + 1` -> `gap` (destroy all); unknown stream -> `unknown_stream`.
Arx retries a revoke every 2 s with a NEW envelope and the SAME sequence and params until a closed answer or
`lease_expires_at + 15 s`; after 5 s without one it also sends the lease's own `capture_cancel` once. While no lease is live
nothing is sent. The host destroys every live lease after 15 s without a revoke or a heartbeat (W?).

## 4. Answers

`lease_event` (closed): `{result: acknowledged, request_id, sequence, destroyed[, live_leases on a heartbeat]}` ·
`{result: duplicate, request_id, sequence}` · `{result: stale, request_id, sequence, last_sequence}` ·
`{result: gap, request_id, sequence, last_sequence, destroyed}` · `{result: conflict, request_id, sequence, destroyed}` ·
`{result: unknown_stream, request_id}` · `{result: rejected, stage, code[, request_id]}` (request_id iff the schema stage passed).
Any other shape, another `request_id` or another `sequence` is NOT an acknowledgement (Arx retries).

`lease_request` (PROVISIONAL, for alignment with WisKey's revised C04): `{result: acknowledged, request_id, session: {session_id,
state}}` (start) · `{..., capture: {state, error, card: {masked_number, technology, reader_id}}}` (status) · `{..., person: {...}}`
(confirm) · `{..., cancelled: true}` (cancel) · `{result: refused, request_id, code}` (WisKey refused before acting; codes such as
`capture_not_found`, `lease_gone`, `capture_station_busy`, `revision_conflict`) · `{result: sent_unknown, request_id}` (confirm
passed the barrier, outcome unknown) · `{result: rejected, stage, code}`. No answer carries a card value beyond the masked form
in a status, a person name in an event answer, or a station address.
