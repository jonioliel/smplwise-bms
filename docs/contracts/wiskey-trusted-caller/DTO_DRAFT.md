# WisKey trusted caller: shared DTO draft (`wiskey-trusted-door-v1`)

Status: DRAFT, 2026-10-04. This is Arx's position after WisKey's eight answers of 2026-10-03/04 (the "open items in
NOTE and README" section of WisKey's reply). It becomes the contract when WisKey agrees in writing. Documents and
synthetic vectors only: there is no `door_open` or `door_open_status` service in Arx or in the bridge yet, and this
file does not authorize building one.

Precedence: an approved change request, `MASTER_SPEC_HE.md` and `docs/security/` override this file. Arx RBAC is the
only authority for who may open which door. WisKey adds no policy, reauth, MFA or second approval on this path.

Files next to this one:

- `GOLDEN_VECTORS.json`, `vectors_version: 2`. The v1 `vectors` array is unchanged (29 vectors, file SHA-256
  `fd39b7ec...` as verified by WisKey). The v2 cases are in `contract_vectors` (68 cases), with the rules in `contract`.
- `smplwise_vms/backend/tests/test_wiskey_golden_vectors.py`: generator, drift test, and a strict reference
  validator in TEST code only.

## 1. Transport

```
POST /api/services/smplwise_bridge/door_open?return_response          (or .../door_open_status?return_response)
service_data = {"signed_message_json": "<the wire message JSON, as ONE string>"}
```

- `service_data` has exactly one key, `signed_message_json`, and its value is a string. Anything else (the wire
  message as an object, an object in the string's place, a second key, no key) is `transport/transport_shape`.
- The bridge parses the string itself, with an `object_pairs_hook` that refuses duplicate keys at every depth. There
  is no fallback to an already-parsed dict: a dict has already lost its duplicates.
- Why a string: HA parses the REST body before the service handler runs, and stdlib JSON keeps the last of two
  equal keys. A duplicate `station` would collapse and its HMAC would verify (v1 vector
  `reject_envelope_duplicate_station`). Inside a string, the bridge sees the raw text.
- The outer `service_data` is still parsed by HA. A duplicate OUTER key collapses before the bridge and cannot be
  detected there (`transport_outer_duplicate_collapsed_by_ha`). That is harmless because all meaning is inside the
  signed string. Arx must emit exactly one key.
- The signing recipe does not change. `return_response` is required; Arx reads `service_response`. A timeout is
  `unknown`; Arx then asks with `door_open_status` and never re-sends the open.

## 2. Wire message (inside the string)

Closed schema at three levels: wire, `actor`, `params`. Unknown fields are refused at every level, including
`capability`, `role` and `duration_s`.

| Field | Type | Constraint | Example |
|---|---|---|---|
| `protocol` | string | exactly `wiskey-trusted-door-v1` | `"wiskey-trusted-door-v1"` |
| `actor` | object | exactly `{id, display_name}` | |
| `actor.id` | string | 1-128 code points, no C0/C1/DEL controls; Arx user id | `"test-user-0001"` |
| `actor.display_name` | string | 1-128 code points, no controls; raw UTF-8, no normalization | `"משתמש בדיקה \"ראשי\""` |
| `action` | string | exactly `door_open` or `door_open_status`, and equal to the service called | `"door_open"` |
| `station` | string | 1-128 code points, no controls (exact WisKey format: open item W3) | `"test_station_entrance"` |
| `params` | object | `door_open`: exactly `{relay}`; `door_open_status`: exactly `{target_request_id}` | `{"relay": 1}` |
| `params.relay` | integer | a real JSON integer, not bool, not string, not float; `>= 1`; per-station range is WisKey's (W1) | `1` |
| `params.target_request_id` | string | lower-case hyphenated UUID of the `door_open` being asked about; not equal to `request_id` | `"3f2b8c1e-9a4d-4e6f-8b7a-1c2d3e4f5a6b"` |
| `request_id` | string | lower-case hyphenated UUID (8-4-4-4-12, `[0-9a-f]`), generated by the Arx server, never reused | `"3f2b8c1e-9a4d-4e6f-8b7a-1c2d3e4f5a6b"` |
| `issued_at` | string | `YYYY-MM-DDTHH:MM:SSZ`, UTC, upper-case `Z`, whole seconds, a real calendar date | `"2026-10-03T12:00:00Z"` |
| `expires_at` | string | same format; `0 < expires_at - issued_at <= 30` s | `"2026-10-03T12:00:30Z"` |
| `ts` | integer | a real JSON integer equal to the epoch seconds of `issued_at`; no coercion | `1791028800` |
| `nonce` | string | exactly 32 lower-case hex characters | `"a1b2c3d4e5f60718293a4b5c6d7e8f90"` |
| `sig` | string | exactly 64 lower-case hex characters | |

Numbers: floats (any number with a fraction or exponent, including `1.0`), `NaN`, `Infinity` and integers outside
+/-(2^53-1) are refused while parsing, wherever they appear.

Unicode: invalid UTF-8 and lone surrogates (in a key or a value, raw or as a `\uD8xx` escape) are refused before any
action. No Unicode normalization (NFC and NFD stay different). Logs never contain the body or the offending text.

The canonical format is the one in `README.md` and the vectors. It is verified, but NOT declared as JCS. Any
serialization change needs a new `protocol` value.

## 3. Signing and digests

```
signed_body   = wire message minus ts, nonce, sig
canonical     = json.dumps(signed_body, sort_keys=True, separators=(",", ":"), ensure_ascii=False) -> UTF-8
body_sha256   = sha256(canonical).hexdigest()
hmac_input    = f"{ts}.{nonce}.{body_sha256}"
sig           = HMAC-SHA256(pairing secret, UTF-8(hmac_input)).hexdigest()
authenticated_message_sha256 = sha256(UTF-8(hmac_input)).hexdigest()
```

- `nonce` is not in the canonical body. It is authenticated through `hmac_input` (`ts.nonce.body_sha256`).
  `authenticated_message_sha256` changes when the nonce changes; `body_sha256` does not (tested).
- Arx must pass an explicit 32-hex nonce (`secrets.token_hex(16)`). The existing signers default to
  `secrets.token_hex(8)`, 16 characters, which v1 refuses (`types_nonce_16_hex`; tested against both signers).

## 4. Immutable internal DTO (bridge -> WisKey trusted Python API)

| Field | Type | Source |
|---|---|---|
| `protocol` | str | wire |
| `actor` | `{id, display_name}` (immutable) | wire |
| `action` | str | wire |
| `station` | str | wire |
| `params` | immutable mapping | wire |
| `request_id` | str | wire |
| `nonce` | str | wire |
| `issued_at` | str | wire |
| `expires_at` | str | wire |
| `body_sha256` | str (64 hex) | computed by the bridge |
| `authenticated_message_sha256` | str (64 hex) | computed by the bridge |

Never in the DTO: the pairing secret, `sig`. `ts` is not carried (it equals `issued_at`). The capability that proves
the call came from the approved bridge/config entry is passed separately and internally; it never reaches Arx,
HTTP, WebSocket or a service. A digest alone is not proof of HMAC verification: the proof is the verifying bridge plus
the approved capability. Every `accept` vector has its `expected_dto`.

## 5. Validation order (before any pending record or dispatch)

Each stage runs only if every earlier stage passed. A refusal returns the code only, never input text.

| # | Stage | Checks | Codes |
|---|---|---|---|
| 1 | `transport` | `service_data` is exactly `{"signed_message_json": <string>}` | `transport_shape` |
| 2 | `encoding` | the string is valid Unicode (no lone surrogate); bytes, where an implementation sees bytes, decode as strict UTF-8 | `invalid_utf8`, `lone_surrogate` |
| 3 | `parse` | strict JSON: duplicate keys at any depth, NaN/Infinity, floats, integers outside +/-(2^53-1), escaped lone surrogates, top level not an object | `invalid_json`, `duplicate_key`, `non_json_constant`, `non_integer_number`, `integer_out_of_range`, `lone_surrogate`, `not_an_object` |
| 4 | `schema` | closed schema (wire, actor, params), exact types (`type(x) is int`, so no bool), formats, constant values | `unknown_field`, `missing_field`, `wrong_type`, `bad_format`, `bad_value` |
| 5 | `binding` | `ts == epoch(issued_at)`; `action` equals the service called; status target is not its own request_id | `ts_mismatch`, `action_service_mismatch`, `target_is_self` |
| 6 | `signature` | HMAC over `hmac_input`, constant-time compare | `bad_signature` |
| 7 | `time` | valid clock (not missing, not before 2026-01-01T00:00:00Z); `0 < expires-issued <= 30`; `issued_at <= now`; `now < expires_at` | `clock_invalid`, `lifetime_invalid`, `not_yet_valid`, `expired` |
| 8 | `state` (WisKey store) | capability valid; nonce not used by another request; request_id not seen with another meaning; status station equals the open record's station; relay allowed at the station | `replay`, `request_id_conflict`, `station_mismatch`, `relay_not_allowed` (+ WisKey's capability codes, W5) |
| 9 | pending | durable pending record (WisKey SQLite, `synchronous=FULL`) for `door_open` only | |
| 10 | dispatch | relay command (`door_open`) or a read of the stored outcome (`door_open_status`) | |

Within the schema stage the reference checks wire keys, then wire scalar types and formats, then `actor`, then
`params`. Every reject vector carries exactly one defect, so a conforming implementation matches both
`reject_stage` and `reject_code` regardless of its internal order.

`door_open_status` never opens a door, never creates a pending record and never changes an open's outcome. A
target the store does not know (never seen, or purged after 7 days) is not a refusal: the answer is
`unknown` / `not_found_or_expired`. An identical completed `door_open` returns the stored result and is not executed
again; a pending one is not executed again either.

## 6. Examples

Accepted (`transport_envelope_door_open`, now = 2026-10-03T12:00:00Z):

```json
{"signed_message_json":"{\"protocol\":\"wiskey-trusted-door-v1\",\"actor\":{\"id\":\"test-user-0001\",\"display_name\":\"משתמש בדיקה \\\"ראשי\\\"\"},\"action\":\"door_open\",\"station\":\"test_station_entrance\",\"params\":{\"relay\":1},\"request_id\":\"3f2b8c1e-9a4d-4e6f-8b7a-1c2d3e4f5a6b\",\"issued_at\":\"2026-10-03T12:00:00Z\",\"expires_at\":\"2026-10-03T12:00:30Z\",\"ts\":1791028800,\"nonce\":\"a1b2c3d4e5f60718293a4b5c6d7e8f90\",\"sig\":\"15d7d47bddfdd07f6f5855c1ef01d9fc27652e91d685cee3eb2eecc30fa862af\"}"}
```

Accepted status (`status_with_target`): `action: door_open_status`, `params: {"target_request_id": "3f2b8c1e-..."}`,
its own `request_id` `5b0c7d1a-...` and nonce, same station.

Refused (one line each; the vectors carry the exact strings):

| Case | Stage / code |
|---|---|
| `{"station": ...}` twice inside the string | `parse/duplicate_key` |
| `ts` as `"1791028800"` / `1791028800.0` / `true` | `schema/wrong_type` / `parse/non_integer_number` / `schema/wrong_type` |
| nonce of 16 hex | `schema/bad_format` |
| `relay: true`, `relay: "1"` / `relay: 0`, `relay: -1` | `schema/wrong_type` / `schema/bad_value` |
| `action: "open_door"` | `schema/bad_value` |
| `capability` at the top, `role` in actor, `duration_s` in params | `schema/unknown_field` |
| lifetime 31 s, 0 s, negative | `time/lifetime_invalid` |
| now = expires_at | `time/expired` |
| issued_at `+00:00`, `.000Z`, lower-case `z` | `schema/bad_format` |
| status with empty params | `schema/missing_field` |
| status carrying `relay` | `schema/unknown_field` |
| the wire message sent as an object instead of a string | `transport/transport_shape` |

## 7. Error codes and the response

The service response for a refusal carries `{"result": "rejected", "stage": "<stage>", "code": "<code>"}` and the
`request_id` only when the schema stage passed. No input text, no body, no digest of a refused message. The
success and outcome shapes (`acknowledged`, `unknown`, stored result) are WisKey's to fix (W6); `acknowledged` means
the command was accepted, not that the door was seen to open.

## 8. Versioning

- `protocol` names the whole contract: wire fields, serialization, signing recipe, time rules and the DTO.
- Any change to the serialization, the recipe, the field set, a type or a constraint needs a new `protocol` value
  (`wiskey-trusted-door-v2`, ...). A v1 verifier refuses an unknown protocol (`types_protocol_unknown`).
- The vectors file has its own `vectors_version`. Adding vectors bumps it; existing vectors are never edited (the v1
  array is pinned by hash in the test). A vector that turns out wrong is superseded by a new id, with a note.
- WisKey-internal changes that keep this contract do not need Arx work.

## 9. Open items

For WisKey:

- W1. Allowed `relay` range per station (today the schema only says `>= 1`; the range check is stage `state`).
- W2. Tolerate up to 2 s of future skew on `issued_at` (now: none; `time_future_issued_at_1s` is refused)?
- W3. The exact `station` id format (Arx accepts 1-128 printable code points for now), and limits for `actor.id`
  and `actor.display_name` (Arx proposes 128 each).
- W4. Maximum length of `signed_message_json` (Arx proposes 8 KiB of UTF-8, not in the vectors yet).
- W5. Capability failure codes in stage `state`, and whether `station_mismatch` should instead answer
  `not_found_or_expired` so a status call cannot probe other stations.
- W6. The success / `unknown` / stored-result response shapes for both services.
- W7. Confirm the clock-validity rule (Arx's reference: missing, or before 2026-01-01T00:00:00Z) or give WisKey's.
- W8. Confirm the refusal response shape in section 7.

For Arx:

- A1. Signer side: build the wire message with an explicit 32-hex nonce, `ts = epoch(issued_at)`, lifetime <= 30 s,
  server-side UUIDs, and send it as `signed_message_json`. Not implemented.
- A2. Bridge side: the `door_open` / `door_open_status` services with this validation order, the strict parser, the
  DTO and the internal capability hand-off. Not implemented. Arx owns the bridge.
- A3. Never re-sign an open with fresh times; after `unknown`, only `door_open_status`.
- A4. Map `access.release` and the `lock.unlock` paths to `door_open` per the owner's release-gate decision.
- A5. Keep the 60 s window of the other bridge paths unchanged (no silent change).
