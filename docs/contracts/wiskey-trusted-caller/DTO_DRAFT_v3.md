# WisKey trusted caller: shared DTO draft v3 (`wiskey-trusted-door-v1`)

Status: DRAFT v3, 2026-10-04. Arx accepts all eight WisKey positions of `ARX_REPLY_TO_VECTORS_V2_2026-10-04` (W1-W8)
and writes them into the contract here. It becomes the contract when WisKey agrees in writing to this text and to
`GOLDEN_VECTORS_v3.json`. Documents and synthetic vectors only: there is no `door_open` or `door_open_status` service
in Arx or in the bridge, and this file does not authorize building one. Runtime work needs the owner's approval.

This file replaces `DTO_DRAFT.md` (v2) as the current draft. `DTO_DRAFT.md` stays in the repository unchanged as the
record of what WisKey verified.

## 1. Transport

```
POST /api/services/smplwise_bridge/door_open?return_response          (or .../door_open_status?return_response)
service_data = {"signed_message_json": "<the wire message JSON, as ONE string>"}
```

- `service_data` has exactly one key, `signed_message_json`, holding a string. Anything else is
  `transport/transport_shape`.
- **Size (W4):** `signed_message_json` is at most **8192 UTF-8 bytes, inclusive**. Bytes, not characters and not
  UTF-16 units. It is measured after the UTF-8 check and before parsing; a longer string is
  `encoding/message_too_large`. Only the inner string is measured, not the outer `service_data`. Insignificant JSON
  whitespace counts toward the size (it is legal JSON and is not part of the signed bytes).
- The bridge parses the string itself and refuses duplicate keys at every depth; there is no fallback to a parsed
  dict. A duplicate OUTER key collapses in HA before the bridge and is harmless (v2
  `transport_outer_duplicate_collapsed_by_ha`); Arx emits exactly one key.
- `return_response` is required. A timeout is `unknown`; Arx then asks with `door_open_status` and never re-sends the
  open.

## 2. Wire message (inside the string)

Closed schema at three levels (wire, `actor`, `params`). Unknown fields are refused at every level.

| Field | Type | Constraint | Example |
|---|---|---|---|
| `protocol` | string | exactly `wiskey-trusted-door-v1` | `"wiskey-trusted-door-v1"` |
| `actor` | object | exactly `{id, display_name}` | |
| `actor.id` | string | the Arx user id. 1-128 code points; no C0 (U+0000-U+001F), DEL (U+007F) or C1 (U+0080-U+009F); no trim, no normalization, no case change; no UUID requirement | `"test-user-0001"` |
| `actor.display_name` | string | 1-128 code points, same character rule; raw UTF-8 | `"משתמש בדיקה \"ראשי\""` |
| `action` | string | exactly `door_open` or `door_open_status`, equal to the service called | `"door_open"` |
| `station` | string | the opaque `ConfigEntry.entry_id` of the WisKey station, matched exactly against the registration; never a hardware id. 1-128 code points, same character rule, no trim, no case change, no UUID requirement | `"test_station_entrance"` |
| `params` | object | `door_open`: exactly `{relay}`; `door_open_status`: exactly `{target_request_id}` | `{"relay": 1}` |
| `params.relay` | integer | a real JSON integer (not bool, string or float), `>= 1`. Its meaning is the `physical_index` in WisKey's verified active mapping for the station; WisKey maps it to its api_id (W1) | `1` |
| `params.target_request_id` | string | lower-case hyphenated UUID of the `door_open` being asked about; not equal to `request_id` | `"3f2b8c1e-9a4d-4e6f-8b7a-1c2d3e4f5a6b"` |
| `request_id` | string | lower-case hyphenated UUID, generated by the Arx server, never reused | `"3f2b8c1e-9a4d-4e6f-8b7a-1c2d3e4f5a6b"` |
| `issued_at` | string | `YYYY-MM-DDTHH:MM:SSZ`, UTC, upper-case `Z`, whole seconds, a real date | `"2026-10-03T12:00:00Z"` |
| `expires_at` | string | same format; `0 < expires_at - issued_at <= 30` s | `"2026-10-03T12:00:30Z"` |
| `ts` | integer | equals the epoch seconds of `issued_at`; no coercion | `1791028800` |
| `nonce` | string | exactly 32 lower-case hex | `"a1b2c3d4e5f60718293a4b5c6d7e8f90"` |
| `sig` | string | exactly 64 lower-case hex | |

"Code points" means Unicode scalar values: U+1F6AA counts as 1 (it is 2 UTF-16 units and 4 bytes). U+00A0 and other
characters above U+009F are allowed. A single space is a valid `display_name`. Floats, `NaN`, `Infinity`, integers
outside +/-(2^53-1), lone surrogates and invalid UTF-8 are refused, as in v2. No Unicode normalization.

## 3. Signing and digests

Unchanged from v2 (`DTO_DRAFT.md` section 3, the README recipe and the v1 vectors):

```
signed_body   = wire message minus ts, nonce, sig
canonical     = json.dumps(signed_body, sort_keys=True, separators=(",", ":"), ensure_ascii=False) -> UTF-8
body_sha256   = sha256(canonical).hexdigest()
hmac_input    = f"{ts}.{nonce}.{body_sha256}"
sig           = HMAC-SHA256(pairing secret, UTF-8(hmac_input)).hexdigest()
authenticated_message_sha256 = sha256(UTF-8(hmac_input)).hexdigest()
```

## 4. Immutable internal DTO

Unchanged from v2: `protocol`, `actor {id, display_name}`, `action`, `station`, `params`, `request_id`, `nonce`,
`issued_at`, `expires_at`, `body_sha256`, `authenticated_message_sha256`. Never the secret or `sig`; `ts` is not
carried. Values are passed exactly as received (no trim, no case change). The capability is handed over separately
and internally and never reaches Arx, HTTP, WebSocket or a service.

## 5. Validation order (before any pending record or dispatch)

Each stage runs only if every earlier stage passed. A refusal returns the code only, never input text.

| # | Stage | Checks | Codes |
|---|---|---|---|
| 1 | `transport` | `service_data` is exactly `{"signed_message_json": <string>}` | `transport_shape` |
| 2 | `encoding` | valid Unicode / strict UTF-8 first, then the 8192-byte limit | `invalid_utf8`, `lone_surrogate`, `message_too_large` |
| 3 | `parse` | strict JSON (duplicates, NaN/Infinity, floats, unsafe integers, escaped lone surrogates, top level not an object) | `invalid_json`, `duplicate_key`, `non_json_constant`, `non_integer_number`, `integer_out_of_range`, `lone_surrogate`, `not_an_object` |
| 4 | `schema` | closed schema, exact types, formats, section 2 limits | `unknown_field`, `missing_field`, `wrong_type`, `bad_format`, `bad_value` |
| 5 | `binding` | `ts == epoch(issued_at)`; action equals the service; status target is not its own request_id | `ts_mismatch`, `action_service_mismatch`, `target_is_self` |
| 6 | `signature` | HMAC over `hmac_input`, constant-time compare | `bad_signature` |
| 7 | `time` | clock valid and healthy (section 8); `0 < expires - issued <= 30`; `issued_at <= now`; `now < expires_at` | `clock_invalid`, `lifetime_invalid`, `not_yet_valid`, `expired` |
| 8 | `state` (WisKey store) | see section 6 | `capability_missing`, `capability_invalid`, `capability_revoked`, `replay`, `request_id_conflict`, `relay_not_allowed`, `storage_unavailable` |
| 9 | pending | durable pending record (WisKey SQLite, `synchronous=FULL`), `door_open` only | |
| 10 | dispatch | relay command (`door_open`) or a read of the stored outcome (`door_open_status`) | |

**No forward skew (W2):** `issued_at <= now < expires_at`, lifetime at most 30 s, whole seconds. A message issued one
or two seconds in the future is `time/not_yet_valid`. The question of a 2-second tolerance is withdrawn. Arx keeps
its clock synchronized instead. The 60 s window of other bridge paths is not changed.

Every stateless reject vector carries exactly one defect, so `reject_stage` and `reject_code` are both binding.

## 6. Stage `state` and the status answer

Proposed order inside stage `state` (each stateful vector has one defect, so the order is not bound by the vectors;
open item W-c): capability, replay (nonce), request_id (duplicate or conflict), relay mapping (`door_open`), pending
record (`door_open`), dispatch or stored-outcome read.

- **Capability (W5):** missing = `state/capability_missing`; a capability of a different bridge/config entry =
  `state/capability_invalid`; revoked on unload/reload = `state/capability_revoked`. For both services. No pending
  record, no dispatch, no extra RBAC.
- **Replay:** a nonce already recorded for a different request_id = `state/replay`.
- **request_id:** a known request_id with a different meaning (actor, station, relay) = `state/request_id_conflict`.
  The identical `door_open` again is never executed again: pending -> `unknown/pending`; completed -> `stored_result`.
- **Relay (W1):** `params.relay` must be a `physical_index` of WisKey's verified active mapping for the station
  (rc.37: a subset of `{1, 2}`; later per vendor and explicit mapping). No contiguous range is assumed: with mapping
  `{2}`, relay 1 is refused. Violation = `state/relay_not_allowed`, before any pending record. This is a technical
  target check, not a policy.
- **Pending write:** if the pending record cannot be written, nothing is sent: `state/storage_unavailable`. That is not
  a success and not a re-open.
- **Status (W5):** a status query is answered from the store only. A target the store does not hold (never seen,
  purged after 7 days) **or whose open record has a different station** answers `unknown/not_found_or_expired`; the
  two cases are indistinguishable, so a status call cannot probe other stations. Station comparison is exact (no
  trim, no case folding). `station_mismatch` is no longer a code. The v2 case `status_station_mismatch_vs_open_record`
  is superseded by v3 `status_station_mismatch_answers_not_found`.
- `door_open_status` never opens, never creates a pending record and never changes an outcome.

## 7. Responses (W6, W8)

`request_id` always identifies the current call. `target_request_id` identifies the open. All ids are lower-case
UUIDs. The JSON schemas are in `GOLDEN_VECTORS_v3.json` (`response_schemas`).

| Situation | Response | Schema name |
|---|---|---|
| `door_open` stored and acknowledged | `{"result": "acknowledged", "request_id"}` (command acknowledgement only, not proof the door opened) | `door_open_acknowledged` |
| `door_open` sent, outcome uncertain | `{"result": "unknown", "request_id", "reason"}`, reason `unconfirmed`, `interrupted` or `outcome_persistence_failed` | `door_open_unknown` |
| identical `door_open` while pending | `{"result": "unknown", "request_id", "reason": "pending"}`; not executed again | `door_open_unknown` |
| identical `door_open` after completion | `{"result": "stored_result", "request_id", "target_request_id", "outcome"}` (both ids equal) | `stored_result` |
| status: target pending | `{"result": "unknown", "request_id", "target_request_id", "reason": "pending"}` | `status_unknown` |
| status: target missing, expired or another station | same with `reason: "not_found_or_expired"` | `status_unknown` |
| status: target completed | `{"result": "stored_result", "request_id", "target_request_id", "outcome"}` | `stored_result` |
| refusal before a full schema pass (stages 1-4) | `{"result": "rejected", "stage", "code"}` | `rejected_before_schema_pass` |
| refusal after a full schema pass (stages 5-8) | `{"result": "rejected", "stage", "code", "request_id"}` | `rejected_after_schema_pass` |

- `outcome` is `{"result": "acknowledged"}` or `{"result": "unknown", "reason"}` with reason `unconfirmed`,
  `interrupted` or `outcome_persistence_failed`.
- `unknown` reasons: `pending`, `unconfirmed`, `interrupted`, `outcome_persistence_failed`, `not_found_or_expired`.
  `not_found_or_expired` is only a status answer.
- **Refusals (W8):** closed code set (section 9); `request_id` is echoed if and only if the schema stage passed; no
  body, digest, actor, station or offending text; the code must belong to the stage.
- **After a possible send** the answer is `unknown`, never `rejected`. A persistence failure after the relay command
  was possible is `unknown/outcome_persistence_failed`; before sending it is `rejected state/storage_unavailable`.
- All schemas are closed (`additionalProperties: false`).

## 8. Clock health (W7) - NOT YET VERIFIED

- Missing clock, or UTC before 2026-01-01T00:00:00Z: `time/clock_invalid` (as in v2).
- The floor alone is not enough. Also blocked with `time/clock_invalid` (Arx reading, open item W-a):
  - no valid UTC anchor stored yet;
  - UTC below the stored UTC anchor (regression, for example after a restart);
  - `|(utc_now - utc_ref) - (monotonic_now - monotonic_ref)| > 2000 ms` (exactly 2000 ms is allowed).
- Until a valid anchor exists: no dispatch and no replay-record deletion. Applies to both services.
- This is **not** a skew allowance: a healthy clock does not admit a future `issued_at` (vector
  `clock_healthy_is_not_a_skew_allowance`).
- The anchor procedure (who stores it, when an anchor becomes valid, how it advances) is open (W-b). The clock vectors
  are marked `verified: false` and use a millisecond snapshot (`utc_now_ms`, `utc_ref_ms`, `monotonic_now_ms`,
  `monotonic_ref_ms`, `stored_utc_anchor_ms`) as a model, not as an interface.

## 10. Versioning

- `protocol` names the whole contract: transport, wire fields, limits, serialization, signing recipe, time rules,
  codes, responses and the DTO. Once v1 is locked, any change to a limit, field, type, code, response shape or the
  serialization needs a new `protocol` value (`wiskey-trusted-door-v2`, ...).
- Vector files have their own `vectors_version`. A new version is an additional file or section; existing vectors are
  never edited. A wrong vector is superseded by a new id with a note (`supersedes` in the v3 file).
- `GOLDEN_VECTORS.json` (v1 `vectors` + v2 `contract_vectors`) stays binding, locked by SHA-256
  `2966133294109546e5a1d4b6dc319264bf17b80a1e468088b087c549f10c5a1f`, except the one superseded case.
- A contradicting change in the pinned documents (section 0) needs an agreed change request.
- WisKey-internal changes that keep this contract need no Arx work.

  `not_found_or_expired`; a status on a completed open answers `stored_result`, not a top-level `unknown`; the
  identical `door_open` while pending answers `unknown/pending` without `target_request_id`.

  `state/relay_not_allowed` and no new code; there is no vector for it yet.
