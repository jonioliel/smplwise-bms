## 3. Broken Hebrew repaired

`services/calendar/events.py`: every Hebrew text (45 refusals - "the event was not found", "the slot is taken", ...) had been
UTF-8 bytes read as cp1255 since CAL-GRID-EDIT-2343 (`e3514b21a`, 02.11): a calendar refusal showed `׳”׳׳™׳¨׳•׳¢...`. The undefined
cp1255 bytes were kept as U+0080..U+009F, so the repair is lossless (re-encode cp1255, decode UTF-8); the result equals the texts of
the commit before the break. Same for one comment in `frontend/src/tickets/settings-locations.ts`. A test now fails on mojibake in
`smplwise/`. (Two backend test files hold mojibake as test input data; left as they are.)

## 4. Server refusal texts (`user_message`)

`smplwise/error_text.py` + `error_text_en.json`: {Hebrew: English} for the 2,304 distinct constant Hebrew texts raised through
`ApiError`, the `errors.py` helpers and the modules' own error classes / helpers (`*Error`, `*Invalid`, `_refuse*`, `_err*`,
`_422`, ...). Keyed by the Hebrew text, like the frontend's `tr()` tables, so nothing at the 3,429 raising sites changed and a Hebrew
reader gets the same bytes. `ApiError.message_in(lang)`: a `Msg` -> `details.message_en` -> this table -> the Hebrew as raised;
`translatable()` is also true when the table has the text, so the handler reads the requester's `ui.lang` (I18N-BACKEND-2490).
`scripts/i18n_backend_errors.py` (AST, imports nothing) counts constants without English and run-time f-string Hebrew texts per
module; `docs/i18n/BE_ERRORS_EN_RATCHET.json` (0 missing, 257 run-time) is read by `tests/test_i18n_errors_en_2520.py`. A new constant
Hebrew refusal without English fails that test: add its English to `error_text_en.json` (or `--ratchet --allow-raise` with a reason).
The WisKey rows add ~4 such lines (R3 2, R4 1, R6 1) - the train adds their English at merge.

## 5. Notification titles and bodies

`services/notify_policy_en.py`: English title / body / resolve text of the 124 sources whose texts are templates
(`notify_policy.SOURCES`; the generator alert types included). `notify_policy.render(source, params, lang="he")` renders them in
English on request. The notification centre (`notify.serialize`, used by the list and the single-row routes) renders a
row again from its stored params for an English reader - only when the stored Hebrew is exactly what the source's Hebrew templates
give for those params (a row written by an older version, or a body from its own `_template`, is shown as stored). Never written back.
Push, e-mail, the phone app and WhatsApp send the stored Hebrew as before (open question 1).

   pack in the worker). (a) a small he/en table in the worker, chosen by the browser language - follow-up; (b) leave.

   Hebrew document, word for word with the server's PDF); (b) an English bill.
6. New TOU season / band default names are written into `name_he` only. (a) keep (the Hebrew half of a bilingual name; the
   English half has its own field); (b) also fill `name_en`.
