## 1. Method and rules applied

- **REVIEW -> DONE** only when the registry itself proves it: every acceptance test of the card is already PASS in
  `management/test_catalog.json` at one common commit (the existing records of the catalog sweeps: main nightly tier L @ `eab715e53`,
  fakes only), that commit is on `origin/main` and contained in a release tag (`git describe --contains`), the card's implementation
  commit (if recorded) is an ancestor of `origin/main` with its first tag named, and every dependency is DONE or OBSOLETE
  (fixpoint, top-down). `scripts/project_status.py` requires the card's `commit` to equal its tests' commit, so the card's commit field
  now names the acceptance commit, and the evidence line keeps the previous implementation commit. This follows the 40 earlier DONE cards
  (their commit is the gated commit, e.g. `7b9b63e7`, `240424e0`, `a06ba53a`).
- A card with all tests PASS was **held in REVIEW** when its own records show open scope, a recorded contradiction, a missing test, or an
  open owner question / acceptance (section 4.1).
- **Not touched:** OBSOLETE / frozen cards (T003, T004, WXD5B, WXIMP, WXG0, WXG1), owner-gated BLOCKED cards (status and blocker kept;
  evidence lines only where there is a new fact). No scope invented: new cards describe only merged work, pushed branches and items the
  owner already named.
- Open cards (BACKLOG / BLOCKED / IN_PROGRESS) were re-checked against the commits since BOARD-HYGIENE-2407 (`v2.40.7..origin/main`:
  CAMERA-STREAM-SOURCES-2410, NVRLESS-CAMERAS-2411, DISK-CLEANUP-2411, one wall test fix). None of them closes an open card; the
  T008 ... T097 chain stays pinned by T005 and T006.
- New cards are REVIEW (shipped) or open, never DONE: DONE needs a catalog PASS tied to a commit, and the change-record receipts of
  2.41.x are not catalog PASS records. Their new tests are NOT_RUN.
- Edits keep the file layout (`json.dumps(..., ensure_ascii=False, indent=2)` round-trips the files byte for byte). New cards,
  requirements and tests are inserted before the last element of each list so a merge with `fix/TEST-DEBT-2412` (which appends
  TEST-DEBT-2412 and FLAKY-S12-PIXEL-2412 at the end) has no overlapping hunks. Test debt is tracked by those two cards, not here.
