## F01 - lease lifecycle (reply section 7)

`_LEASED` stays the one registry. The delta's `_LEASE_STREAMS` does not exist. Each record is now an `_Lease` with these fields: station,
expiry, owner (the `VideoChannel`), profile, digest (the go2rtc registration it made), settings, generation, timer, timers and
quarantined. `_LEASE_LOCK`, `_sweep_leased` and `release_leased_streams` are kept, and so is the last-viewer cleanup in
`station_live_ws`.

1. Names belong to the owner: `smplwise_wiskey_<station>[.sub].w10.<random>`. A lease therefore never re-points or deletes the stills'
   `smplwise_wiskey_<station>` stream, and two owners never share a name.
2. A fresh lease from the same owner, station and profile with an unchanged source renews the registration. The source is not sent
   again, and the timer is re-armed with a new generation. A changed source retires the earlier stream first. If that delete is not
   confirmed, the new source is refused with `intercom_media_cleanup_failed`. If a viewer is still watching the earlier stream, it stays
   until the last viewer leaves.
3. A stream is deleted only while `go2rtc._REGISTERED[name]` still equals the record's digest. A foreign registration is never deleted;
   only the record is dropped.
4. Quarantine: when go2rtc answers a delete with anything other than 200, 204 or 404, or does not answer, the record and the registration
   are both kept. The timer and the janitor do not retry. Each of these explicit events tries once more: the last viewer leaving, the
   owner's close, a new lease from the same owner, and the shutdown.
5. One timer per record fires at `expires_at + LEASE_GRACE_S`. It never deletes while a viewer is watching; that case is left to the
   last-viewer release. `close_leased_streams(owner)` is called by `VideoChannel.close` and by `shutdown_bridge`. It retires every
   stream of that owner, ignoring viewers because the owner is gone, then cancels and joins every timer generation outside the lock.
6. `bridge_provider` closes the earlier provider's video owner before it builds a replacement. While a delete is unconfirmed,
   `media_cleanup_failed` keeps the earlier provider, and `provider_for` serves Arx's own source meanwhile. A failed build adopts nothing.
7. Never touched: any name outside `smplwise_wiskey_` (`discard_leased_stream` refuses), probes, and go2rtc's configuration.

Changed WKLIVE expectations (rule 3/4 of the reply, recorded here):
- `test_a_failing_delete_never_breaks_the_end_of_a_viewer`: an unconfirmed delete used to be forgotten. It is now quarantined, is not
  reported as removed, and the next release removes it.
- The stable-name assertions (`== "smplwise_wiskey_entry-a"`) now check the owner's prefix.

## F02 - two-way talk (reply section 8 and the addendum)

- `WiskeyBridgeTalkChannel.open` asks `talk_open(listen=true)` only when WisKey's descriptor lists `audio.listen_transports`
  containing `signed_ws_pcmu_v1`. When it asks, the answer must carry the exact `listen` block (`arx.station_talk_audio.v1`, 8000 Hz,
  mono, 800-byte packets). Otherwise the talk is refused as `talk_listen_unavailable` and closed by its ref.
- `media/talk_audio` events on the talk's own signed connection are read with `talk_audio_v1`: the talk ref, the sequence from 0 and the
  exact shape are all checked. A foreign, out-of-sequence or malformed event ends the talk. At most 3 packets wait, and none older than
  0.3 s is served. Nothing is kept after close.
- Router `_pump` runs four tasks: browser frames, upstream close, the watch, and the station sound. The station sound goes through the
  one downlink adapter, `ReceiveDownlink.for_talk(channel.receive_audio)`, which passes whole 800-byte packets with three at most
  waiting. The session expiry, the stop request and the permission lease are checked before every packet is published, with no await in
  between. A cancel joins every task.
- The browser's existing talk components play the packets: `talk-session.ts` passes binary messages to `talk-mic.ts` `play` (the
  talk's own AudioContext). The uplink is unchanged: the same `TalkPump`, floor and frames.
- No new audio engine. The direct, signed interface is not bypassed. A talk without the offer opens exactly as before.

## Owner decisions 25.10 (second commit)

1. **Full duplex, the microphone open for the whole session (no push-to-talk).** This is built only on the existing pieces:
   `talk-session.ts` (state machine), `talk-mic.ts` (microphone and playback), `TalkPump` and router `_pump` (server unchanged).
   - One click on the talk button starts the session. When the server says `open`, the microphone opens (`talk/ptt` down = the
     server's floor) and frames flow until the end.
   - The same button mutes and unmutes. The state is visible (`data-muted`, `aria-pressed`, label and a mic-off icon). Muted means
     `talk/ptt` up and no frames; the station's sound still plays.
   - "End" (`data-wk-talk-end`) closes the session explicitly. The server's hard limit and every server-side end are unchanged.
   - The live view's own sound is muted for the whole talk (`talk-floor` held from `open` to the end, not per mute), so the station
     is heard once.
   - **Echo and feedback.** The microphone requests the browser's echo canceller: `MIC_CONSTRAINTS` = `echoCancellation: true`,
     plus noise suppression and auto gain. The value the browser actually applied (`track.getSettings().echoCancellation`) is
     reported as `MicHandle.echoCancellation` / `TalkSession.echoCancelled`. When the browser reports `false`, the talk line shows
     "a headset is recommended".
   - There is no software loop. Station packets play from their own buffer sources straight to the speakers. The microphone graph
     (source to script processor) writes silence, so no station sample is ever routed into the microphone path.
   - Whether the acoustic echo is actually cancelled on a given device and browser is NOT_MEASURED: there was no real microphone or
     speaker.
2. **The station's sound re-arms the 30 s idle timer.** The idle end applies to a MUTED session: 30 s with no station sound ends it,
   and every incoming packet starts a fresh window. While the microphone is open, frames flow continuously and only the server's hard
   limit applies; there is no voice-activity detection.
3. **The station's sound inside a talk needs only the talk permission** (`access.call` and `access.station_media = video_talk`). The
   separate `access.station_listen` setting is not read on the talk path. Tests pin that `_pump` and `TalkLease` never call
   `intercom_listen.listen_mode`.

Browser specs changed to the click / mute model (`evidence-`, `layout-` and `pixel-wiskey-station-media.spec.ts`). They run on the
runner and were NOT_RUN here. The pixel baselines for the talking state will change (new label) and need regenerating there.
