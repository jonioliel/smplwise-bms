# WKB-295 T05: the durable full original of a WisKey people write

Status: built and tested with fakes only. Branch `pilot/WKB-295` (from `origin/main` 90cd7d9ae, release 2.12.1).
Nothing is wired. No route, worker or sync path calls the new functions. No switch or `GO_LIVE_PERMITTED` constant changed.
Nothing was run against WisKey, Home Assistant or a station.

## 1. What WisKey asked (T05, their answer of 2026-10-22)

1. The intents table (migration 0145, `services/wiskey_intents.py`) does not close a durable FULL original:
   `ExactOriginal.as_request` is refs-only, unfit for `peer_receipts` / `resolve`.
2. The full original, its hash and the verified context must be recorded in a COMMIT completed BEFORE any I/O. Crash and restart
   must be tested.
3. pin / epoch / exclusive-writer must come from an agreed source, never assumed.
4. An old intent without an original stays UNKNOWN: no reconstruction, no replay, no extra create.
5. The proposal `person_writes/resolve_create` is not an alias of the existing path.

## 2. What Arx built (fakes only)

| Piece | Where | Rule |
|---|---|---|
| `wiskey_intent_originals` table | `smplwise/migrations/0146_wiskey_intent_originals.sql` (PROVISIONAL number) | One row per fence intent (FK to `wiskey_fence_intents`). It holds the canonical JSON of the full original, its SHA-256, the verified context JSON and its SHA-256. Triggers refuse UPDATE and DELETE. |
| Selector immutability | same migration, trigger `wiskey_fence_intents_selectors_immutable` | The exact-original columns of `wiskey_fence_intents` (repository, owner, operation, request, origin, bindings, epoch, command, user, revision) can no longer be updated. Only state and settlement columns move. CR-ACR7-FENCE-02 section 3 asked for this trigger; 0145 did not carry it. |
| `VerifiedWriteContext` (sealed) | `smplwise/services/wiskey_peer.py` | It has repository, owner, writer epoch, exclusive writer and `source`. It cannot be built from caller values, a dict or a `FenceContext`. The only minter is `_mint_write_context`, reserved for the context client, which is **not built**. A test enforces that no product module calls it. |
| `canonical()` | `smplwise/services/wiskey_intents.py` | Rule `arx-json-c14n-v1`: sorted keys, compact separators, UTF-8, no NaN. Floats, non-string keys, ints beyond 2^53-1, depth over 16, size over 64 KiB and an empty original are refused. |
| Secret keys refused | `wiskey_intents.SECRET_KEYS` | An original carrying `pin`, `card*`, `password`, `token`, `secret` or `credential*` keys at any depth is refused. Nothing is written, and no hash over a PIN is ever stored (it would be a guessing oracle). |
| `admit_with_original` | `wiskey_intents.py` | It runs one `BEGIN IMMEDIATE` ... `COMMIT` around the intent row and the original row. It returns only after the COMMIT. The writer epoch comes from the sealed context, never from the caller. It refuses each of the following: an open transaction on the connection, an unsealed context, a context whose repository or owner differs from the verified peer, `exclusive_writer_established` not True, a message `id` inside the original, and a duplicate operation, request or origin. |
| `stored_original` | `wiskey_intents.py` | It re-hashes both JSON values and re-canonicalises the original on every read. It checks the epoch against the intent. A mismatch is `original_corrupt`: the row is never used or repaired. |
| `send_once` | `wiskey_intents.py` | The order is fixed. (1) Read back and verify the stored original; with none it raises `no_original` and nothing is sent. (2) Require a FRESH sealed context with the same repository, owner, peer binding and epoch, and the exclusive writer; otherwise it raises `epoch_changed` or `context_mismatch`. (3) COMMIT `intent` to `sent`. (4) Give the transport the STORED original. If the transport raises, the intent becomes `unknown` (committed). Nothing is ever resent: a second call raises `not_sendable`. |
| `resolve_request` | `wiskey_intents.py` | This is Arx's PROPOSED resolve body: the exact references, `issued_epoch`, the full original, the context and both hashes. An intent without a recorded original raises `no_original`. |
| `recovery_plan` | `wiskey_intents.py` | It runs at restart, sends nothing and changes nothing. `held_not_sent` is an original still in `intent`; it never left Arx, because `sent` is committed before any I/O, and it is not sent automatically. `resolve_with_original` is `sent` or `unknown` with an original. `unknown_no_original` covers an old intent, one admitted through the older `admit`, or a corrupt original. |

`ExactOriginal.as_request` is unchanged (refs-only); its docstring now points to `resolve_request`. The proposed
`person_writes/resolve_create` (`PROPOSED_CREATE_COMMAND`) and `verify_create_resolution` are unchanged. They are not an alias of
this path, and `LiveResolveTransport` still refuses `not_built`.

## 3. Tests (`smplwise_vms/backend/tests/test_wkb_295.py`, A05 part)

The tests use a file database opened by separate connections to simulate another process or a restart:

- After `admit_with_original` returns, a second connection sees the intent, the full original, its hash and the context. The
  connection is not inside a transaction.
- A failing original insert (a test trigger) leaves no intent row: the admission is atomic.
- Crash after `sent` was committed: the transport is entered, then the process dies with a `BaseException`. After restart the state
  is `sent` and the plan says `resolve_with_original`. The resolve body carries the full original and the hashes. A new send is
  `not_sendable` and the transport is not called.
- Crash between the admission and the send: after restart the plan says `held_not_sent`. A send under a new epoch is refused
  (`epoch_changed`), nothing is sent and the state stays `intent`.
- A transport error commits `unknown` and is never retried.
- An old intent admitted through `admit`, with no original, stays `unknown_no_original`. Both `resolve_request` and `send_once`
  raise `no_original`, and the state is not moved.
- These contexts are refused: a dict, a `FenceContext`, one without the exclusive writer, another repository, another owner. The
  sealed context cannot be forged.
- These originals are refused before anything is written: PIN, nested card number, cards list, float, unsafe int, message id,
  empty, too large.
- Immutability triggers on the original and on the intent selectors; the state still moves. A tampered original is
  `original_corrupt`, and recovery classifies it `unknown_no_original`.
- A duplicate keeps the first original.

## 4. What must come from WisKey (definition needed; Arx stops at the interface)

1. **The agreed source of pin / epoch / exclusive writer.** Arx has the owner pin (`wiskey.peer_pin`, `wiskey_peer_registry.OwnerPin`)
   and the sealed `VerifiedPeerRef` minted only by the registry client. Neither the registry read (`peer_bindings/get`) nor the
   transport is delivered. For the writer epoch and the exclusive-writer fact there is NO source in Arx's code. The r9 draft named
   `person_writes/context`; it is not delivered. WisKey must name the command, its result fields, how fresh it must be, and whether
   `exclusive_writer_established` is per connection, per owner or per repository. Until then `_mint_write_context` has no caller and
   `admit_with_original` cannot run in the product.
2. **The exact bytes of "the full original".** Arx records the request object it would send, without the per-connection message
   `id`. WisKey must say whether the hash is over this canonical JSON (`arx-json-c14n-v1`), over the exact wire bytes, or over its
   own canonical form. It must also say whether `operation_id` / `request_id` must appear inside the original, and which hash
   algorithm and encoding it expects.
3. **The wire shape of the resolve** (`peer_receipts` / `resolve`). `resolve_request` is Arx's proposal only.
4. **PIN- and card-bearing originals.** Arx refuses to store a secret or a hash over it. WisKey must say how such a write is
   identified: for example a WisKey-side commitment Arx never sees, or a salted keyed hash held by WisKey.
5. **What "verified context" means to WisKey**: which fields it compares at resolve time. Arx records repository, owner, epoch,
   exclusive writer, source, verified peer ref and peer binding ref + revision.

## 5. Contradictions recorded (not resolved here)

- Migration 0145 and CR-ACR7-FENCE-02 section 3 say "no payload is stored", "no payload hash". T05 asks for the full original and
  its hash. This branch stores them in a NEW table, without secrets. Names and other personal fields of an original MAY be stored.
  Owner decision needed on retention and purge, and on whether the table goes into the encrypted sensitive backup section.
- `wiskey_peer.py` module docstring (lines 24-25) still says `GO_LIVE_PERMITTED` "is False"; the constant is True since ECCACT-295.
  This is stale documentation, not changed here.

## 6. Open risks

- The migration number 0146 is provisional; another branch may take it. The lead renumbers at integration.
- `BEFORE UPDATE OF` triggers fire whenever a statement names a selector column, even with an unchanged value. No current code does
  this (`_move` sets only state columns).
- The older `admit` still exists (existing tests use it). Fence wiring must use `admit_with_original` only. That is a review rule
  until the older entry is removed.
