### Loading it (owner action)

Custom components load at Home Assistant start. After the add-on with this bridge copies 0.10.2 into `custom_components`, **one Home
Assistant restart by the owner** loads the observer. Until then (and on any bridge that does not register it) the add-on's read gets
`unknown_command` -> `core_runtime_bootstrap_unavailable` -> managed staging refused. Nothing was installed or restarted here.

## Policy B / provenance (unchanged)

`wiskey.auto_install` stays OFF by default; no code path turns it on; the only writer is the owner's `PUT /wiskey/switches`, and ON is
refused in this build (D1=b, S1). The observer is observation only: Arx's reader (`wiskey_core_runtime_gate.evaluate`, S2) checks the
closed shape and the challenge and, with no image verifier, returns `unverified` (`core_runtime_provenance_unavailable`) - or
`unavailable` (`core_runtime_process_unavailable`) without process birth. Nothing in the observation can upgrade it (a claimed
attestation, provenance, identity or extra key is `core_runtime_observation_invalid`). The owner's ON never replaces provenance:
with the switch on and a managed pin, `installer_step` stays `blocked` and the native writer is never called. With the switch off the
observer is never read.
