## Method

(the pinned devDependency of A11Y-AUDIT-2490; tags wcag2a/aa, wcag21a/aa, wcag22aa, best-practice; critical / serious only, inside the

## Findings fixed

| # | Where | Was | Now |
|---|---|---|---|
| 1 | `components/sw-step-up-dialog.ts` | The dialog's name is its heading; the focus lands in the code field; the action line ("הפעולה: פתיחת דלת") and the 90 s expiry were never read by a screen reader | The code / alarm-code field has `aria-describedby` = the action line + the expiry hint (`su-action`, `su-expiry`, same shadow root) |
| 2 | `components/sw-dialog.ts`, `components/modal-stack.ts`, `components/focus-return.ts` (new) | The settings save button is disabled while its request waits on the step-up dialog; the browser dropped the focus to the page body, so the dialog had no opener and Escape returned the focus nowhere | `focus-return.ts` keeps the last focused element (one capturing `focusin` listener); `sw-dialog` takes `openerNow()` (the focused control, else the last one); `restoreFocus()` waits up to 3 s for a disabled opener to be enabled again and focuses it only if the focus is still nowhere. `modal-stack.ts` stays import-free (`focusLost()` lives there) |
| 3 | `generator/gen-alerts-page.ts`, `screens/system-setup.ts`, `components/sw-legacy-import.ts` | After an outcome the control that had the focus was gone or disabled and the focus fell to the page body: the un-mute button (gone with the mute), the pulse / revert buttons (disabled while busy; revert gone once reverted), the legacy dialog (closed by its own result / the 409). Before "revert anyway" was asked the revert button was disabled, so cancel returned the focus nowhere | `focusIfLost(el)`: the outcome line takes the focus (`tabindex="-1"`) only when the focus fell back to the page - it is never moved from anywhere else. Lines: `[data-notice]` / `[data-mute-info]`, `[data-nvr-system-msg]`, `[data-nvr-result]`, `[data-legacy-result]` / `[data-legacy-error]` / `[data-legacy-dialog-error]`; before "revert anyway" is asked the focus goes back to the revert button |
| 4 | `pwa/arx-pwa-prompts.ts` | "אחר כך" / "לא עכשיו" / ✕ removed the card under the focus: the focus fell to the page body | The card gives the focus back to the last control of the page that had it (outside the cards; an `sw-button`'s inner button is in a nested shadow root, so containment walks the hosts) |
| 5 | `arx/arx-reconnect.ts` | `role="status"` around the whole `sw-state-panel` (button included) and the panel's own `role="status"` text: two nested live regions | The outer role is dropped; the panel's text is the one live region |
| 6 | `screens/devices-building.ts` | The area row link's `aria-label` replaced its content, so "N לא ידוע" was never read | When the row draws its indicators, the name adds the unknown indicators' own titles ("מנעולים במצב לא ידוע: 1 מתוך 2"); English in `msg/devices.ts` |
| 7 | `calendars/view-rooms.ts` | The phone's hour-window key showed "00:00–06:00" but was named only "חלון השעות" (axe label-content-name-mismatch, WCAG 2.5.3) | Its name carries the hours it shows |
| 8 | `components/sw-legacy-import.ts` | `sw-table` cells do not wrap: the English explanations widened the items table to 946 px in an 842 px card (desktop) - a sideways scroll region no keyboard could reach (axe scrollable-region-focusable, serious). In Hebrew the longest notes reached the card's edge | The explanation is a wrapping span (`white-space: normal`) |

No colour, size or token was added. Visible changes: (8) the legacy report's long explanations wrap onto a second line (the report is a

## Left (not fixed here)

1. The rooms timeline's DST axis: "01 ×2" is read as "01 times 2" and the skipped hour is only a `title` on the hatch; the resident's
   bar has a `role="note"` line that explains it, the rooms view does not.
2. Live regions are created together with their text (`role="status"` / `role="alert"` rendered with the message) on every screen of
   this scope (and in most of the app); some screen readers do not announce a status region that arrives already filled. An alert is
   announced reliably; a status may be missed.
3. Older findings met on the way, not from 2.53-2.55: the generator alerts list cards are `role="button"` with buttons inside them
   (nested-interactive, serious, also in the 2.49 baseline class); every area row link (tree and cards) fails label-content-name-mismatch
   (its `aria-label` does not hold the counts it shows - the 2.49 baseline's "review per component"); the "not locked" / lights
   indicators are still missing from the row's name.
4. The step-up dialog in a passkey-only / phone-only mode: its only control is an `sw-button` (another shadow root), so the action line
   cannot describe it by `aria-describedby`.
5. A controlled switch says nothing while its save is in flight (it keeps the confirmed state, as asked; no "saving" cue).
