## 2. The changes (step 2)

Only import boundaries and route registration; every element renders exactly where and as it did.

- `shell/sw-app.ts` (minimal: import lines and one call): drops the eager imports of `system-cast`, `notifications-settings`,
  `device-activity`, `maintenance/close-prompt` and the three schedule dialogs; imports `./lazy-overlays` and calls `warmOverlays()`
  next to `warmCommonScreens()`. It now imports `sw-card`, `sw-field` and `sw-toggle` itself: they were in the entry only because the
  push settings brought them, and screens and the specs' harness pages render these shared primitives by tag without importing them
  (keeping them costs ~7 KB gzip; dropping them would make every such page depend on an extra chunk). The templates are untouched.
- `shell/lazy-overlays.ts` (new): the two event-opened overlays the shell mounts (`<device-activity>`, `<maint-close-prompt>`). Its
  window listener is registered by the entry chunk, so it hears each event first; while the element is not defined it holds the event
  (stopImmediatePropagation), fetches the chunk once, and sends the held events again in order once the element listens. The shell sets
  no property on these two elements and they draw nothing while closed, so upgrading them in place is safe (unlike the route screens,
  GATE2342-B). The popup's chunk is fetched while the browser is idle after the first screen is up (same conditions as the screen
  warm-up: the `server.startup_warmup` setting, data-saver, a visible tab), so a first long press rarely waits for the network.
- `shell/lazy-screens.ts`: `'cast-my-screens': () => import('../screens/system-cast')` (one line).
- `shell/sw-user-menu.ts`: `onFactorToggle` fetches `sw-second-factor` and `sw-passkeys` together and renders both once landed; new
  `onHomeToggle` / `homeReady` for `sw-home-personal` (the existing GATE2342 pattern).
- `screens/home-widgets.ts`: `loadRemote()` / `remoteReady`; `<media-remote>` is rendered once its chunk landed. The chunk is fetched
  as soon as the media widget is placed and has a device (from `updated`), not at the first press - the drawer draws nothing while
  closed, so nothing on the screen changes.
- `api/launcher.ts`: `runLaunch` imports `./automations` when a scene / script launch runs (the route and quick kinds never needed it).
- `screens/devices-schedules.ts`, `screens/schedule-drawer.ts`, `screens/multimedia-screens.ts`: import lines for tags they render
  that only the entry chunk used to define (`schedule-*` dialogs, `media-remote`) - found by `scripts/lazy-tags-check.mjs`.
- Loading state: each part follows the existing rule of the codebase for on-demand parts (CR-SHELL-LAZY-2436 / GATE2342): nothing is
  drawn in its place until its chunk landed, so no element shows half-initialised and nothing flashes; route screens keep the shell's
  wait (`waitingScreenTags`, `data-shell-ready` off meanwhile).

Kept in the entry on purpose: the door emergency sheet of the home doors widget (a safety action must never wait for a download), the
home screen itself and its camera card, the notification center and the incoming door-station call banner (both live from the first
second), the settings navigation column (would draw after its screen - a flash). See section 5.

## 3. Budget ratchet (step 3)

`frontend/scripts/gates-baseline.json` `bundle`, the same policy as CR-BRIDGE-BUMP-RATCHETS-2460 (measured entry of this branch's
`vite build`, `marginPct` 5 - the cap `tests/unit-entry-chunk.spec.ts` enforces -, budget = ceil(measured x 1.05 / 1000) x 1000):

| | Before | Now |
|---|---|---|
| measured gzip / raw | 807,703 / 2,810,184 (2.45.0) | **638,012 / 2,204,929** (this branch, Windows) |
| marginPct | 5 | 5 |
| budget gzip / raw | 849,000 / 2,951,000 | **670,000 / 2,316,000** |

The margin is 32 KB gzip / 111 KB raw - enough for a Linux build and normal shell growth, too small for an on-demand part to land in
the entry unnoticed. Note: the committed add-on build `smplwise_vms/www` (2.47.0) is over the new budget until the next release rebuilds
it; nothing enforces the budget on it (the gate and `npm run gate:budget` measure `dist`; the unit spec only annotates `www`).

`scripts/lazy-tags-check.mjs`: NOT_IN_ENTRY lists the 12 modules above, so an eager import anywhere brings the check down; the eager
rule accepts the one-hop starter the lazy-group rule already accepted (an eager module whose own direct import starts the defining
chunk - sw-app's overlays through `lazy-overlays.ts`).

`tests/unit-diag-tabs-2440.spec.ts` (the diagnostics screen's own-chunk source budget, 540,000) is unchanged: with sw-card / sw-field /
sw-toggle kept in the entry it passes again (a first version of this branch that let them go measured 548,930 B there).
