# GEN-UNITS-ARRU-2530 - generator settings: Arabic and Russian unit words in the field frame

Target 2.53. Base: origin/release/2530-train 8ae83adfa. Branch: pilot/GEN-UNITS-ARRU-2530.

## Why

The acceptance of GEN-UNITS-FIELD-2490 (AT-GEN-UNITS-FIELD-2490-1) says the text changes exist in all 4 languages. The change
(`docs/changes/GEN-UNITS-FIELD-2490.md`, released in 2.49.0) added the unit words in Hebrew and English only, and
`docs/changes/ACCEPT-SWEEP-2530.md` kept the card REVIEW for that gap. This row closes it.

## What changed

- `frontend/src/generator/gen-text.ts`: the active-language reader of the generator settings (`GEN`, `GEN_SETTINGS`) also serves an
  Arabic and a Russian page: the Hebrew catalogue with this module's own Arabic / Russian words merged over it (built on a read from the
  live pack table, built again only when the pack's `settings` table is another object - the same pattern as the English path). A Hebrew
  page still reads `he.generator` itself, an English page the English merge; both outputs are unchanged. New export `GEN_TEXT_PACKS`
  (the ar / ru live tables, read by the unit spec).
- New language-pack tables `frontend/src/i18n/lang/ar/generator/gen-text.ts` and `.../ru/generator/gen-text.ts` (module
  `generator/gen-text`, loaded with the rest of the Arabic / Russian pack, never in the entry chunk): `settings.units` (kW, kVA, bar,
  C, %, V, Hz, hours, hours ahead, seconds, minutes, days) and the labels of the fields that carry a unit: `rated`, `ratedKva`,
  `thDefault`, the 15 `th.*` threshold labels, `retAlerts`, `retHistory`, `retStale`.
- `frontend/src/i18n/lang/{ar,ru}/i18n/generator-log.ts`: the run-log settings words (`setSub`, `setIntro`, `setEnabled` and the 12
  `set_*` field labels whose unit moved into the frame in 2490). The generator-routing packs already carried every key in ar / ru
  (including `unitMin`, GEN-UNITS-FIELD-2520) - nothing to add there.
- `frontend/src/i18n/lang/ar.ts`, `ru.ts`: regenerated by `node scripts/i18n-split-langs.mjs` (the new pack file sorts first, so every
  `tN` import index shifts by one; a merge conflict there is resolved by re-running the script).
- Word choices (initial translation, dev-marked like the other ar / ru generator words; a native review is still needed):
  - Arabic keeps the technical symbols in Latin letters as the Hebrew does (kW, kVA, bar, °C, %, V, Hz - as the controller shows them);
    the time words are Arabic in the singular form used after a figure (ساعة, ثانية, دقيقة, يوم), matching the routing screen's
    `unitMin` = دقيقة.
  - Russian uses the Cyrillic symbols of Russian technical texts (кВт, кВА, бар, В, Гц) and short time forms that need no plural
    agreement (ч, с, мин, дн.), matching the routing screen's `unitMin` = мин.
- Tests: `frontend/tests/unit-gen-units-arru-2530.spec.ts` (new, Node only), `frontend/tests/evidence-gen-units-arru-2530.spec.ts`
  (new, browser), `frontend/tests/unit-genlog-tempexplain.spec.ts` (its "Russian falls back to Hebrew" sample key `setIntro` now has a
  Russian word; the check uses `why_none`, still untranslated, and asserts `setIntro` is no longer the Hebrew).
- Unchanged: Hebrew and English words, `he.ts` / `en.ts`, element ids, `data-*` hooks, values, validation, request bodies, saved data,
  design tokens (no new literal). The product's language switch still offers Hebrew and English only; an Arabic / Russian page is reached
  through `<html lang>` (an embedding page), as for the other ar / ru catalogues.
- Not in this row: the rest of the generator settings screen on an Arabic / Russian page (intro lines, buttons, the tab strip, the
  sensor-mapping and routing labels of the main catalogue) stays Hebrew there - the main catalogue `he.ts` / `en.ts` has no Arabic or
  Russian column anywhere in the product. The run-log PAGE words (KPI, columns, reasons) are still partly untranslated in ar / ru.
