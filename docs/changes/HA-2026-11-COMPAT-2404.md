# HA-2026-11-COMPAT-2404 - Home Assistant 2026.11 entity names and child devices

Branch `fix/HA-2026-11-COMPAT-2404`, cut from `origin/main` at `ccb77f28d` (v2.40.2). Target: **Arx 2.40.4**. No version bump, no
tag, no merge here. No lab or device was contacted: every finding below comes from the Home Assistant source at the release tags, and
every test runs on fixtures.

**Owner: do not upgrade Home Assistant to 2026.11 before this ships.** The lab runs 2026.10.4; this change keeps 2026.10 working
unchanged in behaviour that matters (names become the ones Home Assistant itself shows - see section 4).

### 1.1 Entity registry (core `homeassistant/helpers/entity_registry.py` @ 2026.11.0)

|---|---|---|
| Storage version | `STORAGE_VERSION_MINOR = 24` (was 23) | migration `if old_minor_version < 24` (L1053) |
| Migration rule | L1053-1099 | for every entity with a non-empty `name` and a device that has a name (`name_by_user or name`): if the entity has **no area of its own** and `_async_strip_prefix_from_entity_name(name, device_name)` is not None, `name` becomes the stripped name; otherwise `name` is kept and `compat_name = name` (also the first conversation alias when exposed and the alias slot was "computed"). Deleted entities lose their `name`. |
| Prefix strip | `_async_strip_prefix_from_entity_name` L735 | case-folded prefix match, the case-fold length difference handled per character; after the prefix at least one of ` -:` must follow (else None); the separators are stripped; empty rest -> `""` (the name IS the device name); a lower-case first word is capitalised, a mixed-case one kept. |
| `compat_name` | `RegistryEntry.compat_name` (L305); storage only (`as_storage_fragment` L468) | **not** in `as_partial_dict` (the `config/entity_registry/list` answer) nor in `extended_dict` (`get`). Cleared by any update touching `device_id`, `has_entity_name` or `name` (L2185-2192) and when the user renames the device (L1954). |
| `friendly_name` | `async_get_legacy_friendly_name` L634; `Entity._friendly_name` in `helpers/entity.py` | returns `compat_name` while set; else `[device] [entity]` with the device ALWAYS (`use_next_name_part=False`), the entity part = `name`, else `original_name_unprefixed`, else `original_name`. | Composed name | `async_get_full_entity_name` L664 -> `_async_get_full_entity_name` L528 | parts `PARENT_DEVICE, DEVICE, ENTITY`, `use_next_name_part=True`: the device takes part only when the entity's `next_name_part` is `device`; the parent device only when, in addition, the device is a child device whose own `next_name_part` is `parent_device`. |

| WS listing shape | `as_partial_dict` L393 | 2026.11 **removed `has_entity_name`** (present in 2026.10.4, L369 there). `original_name` is `original_name_unprefixed` when set. `next_name_part` present in both. |
| Main entity | `RegistryEntry.entity_name` L330, `_has_own_area_without_own_name` L1347, `_async_get_child_device_accepting_area` L1357 | not a stored flag: an entity **with a device and no name of its own** (`name == ""`, or no name and no original name). |

### 1.2 Device registry (core `homeassistant/helpers/device_registry.py` @ 2026.11.0)

https://github.com/home-assistant/core/blob/2026.11.0/homeassistant/helpers/device_registry.py

- `ChildDeviceEntry` (L847): `parent_device_id`, `name`, `name_by_user`, `area_id`, `identifiers`, `labels`, `config_entry_id`,
  `config_subentry_id`, `disabled_by`; **no** manufacturer, model, connections, via device. `dict_repr` adds
  `next_name_part` (L885: `area` when the child has an area, else `parent_device`). Main devices list `parent_device_id: null`.
- `async_get_effective_area_id` (L4987): the device's area, else - for a child device - its parent's (parent looked up with
  `include_child_devices=False`: one level).
- `config/device_registry/list` (`components/config/device_registry.py` L96) lists `chain(registry.devices, registry.child_devices)`:
  child devices are in the same listing. This is already true in 2026.10.4 (child devices exist since 2026.9); 2026.11 starts
  migrating integrations to them (Tuya multi-channel switches first).

### 1.3 Frontend display rule (frontend @ 20261028.4)

https://github.com/home-assistant/frontend/blob/20261028.4/src/common/entity/compute_entity_name_display.ts

- `computeEntityEntryName` (L75): `entry.name ?? original_name`, an empty result -> undefined.
- `computeEntityEntryNameParts` (L86): device = when `entry.next_name_part === "device"` or the entity has no name of its own;
  parent device = when `entry.next_name_part === "device"` and `device.next_name_part === "parent_device"`.
- `computeEntityNameDisplay` (L149) with no configured name: `DEFAULT_ENTITY_NAME` = `parent_device, device, entity`
  (`entity_name_config.ts`), joined with a space, else the state's friendly name.
- "Main entity of the device ({device})" switch (`panels/config/entities/entity-registry-settings-editor.ts`):
  `_isMainEntity = !!this._device && !this._entryName` (L278); turning it on saves `name: ""` (`_computeName`, L1798) and clears
  the entity's own area (it takes the device's).
- Before (20260930.5): with no configured name a card showed `computeStateName` = the state's friendly name.

## 2. Problems in Arx (before this change)

1. `ha_client.registry_maps` stored `name or original_name or device name`. After the migration every user-renamed entity whose
   name started with its device's name loses that part in Arx ("Front Door Motion" -> "Motion", "Living Thermostat Temperature" ->
   "Temperature"). The alarm's name pairing (strategy 4, `services/alarm.py`) then sees two zones both called "Motion": no pair
   (or, with a unique collision, a wrong one). Search, the device lists and every screen showing `name` show the bare part.
2. An entity's area was `entity area, else device area`. A child device without an area of its own has `area_id: null`: its
   entities fell to "no area" and off the map structure.
3. Child devices: no parent link in the device mirror; switch classification saw no manufacturer / model; media endpoints of a child
   device and its parent were two devices; device lists named a child "Socket 1" with no context.

## 3. What this change does

| Area | File | Change |
|---|---|---|
| Naming rule | `services/ha_naming.py` (new) | Port of the rules above. `registry_shape()` decides per listing: **v124** (`next_name_part` present, `has_entity_name` absent: 2026.11+), **v123** (both present: 2026.9/10), **old** (no `next_name_part`: older core and hand-written fixtures - Arx's earlier rule kept). `entity_names()` returns the displayed name, the short part and the main-entity mark. `strip_prefix()` = core `_async_strip_prefix_from_entity_name`. `effective_area_id()`, `device_label()`, `mirror_row_label()`. |
| Registry map | `services/ha_client.py` `registry_maps` | `name` = the name Home Assistant shows (v124: `[parent] [device] [entity]` by `next_name_part`; v123: the legacy friendly-name rule; old: unchanged); new `short_name`, `main_entity`, `naming`; area = entity, else the device's **effective** area (child -> parent). |
| Storage | migration `0206_ha_entity_names.sql`; `services/ha_sync.py` | `ha_entities.short_name`, `ha_entities.main_entity`; `ha_devices.parent_device_id`, `ha_devices.next_name_part`. `apply_registry` writes them (a separate guarded statement, as for `config_entry_id`). `entity_row` returns `main_entity` as a boolean. |
| Device mirror | `services/media_store.py` `apply_devices` | stores `parent_device_id` / `next_name_part`; `area_id` is the effective area, so every reader (automations' device lists, generator, media) places a child where Home Assistant does; a parent's move is followed on the next refresh. |
| Alarm pairing | `services/alarm.py` | strategy 4 keys on the full displayed name (never the short part), then a second pass on the state's friendly name (Home Assistant keeps the pre-migration name there while a compat name is set). Strategy label stays "שם". The bypass-word check also reads the short and friendly names. Order unchanged: device -> integration key -> entity id -> unique id -> name -> zone number. |
| Search | `routers/search.py` | also matches the state's friendly name (the name the operator knew before the upgrade). |
| Device names | `services/automation_ext.py` (wall-button device list), `services/automation_scope.py` (`device_name`) | a child device without an area of its own is named "Parent Child" (no doubled prefix). |
| Switch protection | `services/switch_protection.py` `_device_lookup` | a child device takes its parent's manufacturer / model for classification. |
| Media | `services/media_model.py` | rung 1 ("same HA device") also joins a child device's endpoints with its parent's; a child's parent describes it for the kind (manufacturer / model). |

Not changed, on purpose: `routers/wall.py` state chips use `original_name` (the integration's name, untouched by the migration);
`routers/devices.py`, `elevators.py`, `generator.py`, `temperature.py`, `tickets.py` read `name`, which now carries the full name;
no frontend change (the API adds `short_name` / `main_entity` to entity rows; no screen uses them yet - a screen that shows the device
beside the entity may switch to `short_name` later).

## 6. Risks and limits

- `registry_shape` keys on `has_entity_name` disappearing from the listing. If a 2026.11.x patch puts it back, Arx would apply the
  2026.10 rule (the legacy friendly name) - still a full name, not the bare part; the alarm pairing keeps working through the friendly
  name. Re-check at each Home Assistant minor.
- The legacy rule is core 2026.10.4's `async_get_legacy_friendly_name`: it prefixes the device also for a legacy-named entity whose
  original name does not start with the device name. Arx shows what Home Assistant shows there.
- `compat_name` is invisible to Arx except through the state's friendly name; a state that has not arrived yet leaves the friendly-name
  pass of the alarm pairing empty for that entity until it does.
- Media: a child device's media endpoints merge with the parent's (rung 1). Media child devices are not known in the field yet
  (Tuya switches first); a merge that is wrong can be split by the administrator's "unlink" rule.
- Migration number 0206: no other branch used it at the time of writing (checked `git log --all` and the local worktrees); a train that
  also adds 0206 must renumber one of them.
- Names change on 2026.10 for entities Home Assistant names device + part (section 4). Screens, search results and alarm zone lists
  show the longer name; this is the requested "same names as Home Assistant".

## 7. Lab check for the owner after the Home Assistant upgrade

After Arx 2.40.4 is installed and BEFORE upgrading Home Assistant: note three names in Arx (an alarm zone, a renamed sensor, a device
with several sockets if there is one). Then upgrade Home Assistant to 2026.11 and:

1. Arx > Settings > System: the infrastructure connection is back (wait for the registry refresh, about a minute after Home Assistant
   is up).
2. Security > Alarm: every zone still shows its bypass control (the same as before the upgrade); no zone moved to "unpaired".
3. Explore > Entities: search the three noted names - each shows the same name Home Assistant shows on its own entity page/cards
   (device + entity name), not a bare "Motion" / "Temperature".
4. A device split into child devices (a Tuya power strip, if any): its sockets appear in the parent's area and are named
   "<strip> <socket>".
5. Report any name that differs from Home Assistant's card, with the entity's Home Assistant settings page (name, device, area,
   "Main entity of the device").

## 8. Rollback

Revert the branch commit. Migration 0206 only adds nullable / defaulted columns; an older Arx ignores them. After a rollback on
Home Assistant 2026.11 the earlier naming bug returns (bare names, alarm name pairing lost).
