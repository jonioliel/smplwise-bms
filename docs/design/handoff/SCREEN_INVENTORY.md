# Screen inventory (designer handoff, 2026-09-30; refreshed 2026-10-09 for product 2.4.2)

Every route the product renders today, as the shell's router (`frontend/src/router.ts`, `frontend/src/shell/sw-app.ts` `renderRoute`,
`frontend/src/shell/nav.ts`) and the screen catalogue (`docs/design/SCREEN_CATALOG.md`) define it. This is the list a designer must cover;
the brief says how. Facts only; unknowns are marked **UNKNOWN**.

**Refresh 2026-10-09.** Rewritten against `main` @ `31fe5d7c` (product **2.4.2**) and compared with release 0.1.148.1 (`1fab444b`). Rows and
sections marked **NEW** did not exist in 0.1.148; **CHANGED (2.4.2)** notes are appended to rows whose screen changed. New sections: §4a
Multimedia, §4b Infrastructure, §6a new settings screens, §7 K2 wall display, §8 (status of the old "screens still to come"), §9a
permission-gated variants. The rail now has up to **six areas** (ראשי · אבטחה · מפה · מולטימדיה · WisKey · תשתיות) plus settings from the
user menu. Screenshot paths still point at the 0.1.148 captures in `current/`; for new screens they point at the committed evidence sets
listed in `REFERENCE_BOARD.md` §1a. No screen was re-shot in this refresh.

Conventions used in the tables:

- **Route** is the hash route of the single-page app (`#/...`). `:id` is a path parameter.
- **Who** is the permission the shell requires before it offers the tab (`TAB_PERMISSIONS` in `nav.ts`); the server checks the same
  permission on every request. "everyone" = every signed-in user with at least one role. Roles and the permissions they hold are in §6.
- **Viewports** are the Playwright projects the product is verified at (`frontend/playwright.config.ts`): **D** desktop 1440×900,
  **T** tablet 1024×768, **P** phone 390×844 (Pixel 7 emulation). The phone breakpoint is `max-width: 767px`; the tablet breakpoint
  `max-width: 1023px`. Bold = the viewport that matters most for this screen.
- **Screenshot** paths are relative to `docs/design/handoff/current/` (see `REFERENCE_BOARD.md` for what each shows and how old its shell
  chrome is). "—" = no committed screenshot of the current build.
- **States** are the ones the implemented screen actually renders (`sw-state-panel state=...` and the screen's own variants), in the
  vocabulary of the design contract: loading · empty · error · forbidden (no permission) · stale/offline · partial · read-only (view-only:
  the user sees but may not act) · edit mode · phone-restricted (a feature the phone does not offer). Every screen also has **ready**.

Visibility rules that shape the UI (all implemented):

- A tab is offered only when the user holds one of its permissions (`TAB_PERMISSIONS`); a whole area leaves the rail when none of its
  tabs remain. Hidden is not a lock-out: a URL still opens for a holder, and a non-holder lands on a `forbidden` panel.
- An administrator can hide and reorder tabs per section for everyone (`ui.tabs`); a user can reorder the rail areas for themselves. The
  tab PRESENTATION (tabs / hybrid / dropdown and the dropdown style) is per installation with a personal override.
- Feature switches hide for everyone: the WisKey area, the map area, the live overview, the schedules segment, **the automations
  segments (`automations.enabled`)**, **the multimedia area (`multimedia.enabled`)**, the alarm pages (only when the platform positively has
  no panel). **Capabilities** hide routes the installation cannot serve (no recorder, no media server) and show a neutral panel on a direct
  URL. **Presence-based**: the infrastructure tabs appear only when meters / a generator exist (or the user manages them); multimedia tabs
  only when the device kinds exist.
- Screen edit modes are entered ONLY from the user menu (never from an in-screen button); the item appears only when the permission holds.
- On the remote channel (Arx app / browser through the tunnel): sign-in page (with MFA and the Android download), live streams capped per
  sign-in (default 4; the tile says so, never retries), main stream over WebRTC when the encoding allows, MSE only as an announced
  fallback, idle lock optional, "יציאה" in the user menu, "הכניסות שלי" list with masked addresses, no NVR batch operations. The UI never
  shows a control the server would refuse; a refused action shows its server message.
