# Screen inventory (designer handoff, 2026-09-30)

Every route the product renders today, as the shell's router (`frontend/src/shell/sw-app.ts` `renderRoute`, `frontend/src/shell/nav.ts`) and the
screen catalogue (`docs/design/SCREEN_CATALOG.md`) define it, plus the screens that are planned but not built. This is the list a designer
must cover; the brief (`DESIGN_HANDOFF_HE.md`) says how. Facts only; unknowns are marked **UNKNOWN**.

Conventions used in the tables:

- **Route** is the hash route of the single-page app (`#/...`). `:id` is a path parameter.
- **Who** is the permission the shell requires before it offers the tab (`TAB_PERMISSIONS` in `nav.ts`); the server checks the same
  permission on every request. "everyone" = every signed-in user with at least one role. Roles and the permissions they hold are in §6.
- **Viewports** are the Playwright projects the product is verified at (`frontend/playwright.config.ts`): **D** desktop 1440×900,
  **T** tablet 1024×768, **P** phone 390×844 (Pixel 7 emulation). The phone breakpoint is `max-width: 767px`; the tablet breakpoint
  `max-width: 1023px`. Bold = the viewport that matters most for this screen.
- **Screenshot** paths are relative to `docs/design/handoff/current/` (see `REFERENCE_BOARD.md` for what each shows and how old its shell
  chrome is). "—" = no committed screenshot of the current build.
- **States** are the ones the implemented screen actually renders (`sw-state-panel state=...` and the screen's own variants), in the
  vocabulary of the design contract: loading · empty · error · forbidden (no permission) · stale/offline · partial · read-only (view-only:
  the user sees but may not act) · edit mode · phone-restricted (a feature the phone does not offer). Every screen also has **ready**.

## 9. Roles (built-in) and what they see — for permission-driven variants

Source: `smplwise_vms/backend/smplwise/roles.json`. Every role is bound with a scope (installation / site / building / floor); a floor-scoped
user sees narrowed trees, maps and lists. Sensitive permissions are never implied by a role name.

| Role id | Hebrew name | Holds (summary) | Typical surface |
|---|---|---|---|
| `viewer` | צופה | map.read, video.live, devices.read, alarm.view, entity.state.read, access.read | everything read-only: counters without controls, tiles without toggles, the alarm state without arm / disarm |
| `kiosk` | תצוגת קיוסק | map.read, video.live | the kiosk wall only |
| `operator` | מפעיל | viewer + devices.control, alarm.arm, video.playback, events.read/ack, video.export, cases.manage, ha.entity.control | daily operator: single-device control, arm, playback, events, cases; no bulk, no disarm, no editing |
| `editor` | עורך מפות ותצוגות | viewer + map.import/edit/publish, placement.edit, views.edit, catalog.manage | Plan Studio and saved views |
| `site_admin` | מנהל אתר / מבנה / קומה | operator + editor + devices.control_bulk, alarm.disarm/bypass, access.release/people/cards, rules.manage, rbac.assign, schedule.view/manage, site.content.configure | everything in their scope incl. bulk off, disarm, schedules, delegation |
| `system_admin` | מנהל מערכת | all of the above + system.configure, sources.configure, audit.read, backup.manage, rbac.roles.manage, schedule.sensitive, nvr.* | the settings area, editors of layouts / tabs / themes, the wizard |

Visibility rules that shape the UI (all implemented):

- A tab is offered only when the user holds one of its permissions (`TAB_PERMISSIONS`); a whole area leaves the rail when none of its
  tabs remain. Hidden is not a lock-out: a URL still opens for a holder, and a non-holder lands on a `forbidden` panel.
- An administrator can hide and reorder tabs per section for everyone (`ui.tabs`); a user can reorder the rail areas for themselves.
- Feature switches hide for everyone: the WisKey area, the map area, the live overview, the schedules tab, the NVR areas (NVR-less mode),
  the alarm pages (only when the platform positively has no panel).
- Screen edit modes are entered ONLY from the user menu (never from an in-screen button); the item appears only when the permission holds.
- On the remote channel (Arx app / browser through the tunnel): sign-in page, live streams capped per sign-in (default 4; the tile says
  so, never retries), main stream over WebRTC when the encoding allows, MSE only as an announced fallback, idle lock optional, "יציאה" in
  the user menu, "הכניסות שלי" list with masked addresses. The UI never shows a control the server would refuse; a refused action shows
  its server message.
