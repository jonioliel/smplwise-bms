# חיבור ראשון של Google Drive לגיבוי - מדריך צעד אחר צעד

הגרסה באנגלית: `GDRIVE_CONNECT_SETUP.md`. המדריך הקצר הקודם: `GDRIVE_BACKUP_SETUP_HE.md`.

זמן משוער: 15-20 דקות, פעם אחת. צריך: מחשב עם דפדפן, חשבון Google שבו יישמרו הגיבויים, וגישת מנהל מערכת ל־Arx.

Arx לא יוצר עבורכם שום דבר ב־Google. אתם יוצרים "פרויקט" קטן ב־Google Cloud (חינם), ו־Arx מקבל ממנו רק שני ערכים: **Client ID** ו־**Client secret**. ההרשאה שמבוקשת היא הצרה ביותר שיש (`drive.file`): Arx רואה רק את התיקייה ואת הקבצים שהוא עצמו יצר, ולא שום קובץ אחר ב־Drive שלכם.

> שמות המסכים ב־Google Cloud Console מופיעים כאן באנגלית, כמו שהם מופיעים במסוף. אם המסוף מוצג אצלכם בעברית, אפשר להחליף את שפת המסוף לאנגלית לזמן ההגדרה (תמונת הפרופיל › Preferences › Language), או להיעזר במיקום הכפתורים.

---

## חלק א. ב־Google Cloud Console

### 1. פרויקט חדש
1. נכנסים ל־https://console.cloud.google.com עם חשבון Google (רצוי אותו חשבון שבו יישמרו הגיבויים).
2. בפס העליון לוחצים על בורר הפרויקטים (ליד הלוגו של Google Cloud) › **New project**.
3. **Project name**: למשל `SmplWise Arx backup` › **Create**.
4. מוודאים שהפרויקט החדש נבחר בבורר הפרויקטים לפני שממשיכים.

אל תמחקו את הפרויקט כל עוד הגיבויים נשמרים: מחיקתו מבטלת את החיבור.

### 2. הפעלת Google Drive API
1. תפריט ☰ › **APIs & Services** › **Library**.
2. מחפשים `Google Drive API` › לוחצים על התוצאה › **Enable**.

זו הטעות הנפוצה ביותר בניסיון ראשון. אם מדלגים, "בדיקת חיבור Google" ב־Arx תאמר: "Google Drive API לא הופעל בפרויקט".

### 3. מסך ההסכמה (Google Auth Platform)
1. תפריט ☰ › **Google Auth Platform** (או APIs & Services › **OAuth consent screen**, שמעביר לאותו מקום) › **Get started**.
2. **App Information**: **App name** = `SmplWise Arx`, **User support email** = הכתובת שלכם › **Next**.
3. **Audience**: בוחרים **External** › **Next**. (Internal מתאים רק לארגון Google Workspace; עם חשבון Gmail רגיל הוא ייכשל בשגיאה `org_internal`.)
4. **Contact Information**: הכתובת שלכם › **Next**.
5. **Finish**: מסמנים את ההסכמה ל־Google API Services: User Data Policy › **Continue** › **Create**.
6. לא מעלים לוגו (לוגו מחייב אימות של Google ומעכב).

### 4. ההרשאה drive.file
1. ב־Google Auth Platform › **Data Access** › **Add or remove scopes**.
2. בשדה הסינון מקלידים `drive.file` ומסמנים את `.../auth/drive.file` (התיאור: "See, edit, create, and delete only the specific Google Drive files you use with this app").
3. **Update** › **Save**.

לא מוסיפים שום הרשאה אחרת. Arx מבקש רק את זו ויסרב לעבוד עם חיבור שנותן משהו אחר.

### 5. משתמש בדיקה (מצב Testing)
1. Google Auth Platform › **Audience**. ב־**Publishing status** כתוב **Testing** - משאירים כך לניסיון הראשון.
2. באותו מסך, **Test users** › **Add users** › כתובת חשבון Google שבו יישמרו הגיבויים › **Save**.

בלי זה, בשלב האישור Google יציג "Access blocked" / "הגישה חסומה" או "has not completed the Google verification process", ו־Arx יראה "האישור נדחה".

**חשוב - תוקף 7 ימים:** כל עוד הסטטוס הוא Testing, Google מבטל את החיבור **7 ימים** אחרי האישור. לכן אחרי שהניסיון הראשון הצליח, עושים את שלב 9.

### 6. לקוח OAuth מהסוג הנכון
1. Google Auth Platform › **Clients** › **Create client**.
2. **Application type**: בוחרים **TVs and Limited Input devices**. לא Web application ולא Desktop app.
3. **Name**: `SmplWise Arx` › **Create**.
4. בחלון **OAuth client created** מעתיקים את **Client ID** ואת **Client secret** (אפשר גם **Download JSON** ולשמור במקום בטוח).

**הסוד מוצג רק עכשיו.** אם סגרתם בלי להעתיק: Clients › הלקוח › **Add secret**, ומעתיקים את הסוד החדש.

**אין Redirect URI.** Arx מתחבר בקוד קצר שמאשרים ב־google.com/device, ולכן אין "Authorized redirect URIs" ואין מה להדביק שם. אם המסך שאתם רואים מבקש Redirect URI - נבחר סוג לקוח שגוי; חוזרים לסעיף 2.

## חלק ב. ב־Arx

הגדרות › אבחון › גיבוי ושחזור › **עותקים מחוץ למכונה**. נדרש מנהל מערכת.

### 7. מפתח ההצפנה קודם
אם בכרטיס "מפתח ההצפנה" כתוב שהמפתח לא יוצא - **ייצוא מפתח**, מקלידים `EXPORT`, ושומרים את המפתח מחוץ למערכת (מנהל סיסמאות, דף מודפס בכספת). ב־Drive נשמר רק עותק מוצפן; בלי המפתח אי אפשר לפתוח אותו.

### 8. היעד, הבדיקה והחיבור
1. **הוספת Google Drive**.
2. מדביקים:
   - **Client ID** - הערך שמסתיים ב־`.apps.googleusercontent.com`.
   - **Client secret** - בלקוחות חדשים מתחיל ב־`GOCSPX-`. רק הערך עצמו: בלי רווחים, בלי מירכאות, לא את קובץ ה־JSON כולו.
   - **שם התיקייה** - אפשר להשאיר `SmplWise Arx backups`.
   - לא מדביקים API key, לא Redirect URI ולא "refresh token" - אין שדות כאלה ואין בהם צורך.
3. **שמירה**. היעד נשמר **כבוי** (זה תקין).
4. **בדיקת חיבור Google**. התוצאה הצפויה: "ההגדרות ב־Google תקינות. השלב הבא: 'חיבור חשבון Google'." אם מופיעה בעיה - הטבלה בסוף המדריך אומרת מה לתקן. הבדיקה לא יוצרת שום דבר ב־Drive.
5. **חיבור חשבון Google**. מופיעים קוד קצר (למשל `ABCD-EFGH`) וקישור.
6. בטלפון או במחשב: פותחים https://www.google.com/device › מקלידים את הקוד › **Next** › בוחרים את חשבון Google שהוספתם כ־Test user.
7. מופיע "Google hasn't verified this app" - זה צפוי במצב Testing › **Continue**.
8. במסך ההרשאות ("SmplWise Arx wants access to your Google Account") משאירים מסומנת את ההרשאה לקבצים שהאפליקציה יוצרת › **Continue** / **Allow**. אם תוריד את הסימון, Arx יסרב לחיבור ("Google לא אישר את ההרשאה המצומצמת").
9. בדף של Google יופיע שהמכשיר חובר; ב־Arx יופיע "החשבון חובר. אפשר להפעיל את היעד." (בתוך כמה שניות).
10. שוב **בדיקת חיבור Google** - כל השורות ירוקות, ובשורה של Google Drive API מופיעה כתובת החשבון שבו יישמרו העותקים.
11. מפעילים את המתג של היעד › **בדיקה** (כותבת קובץ קטן, קוראת, מוחקת) › **העלאה עכשיו**.
12. אימות: ב־https://drive.google.com מופיעה התיקייה `SmplWise Arx backups` ובה קובץ שמסתיים ב־`.zip.swxb`. בכרטיס "תרגיל שחזור" אפשר להריץ תרגיל מהעותק ב־Drive (לא משנה דבר במערכת).

### 9. אחרי שהכול עובד: יציאה ממצב Testing (מומלץ מאוד)
1. Google Auth Platform › **Audience** › **Publishing status** › **Publish app** › **Confirm**. הסטטוס יהיה **In production**.
   - עם ההרשאה `drive.file` בלבד ובלי לוגו, Google לא דורש תהליך אימות.
2. ב־Arx: **חיבור מחדש** פעם אחת (החיבור שנוצר במצב Testing עדיין יפוג אחרי 7 ימים).
3. **בדיקת חיבור Google** - בשורה "תוקף החיבור" כבר לא צריך לטפל.

אם לא מפרסמים: אחרי 7 ימים הגיבוי היומי ייכשל עם "החיבור ל־Google Drive פג או בוטל", ו"בדיקת חיבור Google" תסביר שזו תוצאת מצב Testing.

## מה "בדיקת חיבור Google" אומרת ומה עושים

| מה מופיע | הסיבה | התיקון |
|---|---|---|
| לא הוזן מזהה לקוח / סוד הלקוח | שדה ריק | שלב 6, ואז עריכת היעד ב־Arx |
| בשדה הסוד הודבק מזהה הלקוח | הערכים הוחלפו | הסוד מתחיל ב־`GOCSPX-`; המזהה מסתיים ב־`.apps.googleusercontent.com` |
| בסוד יש רווחים, מירכאות או סוגריים | הודבק קובץ JSON או רווח | מדביקים רק את ערך הסוד |
| אין חיבור לשרתי Google | אינטרנט / DNS / חומת אש | לוודא HTTPS יוצא מהמערכת |
| החיבור המאובטח נכשל (אימות התעודה) | כמעט תמיד שעון שגוי | לתקן את השעון של המחשב המארח |
| שעון המערכת מקדים/מאחר בכ־X דקות | אין סנכרון זמן | להפעיל NTP במחשב המארח |
| סוג הלקוח שגוי | נוצר Web application / Desktop app | שלב 6: לקוח חדש מסוג TVs and Limited Input devices |
| Google לא מכיר את מזהה הלקוח | נמחק / פרויקט אחר / הועתק חלקית | להעתיק שוב מ־Clients |
| מסך ההסכמה לא הוגדר | דילגתם על שלב 3 או 4 | שלבים 3-4 |
| הסוד לא תואם למזהה הלקוח | סוד של לקוח אחר או הועתק לא נכון | Clients › הלקוח › Add secret |
| ממתין לאישור + "Access blocked" בדפדפן | החשבון לא Test user | שלב 5 |
| Google ביטל את החיבור, נוצר לפני כ־7 ימים | מצב Testing | שלב 9 |
| Google ביטל את החיבור (מוקדם יותר) | הגישה הוסרה ב־myaccount.google.com, סיסמה שונתה | חיבור מחדש |
| Google Drive API לא הופעל | דילגתם על שלב 2 | שלב 2, לחכות כמה דקות, לבדוק שוב |
| נשארו רק X GB פנויים | Drive כמעט מלא | לפנות מקום או להקטין "מינימום פנוי" / מספר העותקים |
| התיקייה עדיין לא קיימת (מידע) | עוד לא הועלה דבר | תקין; נוצרת בבדיקה או בהעלאה הראשונה |

## דברים שכדאי לדעת
- **התיקייה**: Arx מוצא את התיקייה לפי השם. מותר להעביר אותה בתוך Drive; לא לשנות לה את השם (אחרת תיווצר חדשה). תיקייה שיצרתם בעצמכם באותו שם לא תשמש: Arx רואה רק מה שהוא יצר.
- **פרויקט או לקוח חדש** ב־Google: Arx לא יראה את התיקייה הישנה (ההרשאה צמודה ללקוח). העותקים הישנים נשארים ב־Drive.
- **ניתוק החשבון** ב־Arx מבטל את ההרשאה ב־Google, מוחק את האסימון ומכבה את היעד. העותקים נשארים ב־Drive. אפשר לבטל גם מצד Google: https://myaccount.google.com › Security › Your connections to third-party apps & services.
- **סודות**: Client secret ואסימון הרענון נשמרים מוצפנים במפתח ההתקנה, לא מוצגים, לא נרשמים ביומן ולא נכללים בגיבוי פרויקט.
- **מכסות**: אם Google מגביל את קצב הבקשות, הגיבוי הבא ינסה שוב לבד.

## חזרה יבשה (בלי Google אמיתי)
`python scripts/gdrive_connect_dry_run.py` מריץ את כל המסלול הזה מול שרת Google מדומה ומדפיס מה "בדיקת חיבור Google" אומרת בכל שלב, כולל שתי הטעויות הנפוצות ותפוגת 7 הימים.
