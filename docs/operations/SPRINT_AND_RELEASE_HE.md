# פיילוט מותנה של שבעה ימים

הספרינט מתחיל רק אחרי שקיימים גישת הרצה מקומית, קוד legacy אמיתי, מעבדה בטוחה ואישורים בשם.
מספרי הימים הם יעדי סידור, לא משכי זמן חוזיים. התקציב שהוזכר בדיון קודם היה תקרה להמחשה, לא
הרשאת הוצאה.

| יום | שער / ראייה |
|---|---|
| 1 | ביקורת legacy, בסיס עיצוב, עקבות מוגבלים והחלטות API |
| 2 | הוכחת זמן ניגון, Live מאומת, מודל קומה והעלאה |
| 3 | סיכת מצלמה ← Live אמיתי ← חיפוש הקלטות ו-seek במצלמה בודדת |
| 4 | קטלוג/מצב HA מורשה ← מפה ← פעולה מאושרת אחת בסיכון נמוך |
| 5 | אירועים בסיסיים, התחברות מחדש, שחזור וזרימה מקצה לקצה |
| 6 | תיקון כשלים; סקירת נייד/RTL/עיצוב. הקפאת פיצ'רים חדשים |
| 7 | ראיית קבלה ו-Go/No-Go אנושי לפריסת ייחוס אחת |

גבולות אבטחה הם P0 גם בפיילוט. סנכרון רב-מצלמות מתקדם, AI, תיקים מלאים והיקף ארגוני לא דוחקים
את שימושיות המפה הבסיסית או את זמן ההקלטה הנכון. אם T006 נכשל, יש לשמר את נתיב הניגון של
ה-legacy או לדחות את שחרור הניגון; אין להסוות הקלטה שגויה עם חותמת זמן ב-UI.

דוח שחרור: תג/commit, מטריצת סביבה, היקף, בדיקות עם ראיות, פעולות פיזיות מותרות, מדידות
משאבים, מגבלות ידועות, גיבויים/שחזור, חזרה לאחור (rollback), מאשר/תאריך. אין בדיקת mock עוברת
שמוכיחה תאימות להתקן אמיתי. כשלי P0/P1 בנתיבים קריטיים ששוחררו חוסמים שחרור.

## תיקון שער השחרור של v1.1
PILOT כולל סנכרון זהות HA, קבוצות/תפקידים מובנים בהיקף וזרימת העבודה הלא-מנהלית. T076–T081/T083
חייבים לספק קבלה לפני T035/T036. V1 דורש בנוסף את T082, ניהול מואצל (delegated administration).
לשמור על שערי אבטחה/זמן/ניגון/rollback המקוריים. אין לדחות את כל ניהול המשתמשים ל-T055 המלא
של RBAC.
