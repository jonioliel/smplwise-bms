- ראיות: העותק הגולמי נשמר רק ב-`private-evidence/lab-2540/<בדיקה>/`. למאגר נכנסות רק טבלאות מושחרות (תוצאה, מספרים, קודים),
  בהערת השינוי של שורת הקבלה (הצעה: `docs/changes/LAB-ACCEPTANCE-2540.md`). אין תמונות ממצלמות אמיתיות במאגר.
- תוצאה לכל בדיקה: PASS / FAIL / BLOCKED / NOT_RUN. בדיקה שלא רצה אינה PASS.
- לפני כל פגישה רושמים את הגרסה המותקנת (גרסת התוסף, קומיט התג, `#addon`, הגשר). הבדיקות בודקות את מה שמותקן, לא את מה שבענף.

## 7. בדיקה 5 - מה go2rtc שולח למקור `ffmpeg:` שנכשל (VIDEO-SECFIX-2520 שאלה 3)

- **מה בודקים:** האם הטקסט הגולמי של שגיאת go2rtc עבור מקור `ffmpeg:` (ברירת המחדל של Provision-ISR) כולל כתובת URL מלאה עם שם
  משתמש וסיסמה של המקליט. הדליפה לצופה כבר סגורה ב-2.52 (`sanitize_upstream_frame`); הבדיקה מחליטה אם כדאי להחליף את סיסמת
  המקליט.
- **אישור:** קריאה בלבד. `מאשר: בדיקת שגיאת go2rtc (קריאה בלבד)`.
- **צעדים:**
  1. קריאה בלבד: האם יש במעבדה זרם `smplwise_` עם מקור `ffmpeg:`. אם אין - התוצאה `N/A` (נרשם), ועוצרים כאן.
  2. גורמים לכישלון בדרך רגילה של משתמש: הבעלים פותח ב-Arx הקלטה של המצלמה הזו בשעה שמחוץ לתקופת השמירה של המקליט (קריאה רגילה,
     בלי כתיבה למקליט). **לא** יוצרים זרם עם כתובת שגויה בכוונה - זו כתיבה להגדרות go2rtc.
  3. באותו זמן, היומן של go2rtc (קריאה בלבד) נשמר ישר לקובץ פרטי בלי להציג אותו; סקריפט מקומי מסווג (נספח A.4).
  4. במסך של Arx: הנגן מציג רק "Stream error: upstream_error" (אין טקסט גולמי).
- **מעבר / החלטה:** הבדיקה עוברת אם הסיווג הושלם והנגן מציג רק `upstream_error`. ההחלטה: אם בטקסט הגולמי יש URL עם פרטי כניסה -
  המלצה להחליף את סיסמת המקליט (כתיבה ל-NVR, אישור נפרד, לא כאן) ולבדוק מי יכול לקרוא את היומן ואת ה-API של go2rtc.
- **ראיות:** רק הסיווג: "יש פרטי כניסה: כן / לא", "יש כתובת: כן / לא", "סוג השגיאה". הטקסט עצמו נשאר פרטי.

## 8. בדיקה 6 - אישור בטלפון וקוד אזעקה, בטלפון אמיתי (MFA-T095-REST-2530 שאלה 4)

- **מה בודקים:** (א) אישור בטלפון עם התאמת מספר (`security.push_approval`); (ב) קוד האזעקה האישי כאימות נוסף לפעולת אזעקה אחת
  (`security.step_up_alarm_pin`). שניהם כבויים כברירת מחדל; שניהם דורשים שהאימות הנוסף (`security.step_up`) דלוק.
- **אישור: כתיבה.** הבעלים מדליק בעצמו (הגדרות › משתמשים והרשאות › גורם שני, כרטיס "אישור לפני שינויים רגישים"):
  `מאשר: הדלקת אישור בטלפון וקוד אזעקה לבדיקה`. פעולת האזעקה (נטרול) - אישור נפרד שמציין את המחיצה, והבעלים ליד הלוח:
  `מאשר: נטרול מחיצה <כינוי> לבדיקה`. בחירת הפעולה הרגישה לבדיקה (א) - הגדרה תמימה שמשנים ומחזירים - באישור משלה.
- **צעדים:**
  1. לפני: רישום הערכים הנוכחיים של שלושת המתגים; הטלפון של הבעלים עם אפליקציית Android ומפתח טלפון פעיל.
  2. (א) מהמחשב: פעולה רגישה תמימה → 403 `step_up_required` → "אישור בטלפון". הטלפון מקבל הודעה **בלי** המספר ובלי הפעולה.
     הבעלים מקליד בטלפון את שתי הספרות שעל המחשב, מאשר בטביעת אצבע / פנים. המחשב ממשיך; הפעולה מתבצעת פעם אחת.

## Appendix A - technical (English)

Nothing here was run. Lab access uses the owner's long-lived token and SSH key from `secrets/lab.env`, read by the scripts and never
printed. No password login, no HA user creation.

### A.1 Session record

Per session, in `private-evidence/lab-2540/session-<date>.md`: installed add-on version, tag commit, `#addon` commit, bridge
`active_version`, HA Core version, WisKey label, who was present, the approval strings as typed, start / end times. The repository
note gets the version line and the result table only.

### A.2 V6 scanner (local, PC)

Input: the exported `arx-logs-<stamp>.json` in `private-evidence/lab-2540/v6/`. Run Python with `-I`, script kept outside that folder.
Rules (count only, never print a match): IPv4 (excluding 127.0.0.1 and 0.0.0.0), IPv6 (non-loopback), MAC (`xx:xx:xx:xx:xx:xx` /
`-`), URL userinfo (`[a-z]+://[^/\s:@]+:[^/\s@]+@`), `Bearer `, JWT shape (`eyJ[\w-]+\.[\w-]+\.`), e-mail, phone (Israeli and E.164),
plus exact-value matches for every value in `secrets/lab.env` and the private serial / MAC lists. Output: `rule -> count`, the
file's `redaction.total`, `records` count. Pass: every count 0.

### A.3 V7 walker

Playwright on the runner (slot B, not during a gate) or on the owner's PC. Fresh browser context; the owner signs in. Route handler:
abort every request whose method is not GET / HEAD / OPTIONS except the sign-in / session refresh endpoints; count aborts per screen.
Language for the session only (open question 2). Screen list: the four primary modes, every Settings tab, the home interface,
WisKey status / relay map / visits, tickets, calendars, notice board, recordings, map; about 40 routes, fixed in the script before
the session. Checks per screen and size: visible text nodes matching `[֐-׿]` outside an allow-list of data fields; raw key
pattern (`^[a-z0-9_]+(\.[a-z0-9_]+)+$` as visible text); `scrollWidth > clientWidth` on the document; console errors. Output: a JSON
table of counts; screenshots stay private.

### A.4 go2rtc read (check 5)

Only `smplwise_` streams. Per-stream read (`GET /api/streams?src=<smplwise_name>`), never the full listing of foreign streams' sources.
The go2rtc add-on log is read through the HA Supervisor API with the owner's token, written straight to a private file, and classified
by a local script: contains URL userinfo (yes / no), contains a non-loopback address (yes / no), the error class (`auth`, `timeout`,
`refused`, other). Arx side: the player's message and the playback socket's `LiveDiag` warning (already sanitized). No stream is
created, changed or deleted.

### A.5 Home controls and MFA (checks 4, 6)

Read-only evidence: HA logbook for the chosen entities (owner's token, GET), Arx audit rows filtered by action (`ha.action` for
the entity commands of the control routes in `routers/ha.py` - confirm at the session which rows the home interface's room / house
off writes; `auth.push_approval.*`, `auth.step_up.ok`). Entities and partitions are recorded by alias; the alias -> entity id map stays private.
MFA settings keys: `security.step_up`, `security.push_approval`, `security.step_up_alarm_pin` (all default off; the owner flips them
in the UI). Push approval routes: `POST auth/step-up/push`, `GET auth/push-approvals`, `POST auth/push-approvals/{id}/challenge`,
`POST auth/push-approvals/{id}/approve | deny`, `POST auth/step-up/verify {method: "push" | "alarm_pin"}`.
