# חיבור חשבון OpenAI לסקינים המרונדרים (AI) — הסבר לבעל המערכת

מסמך הסבר בעברית. מקור באנגלית: `smplwise_vms/DOCS.md` (הסעיף "AI-rendered floor skins") ו-`docs/changes/CR-006-PLAN-STUDIO-3D-VISUAL-LEVEL.md` §7d.
נכון ל-0.1.126. **המצב היום:** הרינדור ב-AI הוא יסודות בלבד (פרוסה 2a). שום תמונת קומה לא נשלחת לשום מקום; הדבר היחיד
שיכול לצאת הוא בדיקת חיבור של מנהל מערכת עם דוגמה סינתטית של 64×64. המשך הפיתוח (2b/2c) הושהה לפי החלטת בעל
המערכת ב-2026-09-29.

## 1. הדבר החשוב ביותר: מנוי ChatGPT ≠ חשבון API

- **ChatGPT (Plus / Pro / Team)** הוא מוצר צ'אט לבני אדם. המנוי שלו **לא כולל** גישה ל-API ולא נותן "קרדיט" ל-API.
- **OpenAI API Platform** (`https://platform.openai.com`) הוא שירות נפרד לתוכנות. הוא מחויב לפי שימוש (per image /
  per token), ודורש **מפתח API** ו**אמצעי תשלום או יתרה משולמת מראש** משלו.
- אפשר להיכנס ל-platform עם אותו משתמש (אימייל) של ChatGPT, אבל החיוב והמפתחות נפרדים לגמרי. לא ניתן "לקשר את
  חשבון ה-ChatGPT" למערכת; מה שמקשרים הוא **מפתח API**.

## 2. איך משיגים מפתח API (פעם אחת, ~10 דקות)

1. כניסה ל-`https://platform.openai.com` עם המשתמש שלך (או יצירת ארגון חדש אם נשאל).
2. **חיוב (Billing):** Settings ← Organization ← Billing ← הוספת אמצעי תשלום או טעינת יתרה (prepaid credits).
   בלי יתרה/אמצעי תשלום, בקשות התמונה נדחות (שגיאת 429 "insufficient_quota" או דומה) — זו לא תקלה במערכת.
   מומלץ להגדיר שם גם **תקרת הוצאה חודשית** (Usage limits) לביטחון, בנוסף לתקציב שהמערכת אוכפת בעצמה.
3. **מפתח:** Dashboard ← API keys ← "Create new secret key". תן לו שם (למשל `smplwise-skins`), והגבל אותו אם
   מוצע: הרשאה לתמונות בלבד / פרויקט ייעודי. המפתח מוצג **פעם אחת** (`sk-...`) — העתק אותו מיד.
4. אל תשלח את המפתח בצ'אט, במייל או במסמך. הוא נכנס רק להגדרות התוסף (סעיף 3). אם דלף — מוחקים אותו ב-API keys
   ויוצרים חדש.

## 3. איך מכניסים את המפתח למערכת

1. **Home Assistant ← הגדרות ← תוספים ← SMPLWISE VMS ← לשונית "הגדרות" (Configuration)** ← השדה
   `openai_api_key` ← הדבק את המפתח ← שמור ← **הפעל מחדש את התוסף**. המפתח נשמר רק בהגדרות התוסף (מוצפן על ידי
   ה-Supervisor), לא בבסיס הנתונים של המערכת, לא ביומנים ולא ברשומות הביקורת.
2. **במערכת ← הגדרות ← וידאו ומדיה ← "סקינים מרונדרים (AI)"** (מנהלי מערכת בלבד):
   - הכרטיס מציג "מפתח מוגדר: כן/לא" (לעולם לא את המפתח עצמו).
   - **אישור פרטיות** — כבוי כברירת מחדל. כל עוד הוא כבוי לא נשלח דבר, גם לא בדיקת חיבור. הכרטיס מפרט מילה
     במילה מה יכול לצאת (תמונת בקרה סכמטית שלנו בלי שמות; תמונת התוכנית המקורית רק אם תבחר זאת בשליחה) ומה לעולם
     לא יוצא (תמונות מצלמה, אנשים, שמות אזורים/ישויות, מצבי חיישנים, נתוני HA, כתובות).
   - **תקציב** — "רינדורים לקומה" (ברירת מחדל 4) ו"רינדורים בחודש" (ברירת מחדל 20; בדיקות חיבור נספרות, הן
     בקשות בתשלום).
   - **מודל** — ברירת מחדל `gpt-image-1.5`. ניתן לשינוי בהגדרות בלי קוד.
3. **"בדיקת חיבור לספק הרינדור"** — שולח דוגמה סינתטית אחת (פסי צבע ולוח שחמט, לא תוכנית) ומציג את תשובת הספק
   (סטטוס HTTP והתמונה שחזרה). נרשם בביקורת ונספר בתקציב החודשי. זו הדרך לוודא שהמפתח והחיוב תקינים — ולראות
   בחשבון OpenAI את העלות האמיתית לתמונה (המערכת מציגה רק הערכה מסומנת, מחירון לתמונה לא אומת).

## 4. כמה זה עולה (בקירוב, לא מחירון)

חיוב לפי תמונה/טוקנים בחשבון OpenAI. בדף המחירים של OpenAI (Images) מופיע מחיר לפי איכות וגודל; בפועל רינדור
קומה אחד = בקשת edit אחת עם תמונת בקרה אחת. ההערכה בכרטיס מסומנת "הערכה, לא אומת". הדרך היחידה לדעת בוודאות היא
בדיקת חיבור אחת ואז "Usage" בחשבון OpenAI. עם ברירות המחדל (4 לקומה, 20 בחודש) התקרה הטבעית היא עשרות תמונות
בחודש לכל היותר.

## 5. איך מבטלים

- מוחקים את `openai_api_key` מהגדרות התוסף ומפעילים מחדש ← "מפתח מוגדר: לא", שום דבר לא יכול להישלח.
- מכבים את אישור הפרטיות ← אותה תוצאה גם כשהמפתח קיים.
- מוחקים את המפתח גם בצד OpenAI (API keys ← Revoke) — כדי שגם גיבוי ישן של הגדרות התוסף לא יוכל להשתמש בו.

## 6. מה יקרה כשנחליט להמשיך (2b/2c — מושהה)

הצעת סט רינדורים לקומה (למשל "כל התאורה כבויה / דולקת"), דיאלוג שליחה שבו בוחרים מה יוצא, שמירת התוצאות לשימוש
חוזר, והרכבתן לתצוגת ה-3D וה-2D עם דעיכת נוכחות. עד אז אפשר להשאיר את הכרטיס כפי שהוא — הוא לא עושה כלום בלי
מפתח ואישור.
