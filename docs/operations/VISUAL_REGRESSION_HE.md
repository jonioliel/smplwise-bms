**סטטוס:** חבילות צילומי המסך רצות בכל קטע עבודה מקומית (0.1.10 … 0.1.28); הרצת CI עוד לא
מחווטת.

חבילות ה-fixture הן 129 בדיקות וחייבות לעבור לפני כל commit (`npx playwright test
tests/screenshots.spec.ts tests/screens.spec.ts` כאשר ה-backend של המפתח עצור, כך שה-UI לוקח
את נתיב הדמו). הבדיקות החיות (live specs) הן ראייה, לא שער: הן תלויות במה שהמעבדה מכילה במקרה
(הקלטות, אירועים, פריטים ממוקמים).

## אישור שינויים מכוונים

1. יש להריץ את חבילות ה-fixture; קובצי ה-PNG תחת `docs/evidence/T007` נוצרים מחדש במקום.
2. `git diff --stat docs/evidence/T007` מציג אילו מסכים השתנו. יש לפתוח את אלה ששינו זה לצד
   זה (`git difftool` או ה-IDE).
3. שינוי לא מכוון ← לתקן את הקוד ולהריץ מחדש. שינוי מכוון ← לעשות commit לקובצי ה-PNG החדשים
   באותו commit כמו הקוד, ולנקוב בשמות המסכים בגוף ה-commit (`sc06-plan-editor`,
   `sc20-storage`, …). קטע עבודה שרק מרענן ראייה משתמש ב-`git checkout -- docs/evidence/T007`
   כדי להשליך רעש.
4. הפניית העיצוב (`docs/design/`) היא הפוסקת (arbiter); צילום מסך שסוטה ממנה הוא פגם גם כאשר
   הבדיקה עוברת.

## הסתרת תוכן משתנה

- מסכי ה-fixture אינם מכילים וידאו חי: `sw-scene` מצייר סצנות סינתטיות, חותמות זמן קבועות
  ב-fixtures.
- צילומי מסך של ראיה חיה מכילים פריימי וידאו ושמות מעבדה ולכן לעולם אינם נכנסים למאגר. כאשר
  צילום מסך חי נדרש במסמך ציבורי, יש לטשטש את הפריים ולשנות שם למצלמה לפני ההעתקה מחוץ
  ל-`private-evidence/`.
- אם מסך חי חייב להיות מושווה אוטומטית בעתיד, יש למסך (mask) את `sw-live-player`,
  `[data-tl-preview]`, `.frame` ואת שבבי השעון (`page.screenshot({ mask: [...] })`).

## קישור משוב למסך / דרישה / commit

כל שורת ראייה ב-`management/tasks.json` עוקבת אחר `pre-evidence (<date>, <version>): <what> …
- private-evidence/<task>-live/*.png`. משוב הבעלים נרשם על כרטיס המשימה (או ב-`docs/changes/`)
עם: מזהה מסך (`sc..`), מזהה דרישה (`R..`), הגרסה שבה ניתן המשוב, וה-commit שענה עליו.
`python scripts/project_status.py --write` יוצר מחדש את הלוחות.
