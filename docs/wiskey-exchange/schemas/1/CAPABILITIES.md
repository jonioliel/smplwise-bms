# מסמכי יכולות (capabilities) — סכמה 1

טיוטת Arx, 04.10.2026. הסכמה: `capabilities.schema.json`. דוגמה: `examples/valid/capabilities.json`.
זו דרישה חדשה של Arx; ממתינה לאישור WisKey.

## 1. איפה

- בכל מסירה: תיקייה `capabilities/` עם:
  - `capabilities.json`: כל היכולות, בפורמט מכונה.
  - `<id>.he.md` לכל יכולת: טקסט קצר בעברית, עד עמוד אחד.
- כל הקבצים רשומים ב־`artifacts_sha256` של המניפסט, ו־Arx מאמת אותם לפני שהוא מציג משהו.

## 2. מה בכל יכולת

| שדה | מה לכתוב |
|---|---|
| `id` | מזהה יציב, למשל `intercom.door_open`. לא ממחזרים מזהה למשמעות אחרת |
| `name_he` | שם קצר |
| `description_he` | מה היכולת עושה, בשפה פשוטה, בלי קודים פנימיים |
| `kind` | `read_only` (רק מציג), `control` (משנה מצב תוכנה, בלי חומרה), `physical_action` (פותח, מחזיק, משחרר או מזיז משהו בעולם) |
| `physical_action` | רק לפעולה פיזית: מה קורה, אישור (`confirm` או `confirm_with_reason`, אין "בלי אישור"), ומתי מותר או אסור |
| `suggested_permission` | הרשאת Arx מוצעת. קיימת (למשל `access.release`) או חדשה. Arx RBAC מחליט |
| `suggested_roles` | תפקידי Arx מוצעים: `viewer`, `kiosk`, `operator`, `editor`, `site_admin`, `system_admin` |
| `suggested_screen` | `existing_template` עם `template_id`, או `new_screen`, או `no_screen`; ולמה |
| `data_read` / `data_written` | אילו נתונים נקראים ונכתבים. ליכולת `read_only` אין כתיבה |
| `when_unavailable_he` | מה המפעיל רואה כשהעמדה, האינטגרציה או היכולת לא זמינות. אף פעם לא ניסיון חוזר שקט של פעולה פיזית |
| `contract_changes` | `"none"`, או רשימה של שינויי חוזה, DTO או serialization שהיכולת צריכה |
| `doc_file` | `capabilities/<id>.he.md` |
| `since_version` | הגרסה הראשונה שבה היכולת קיימת |

- קטלוג תבניות המסך של Arx (`template_id`): `TO_BE_CONFIRMED`. Arx יפרסם אותו. עד אז אפשר לכתוב `new_screen` ולהסביר.

## 3. הכלל

- יכולת בלי מסמך: Arx מדווח עליה כ"לא נתמכת" ולא מציג אותה.
- מסמך אינו הוספה אוטומטית. Arx סוקר כל יכולת עם הבעלים לפני שמסך נוסף.
- יכולת לא מוכרת לא פוסלת חבילה תואמת (`COMPAT.md` סעיף 4).

## 4. שלוש דרגות

| דרגה | מה קורה ב־Arx |
|---|---|
| תבנית קיימת (`existing_template`), לא פעולה פיזית חדשה | אחרי הסקירה היכולת מופיעה מושבתת. מנהל מערכת מפעיל אותה ומקצה הרשאה. עד אז היא לא פעילה לאף אחד |
| לא מוכרת (אין מסמך, או לא נסקרה) | "לא נתמכת". לא מוצגת |
| מסך חדש (`new_screen`) או פעולה פיזית | עבודת Arx ואישור הבעלים לפני כל תצוגה. פעולה פיזית רק בנתיב החתום, ואם היא דורשת שינוי חוזה, גם הסכמה מפורשת של שני הצדדים |

## 5. דוגמה לקובץ טקסט (`capabilities/intercom.door_open.he.md`)

```
# פתיחת דלת
מה זה עושה: פותח את הדלת של עמדה אחת לזמן הקצר שמוגדר בעמדה.
סוג: פעולה פיזית. דורש אישור לפני שליחה.
מתי לא עובד: העמדה לא מחוברת, או שהתוצאה לא ודאית. אז מוצג "לא ידוע", ואין שליחה חוזרת.
הרשאה מוצעת: access.release. תפקידים: operator, site_admin, system_admin.
שינוי חוזה: אין.
```
