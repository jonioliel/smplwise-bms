# סטודיו התוכנית (Plan Studio) — מסמך תכנון

**סטטוס:** תכנון מאושר עקרונית על ידי הבעלים (22–23.9.2026: גישה א, סדר השלבים יסודות → ספרייה → זיהוי → 3D, השם
"סטודיו התוכנית"). מסמך זה הוא הבסיס לתוכנית המימוש ולכרטיסי המשימות; הוא מרחיב את פרקים 10–12 ו־17–18 של
`MASTER_SPEC_HE.md` ואת T059. במקום שבו הוא חורג מהמפרט (עצמים, תאורה ומעגלים, גבהים ומפלסים, 3D, ייצוא) הוא
בקשת שינוי שאושרה, ותירשם ב־`DECISIONS.md` עם אישור המסמך.

**המטרה במשפט אחד:** לטעון תוכנית (PDF/תמונה/DXF), לכייל פעם אחת, לצייר או לזהות אוטומטית קירות ופתחים, להציב
עצמים מספרייה עשירה, להגדיר גבהים ומפלסים, לראות את כל זה בתלת־ממד עם המצלמות והישויות החיות — ולייצא הכול.

## 1. תחום ומה מחוץ לתחום

**בתחום**
- כיול קנה מידה (שתי נקודות + מרחק; DXF אוטומטי; רמז אוטומטי מרוחב דלת).
- מסמך גאומטריה קנוני v2 לכל גרסת תוכנית, עם טיוטה/פרסום/diff/rollback/אודיט.
- כלי ציור: קירות, פתחים (דלת/חלון/מעבר), עצמים מספרייה, מדידה, מפלסים, מחברים, תאורה ומעגלים.
- ספריית עצמים מובנית (JSON) + פריטים מותאמים + חיפוש בעברית/אנגלית + כלי "מערך".
- זיהוי אוטומטי מקומי: קירות, דלתות, חלונות (רסטר) ומיפוי שכבות/בלוקים (DXF) עם מסך אישור.
- תצוגת 3D סכמטית עם המצלמות, הישויות והמצבים החיים, מסונכרנת עם ה־2D; אחר כך רמה ריאליסטית וסיור בגובה עין.
- ייצוא: JSON קנוני, SVG/PNG, חבילת תוכנית (ZIP חתום), DXF, glTF/OBJ; ייבוא: JSON, DXF, חבילה.

**מחוץ לתחום (במפורש)**
- ניתוח AI חיצוני של תוכניות (T060/T061): נשאר להחלטה עתידית; המסמך שומר לו נקודת חיבור (סעיף 9.5).
- BIM/IFC מלא, חישובי חשמל נורמטיביים (עומסים לפי תקן), סימולציית תאורה (lux).
- DWG (ממירים ל־DXF מחוץ למערכת, כמו היום).
- עריכה ישירה בתלת־ממד (גרירת עצמים ב־3D) — לא בשלבים 1–5; אפשרית אחרי שלב 6.

## 2. עקרונות מחייבים (מהמפרט הראשי)

1. **קואורדינטות 0–1** ביחס לתמונת הגרסה, ראשית שמאל־למעלה; זווית: 0° = למעלה, עם כיוון השעון (כמו העוגנים).
   Zoom ומיקום מסך אינם חלק מהגאומטריה; RTL לא משקף את המפה.
2. **מטרים רק אחרי כיול.** סטטוס הכיול (`measured` / `estimated` / `missing`) גלוי תמיד; בלי כיול אין מספרים במטרים,
   רק יחסים. שינוי כיול לא מזיז אף עצם — הוא משנה רק את התרגום למטרים.
3. **שום דבר אוטומטי לא מתפרסם.** זיהוי מייצר מועמדים עם ציון ביטחון ומקור (`auto`); אדם מקבל/דוחה/עורך; רק
   פרסום יוצר גרסה.
4. **רינדור דטרמיניסטי:** אותו JSON + אותה גרסת tokens → אותה תמונה (2D) ואותו גרף סצנה (3D). הסגנון (עובי קיר,
   קווי דלת, צבעים) מגיע מ־design tokens ולא מהמסמך.
5. **המקור לעולם לא משתנה.** קובץ התוכנית, תמונת הגרסה וה־hash שלהם נשמרים; כל גרסת גאומטריה מצביעה עליהם.
6. **טיוטה/פרסום/diff/rollback/אודיט** — כמו גרסאות תוכנית היום (T038), עם נעילה אופטימית (`revision`).
7. **הרשאות VMS** (לא HA): `map.read` צפייה (כולל 3D וייצוא תמונה), `map.edit` עריכה וכיול, `map.publish` פרסום
   ו־rollback, `map.import` ייבוא DXF/חבילה, הרשאה חדשה `catalog.manage` לניהול הספרייה.

## 3. ארכיטקטורה

```text
                        ┌────────────────────────────────────────────────────────┐
  PDF / תמונה / DXF ──► │ plan_assets + plan_versions (קיים)  scale_m_per_px      │
                        └───────────────┬────────────────────────────────────────┘
                                        │ תמונת גרסה (רקע)              ▲ כיול (חדש)
                                        ▼                                │
   זיהוי מקומי (חדש)   ┌────────────────────────────────┐   ספריית עצמים (חדש)
   plan_detect.py ───► │ plan_geometry  (מסמך v2, חדש)  │ ◄── catalog/objects.json + catalog_items
   plan_dxf_map.py     │ טיוטה ⇄ פרסום ⇄ rollback        │
                        └──────┬──────────────┬──────────┘
                               │              │
                 GET /floors/{id}/map (קיים, + geometry)      ייצוא (חדש): SVG/PNG, DXF, חבילה, JSON
                               │
        ┌──────────────────────┴───────────────────────┐
        ▼                                              ▼
  sw-plan-canvas (SVG, קיים + שכבות חדשות)       sw-plan-3d (three.js, chunk נטען לפי דרישה)
  explore-plan-editor (כלים חדשים)                בנאי סצנה דטרמיניסטי + מצבים חיים
```

**Backend (Python, בתוך ה־add-on):**
- `services/plan_geometry.py` — מודל v2, ולידציה, canonical JSON, diff, מיזוג מועמדים, המרות מטר↔0–1.
- `services/plan_detect.py` — זיהוי רסטר (קירות/דלתות/חלונות) על בסיס `plan_stylize`/`plan_zones` הקיימים.
- `services/plan_dxf_map.py` — מיפוי שכבות/בלוקים של DXF לקירות/פתחים/עצמים (על `plan_dxf.py` הקיים).
- `services/plan_catalog.py` — טעינת הספרייה המובנית, פריטים מותאמים, חיפוש, ייבוא/ייצוא.
- `services/plan_export.py` — SVG/PNG דטרמיניסטי, DXF (ezdxf), חבילת תוכנית (על `bundle.py`/`signing.py`).
- `routers/plan_geometry.py`, `routers/plan_catalog.py` — ה־API (סעיף 5).
- מיגרציות: `0018_plan_geometry.sql`, `0019_catalog_items.sql`, `0020_zone_levels.sql` (שלבים 1–2), `0021_anchor_tilt.sql` (שלב 4, שדה `tilt_deg` לעוגן מצלמה).

**Frontend (Lit/TypeScript):**
- `api/geometry.ts`, `api/catalog.ts` — טיפוסים וקריאות.
- `map/geometry-render.ts` — רינדור SVG של המסמך (קירות, פתחים, עצמים, מחברים, תוויות) לתוך `sw-plan-canvas`.
- `map/geometry-tools.ts` — מצבי הכלים (קיר, פתח, עצם, מדידה, כיול) והצמדות.
- `screens/explore-plan-editor.ts` — הרחבה: פאנל ספרייה, פאנל מאפיינים, מתג מפלס, פאנל מעגלים, זיהוי ואישור.
- `map3d/` — `sw-plan-3d.ts` (רכיב), `scene-builder.ts` (JSON → גרף סצנה), `materials.ts`, `controls.ts`;
  נטען ב־`import()` דינמי כדי ששאר הצרור לא יגדל.

## 4. מודל הנתונים

### 4.1 טבלאות

**`plan_geometry`** (מיגרציה 0018) — גרסאות המסמך, אחת פעילה כטיוטה ואחת מפורסמת לכל גרסת תוכנית.

| עמודה | סוג | הערה |
|---|---|---|
| id | TEXT PK (16 hex) | |
| plan_version_id | TEXT FK → plan_versions | |
| floor_id | TEXT FK → floors | לנוחות שאילתות |
| status | TEXT | `draft` / `published` / `archived` |
| revision | INTEGER | נעילה אופטימית של הטיוטה |
| doc_json | TEXT | המסמך הקנוני (סעיף 4.2) |
| doc_hash | TEXT | SHA-256 של ה־canonical JSON |
| created_by / created_at, published_by / published_at, archived_at | | כמו `plan_versions` |

כללים: לכל `plan_version_id` יש לכל היותר טיוטה אחת; פרסום מארכב את המפורסמת הקודמת ומעביר את הטיוטה ל־published
(ויוצר טיוטה חדשה כהעתק); rollback מפרסם מחדש גרסה ארכיונית כגרסה חדשה (ההיסטוריה לעולם לא נמחקת).

**`catalog_items`** (מיגרציה 0019) — פריטים מותאמים של המתקן (הספרייה המובנית היא קובץ, לא טבלה).

| עמודה | הערה |
|---|---|
| id, category, name_he, name_en, tags_json, shape, size_w_m, size_d_m, size_h_m, params_json, icon_svg, color_token, role, based_on (id של פריט מובנה, אופציונלי), revision, created_by/at, updated_at, deleted_at | |

**`spatial_zones`** (מיגרציה 0020) — נוספים `level_id TEXT NULL` (מזהה מפלס מתוך המסמך המפורסם של אותה גרסה) ו־
`ceiling_height_m REAL NULL` (עוקף את ברירת המחדל של המפלס). החדרים נשארים מקור האמת לחיפוש, אירועים ו־HA Areas.

**`plan_versions`** — `scale_m_per_px` הופך לניתן לעדכון דרך endpoint הכיול (סעיף 5); נוסף `calibration_json`
(נקודות הכיול, השיטה, השארית) כדי שאפשר יהיה לבדוק ולשחזר.

### 4.2 המסמך הקנוני v2 (`schema_version: "2.0"`)

בנוי כהרחבה של v1 (`contracts/schemas/plan_geometry.v1.schema.json`): כל שדה של v1 נשמר; חדשים מסומנים ★.
הסכימה החדשה נשמרת כ־`contracts/schemas/plan_geometry.v2.schema.json`; הסכימה הישנה `plan.schema.json` (פרומפט
ה־AI) מוצאת משימוש ומוחלפת בהפניה ל־v2 (סעיף 9.5) — פותר את כפילות הסכימות.

```text
source        { asset_sha256, page, source_dimensions{w,h}, version_dimensions{w,h}, transform_to_original }
calibration   { status: measured|estimated|missing, scale_m_per_px, method: two_point|dxf_units|door_width|manual,
                points: [{a:{x,y}, b:{x,y}, metres}], residual_pct, reason }
levels ★      [{ id, name, elevation_m, ceiling_height_m, is_default }]          — לפחות אחד; ברירת מחדל 0 / 2.8
walls         [{ id, level_id★, points: [{x,y}…] (≥2), thickness_m★, height_m★ (ברירת מחדל = תקרת המפלס),
                base_z_m★ (0), kind★: exterior|interior|partition|railing|low, provenance: manual|auto|imported,
                confidence (0–1, רק ל־auto), locked★ }]
openings ★    [{ id, wall_id, t (0–1 לאורך הקיר), kind: door|window|passage, width_m, height_m, sill_m,
                swing: left|right|double|sliding|none, hinge: start|end, entity_id (HA lock/door/binary_sensor),
                provenance, confidence }]                                          — מחליף את `doors`/`windows` של v1
rooms         [{ id (= spatial_zones.id), level_id, ceiling_height_m }]           — הפניה בלבד; הפוליגון ב־spatial_zones
objects ★     [{ id, level_id, catalog_id, custom_item_id, name, pose:{x,y,rotation_deg,z_m}, size:{w_m,d_m,h_m},
                params:{…לפי הפריט}, entity_ids:[…], circuit_id, group_id, flip, locked, provenance, confidence }]
circuits ★    [{ id, name, switch_entity_id, panel_object_id, planning:{rated_w, breaker_a, phase, notes} }]
connectors    [{ id, kind: stairs|ramp|elevator|tribune|ladder, from_level_id, to_level_id, floor_ids:[…],
                footprint: [{x,y}…], width_m, steps, direction_deg, object_id (כשנוצר מעצם) }]
labels        [{ id, text, position:{x,y}, level_id, size }]
uncertain_regions [{ id, polygon, reason }]
groups ★      [{ id, name, object_ids:[…] }]                                       — למערכים ולבחירה מהירה
meta          { generator, tokens_version, detector_version, created_at }
```

**כללי ולידציה (מורחבים מ־v1):** גבולות 0–1; פוליגונים סגורים ללא חיתוך עצמי; מזהים ייחודיים בכל האוספים; קיר
עם ≥2 נקודות ולא באורך אפס; `opening.t` בטווח והפתח כולו בתוך אורך הקיר (`width_m` ≤ אורך הקיר במטרים כשמכויל);
`level_id` קיים; `elevation_m` ייחודי לכל מפלס; מידות חיוביות; `circuit.switch_entity_id` מפנה לישות HA מסונכרנת
(אזהרה, לא שגיאה, כשהישות נעלמה); `connector.from/to` מפלסים שונים; מספר עצמים ≤ 5,000 וקירות ≤ 2,000 לתוכנית
(מכסה, לא מגבלת עיצוב). תוצאה חלקית נשמרת כטיוטה עם דוח שגיאות — לעולם לא מתפרסמת.

**המרות:** `metres_per_norm_x = scale_m_per_px × version_w_px`, ובדומה ל־y. מידות העצמים נשמרות במטרים; טביעת הרגל
ב־0–1 מחושבת בזמן רינדור. בלי כיול: הרינדור משתמש ב"קנה מידה משוער" (סעיף 6.3) ומסמן את כל המספרים כמשוערים.

### 4.3 ספריית העצמים

קובץ `smplwise_vms/backend/smplwise/catalog/objects.json` (נשלח עם ה־add-on, גרסה משלו) + `catalog_items` (מותאמים).

```text
item { id, category, names:{he,en}, tags:[…he/en], role: furniture|light|electrical|safety|medical|sport|
       structure|circulation|security|outdoor|sanitary|office|kitchen, shape: box|cylinder|extruded_polygon|
       stepped|composite, size:{w_m,d_m,h_m}, z_m (גובה מהרצפה, למשל מנורת תקרה = תקרה − 0.3),
       params_schema:{…}, icon (SVG סמלי 2D), color_token, mesh (ל־composite: רשימת קופסאות/גלילים יחסיים) }
```

קטגוריות ופריטים לדוגמה (יעד: ~150 בגרסה הראשונה, כולם ניתנים לעריכה כ"מבוסס על"):
- **מבנה:** עמוד עגול/מרובע, קורה, מעקה, מחיצה נמוכה, דלפק.
- **תנועה:** מדרגות ישרות/עם פודסט, רמפה, מעלית, סולם, טריבונה (מדורגת, פרמטרים: שורות, גובה ורוחב מדרגה).
- **ישיבה/שולחנות:** כיסא, כורסה, ספה, ספסל, שרפרף, שולחן משרדי/ישיבות/אוכל, עמדת קבלה, דלפק.
- **אחסון:** ארון, מדף, לוקר, כספת, מקרר, ארון שרתים.
- **תאורה:** מנורת תקרה, ספוט, פס לד, פלואורסנט, תאורת חירום, פרוז׳קטור, עמוד תאורה (חוץ).
- **חשמל:** לוח חשמל, שקע, מפסק, גנרטור, UPS.
- **בטיחות:** מטף, הידרנט, גלאי עשן, שלט יציאה, AED, נקודת התקהלות.
- **רפואה:** מיטת אשפוז, אלונקה, עמדת אחיות, מוניטור, עמוד עירוי, ארון תרופות, כיסא גלגלים, מכשיר רנטגן נייד.
- **ספורט:** שער כדורגל/כדוריד, סל, רשת כדורעף, מזרן, מתקן כושר, ספסל שחקנים.
- **משרד/מטבח/סניטרי:** מדפסת, לוח, מקרן, מקרר, תנור, כיור, אסלה, מקלחת.
- **אבטחה:** עמדת דלת (אינטרקום), מחסום, קרוסלה, שער, עמדת שומר, קורא כרטיסים (מצלמות נשארות עוגנים).
- **חוץ:** עץ, שיח, ספסל, חניה, פח, גדר, שער.

**חיפוש:** בצד הלקוח, על השמות והתגיות (עברית/אנגלית, מילים נרדפות: "טריבונה/יציע/bleachers"), תוצאות תוך כדי
הקלדה, קטגוריות כצ׳יפים, "לאחרונה" ו"מועדפים" לכל דפדפן. **פריט מותאם:** מהעורך ("צור פריט מזה"), שם, מידות, צורה,
סמל (בחירה מסמלים קיימים או SVG משלך), קטגוריה; ייצוא/ייבוא הספרייה המותאמת כ־JSON.

## 5. API (`/api/v1`)

| נתיב | מה | הרשאה |
|---|---|---|
| `GET /floors/{id}/map` (קיים) | מקבל שדה `geometry` (המסמך המפורסם; `?draft=true` — הטיוטה) ו־`catalog_revision` | map.read |
| `GET /plan-versions/{id}/geometry?draft=true` | המסמך + `revision` + `status` + דוח ולידציה | map.read |
| `PUT /plan-versions/{id}/geometry` | שמירת טיוטה (autosave). גוף: `{doc, base_revision}`; 409 `stale_revision` | map.edit |
| `POST …/geometry/publish` | ולידציה מלאה → published; `{summary}` של ה־diff; אודיט `geometry.publish` | map.publish |
| `GET …/geometry/diff?from=&to=` | diff מובנה (נוספו/הוסרו/הוזזו לפי אוסף) | map.read |
| `GET …/geometry/versions` / `POST …/geometry/rollback` | היסטוריה / rollback; אודיט `geometry.rollback` | map.read / map.publish |
| `PATCH /plan-versions/{id}/calibration` | `{points:[{a,b,metres}], method}` → `scale_m_per_px`, `status`, `residual_pct`; אודיט `plan.calibrate` | map.edit |
| `POST /plan-versions/{id}/detect` | `{targets:[walls,openings,rooms], strength, level_id}` → מועמדים (סינכרוני, timeout 60 שנ׳) | map.edit |

## 6. כיול

### 6.1 שתי נקודות + מרחק
בעורך: כלי "כיול" → לחיצה על שתי נקודות (עם הצמדה לקצות קירות אם קיימים) → הזנת המרחק במטרים → זוג נוסף אופציונלי.
עם זוג אחד: `scale = metres / distance_px`. עם ≥2 זוגות: ממוצע משוקלל לפי אורך, ו־`residual_pct` = הסטייה המרבית;
מעל 3% מוצגת אזהרה "הסריקה כנראה מעוותת — כייל שוב או הוסף זוג". סטטוס: `measured`.

### 6.2 DXF
`meters_per_px` מיחידות השרטוט (קיים) → `measured`, שיטה `dxf_units`; אפשר לעקוף ידנית.

### 6.3 רמז אוטומטי לרסטר
אחרי זיהוי דלתות (סעיף 9): חציון רוחב הדלתות הפנימיות ≈ 0.9 מ׳ → `estimated`, שיטה `door_width`, עם "משוער" בכל
מקום שמוצגים מטרים. בלי דלתות: `missing`, והרינדור משתמש בעובי קיר יחסי (0.6% מרוחב התוכנית) רק כדי לצייר.

### 6.4 מה קורה כשמכיילים מחדש
שום עצם לא זז (0–1). מידות במטרים של עצמים שכבר הוצבו נשארות — טביעת הרגל שלהם על המפה משתנה בהתאם; המערכת מציגה
לפני האישור "N עצמים ישנו את גודלם על המפה" ומאפשרת "המר מידות" (לשמור את טביעת הרגל ולשנות את המטרים) לכל עצם.

## 7. העורך (2D)

**כלים (מצטרפים ל־select / camera / lights / entity / zones / layers הקיימים):**

| כלי | אינטראקציה |
|---|---|
| קיר | לחיצה-לחיצה לפוליליין; Shift = חופשי, ברירת מחדל הצמדה ל־0/45/90°, לקצוות קירות ולרשת (ברירת מחדל 10 ס"מ כשמכויל); Enter מסיים, Esc מבטל, Backspace מוחק נקודה אחרונה; עובי/גובה/סוג בפאנל |
| פתח | לחיצה על קיר → דלת (0.9×2.1) / חלון (1.2×1.2, סף 0.9) / מעבר; גרירה לאורך הקיר; כיוון פתיחה בלחיצה על החץ |
| עצם | פאנל ספרייה (חיפוש) → לחיצה להצבה (או גרירה); ידיות: סיבוב, מתיחה (שומרת יחס ב־Shift); Alt+גרירה = שכפול; מקשי חצים = הזזה עדינה |
| מערך | בחירת עצם → "מערך": שורות × עמודות, רווח, כיוון; יוצר קבוצה (`groups`) — 6 שורות של 12 כיסאות בלחיצה |

| מעגלים | פאנל: מעגל חדש → בחירת ישות מפסק ב־HA → לחיצה על מנורות מצרפת/מסירה; סכום הספק לפי מעגל; צבע מעגל על המפה |
| זיהוי | "זהה אוטומטית" → מועמדים בשכבה נפרדת (מקווקו, כחול) עם ציון → קבל הכול / קבל לפי סוג / לחיצה על מועמד |

autosave 2 שניות אחרי שינוי (טיוטה), פרסום עם diff (קיים), קיצורי מקלדת מתועדים בפאנל "?", תצוגת RTL של הפקדים
בלבד. **טלפון:** צפייה מלאה, הצבה/הזזה של עצמים בודדים; ציור קירות ומערכים בדסקטופ בלבד (מוצג בהודעה, לא נכשל בשקט).

**רינדור 2D (`geometry-render.ts`):** קירות כמסלולים ברוחב `thickness` (משתנה עם ה־zoom), פתחים "חותכים" את הקיר
(מסכה) ומצוירים לפי סוג (קשת דלת, קו כפול לחלון), עצמים כסמל בתוך טביעת רגל מסובבת, מנורות עם הילה כשהישות דולקת,
מחברים עם חץ כיוון ("↓ −1.2 מ׳"), תוויות. הסגנון מ־tokens; אותו קוד משמש ל־SVG בייצוא (השרת מריץ אותו כלוגיקה
מקבילה ב־Python — שני הרינדורים נבדקים זה מול זה על סט התוכניות).

## 8. מפלסים ומחברים

- לכל קומה מפלס ברירת מחדל (0 מ׳, תקרה 2.8 מ׳ — ניתן לשינוי). מפלס נוסף = שם + גובה רצפה + תקרה. חדר שייך למפלס
  (`spatial_zones.level_id`); עצם/קיר שייכים למפלס; ה־2D מציג לפי הסינון, ה־3D מציג הכול בגובה הנכון.
- **מחבר** מחבר שני מפלסים באותה קומה (מדרגות, רמפה, טריבונה) או שתי קומות (מדרגות/מעלית, `floor_ids`). טריבונה
  היא עצם (מדורג) שמסומן `connects_levels`; בפרסום נוצר ממנו connector אוטומטית. מדרגות בין קומות נשמרות בשתי
  הקומות עם אותו `id` ("קומה 0 ↔ קומה 1"), כדי ש־T064 (מסלול חוצה קומות) יוכל להשתמש בהן.
- ב־3D: לוח רצפה לכל מפלס בגובהו; קירות של מפלס נמוך מתחילים מ־`elevation_m`; הטריבונה יורדת בפועל למפלס התחתון.

## 9. זיהוי אוטומטי מקומי

### 9.1 רסטר — קירות (`plan_detect.walls`)
1. מסכת קירות מ־`plan_stylize` (Otsu → סגירה/פתיחה מורפולוגית) ב־1600 px.
2. דילול Zhang–Suen (numpy, איטרטיבי) → שלד ברוחב פיקסל.
3. מעקב קווים על השלד: צמתים (≥3 שכנים) וקצוות; כל ענף → פוליליין; Douglas–Peucker (קיים) → יישור ל־0/90° כשהסטייה
   ≤ 4° (`_orthogonalize` קיים) → מיזוג קטעים קו־ליניאריים ומחיקת קטעים < 0.25 מ׳ (או 0.5% מהרוחב כשאין כיול).
4. עובי: chamfer distance transform (שני מעברים) על מסכת הקירות; עובי הקטע = חציון 2×distance לאורכו; `kind`
   לפי עובי (חיצוני ≥ 1.6× החציון) ומיקום (נוגע במסגרת התוכנית → exterior).
5. ציון ביטחון: אורך, ישרות, עקביות עובי, השתלבות בפוליגון חדר מזוהה.

### 9.2 רסטר — דלתות
- **פער בקיר:** שני קטעים קו־ליניאריים עם פער 0.6–1.5 מ׳ (מכויל) או 1.5–4× עובי הקיר → מועמד `door`.
- **קשת פתיחה:** במסכת "דיו דק" (דיו פחות קירות): דגימת רבע מעגל ברדיוס = רוחב הפער סביב כל אחד משני קצוות הפער;
  ≥ 60% דיו לאורך הקשת → הדלת מאושרת עם `hinge` ו־`swing`; פער בלי קשת → `passage` (ביטחון נמוך יותר).
- דלת כפולה: שתי קשתות במראה על פער 1.5–2.4 מ׳.

### 9.3 רסטר — חלונות
לאורך כל קיר: פרופיל עובי (מה־distance transform) בצעדים של 5 ס"מ; קטע שבו העובי יורד מתחת ל־50% מחציון הקיר
לאורך 0.5–3 מ׳ ובמסכת הדיו הדק יש 2–3 קווים מקבילים → מועמד `window` (סף ברירת מחדל 0.9 מ׳, גובה 1.2 מ׳).

### 9.4 DXF (`plan_dxf_map`)
- שכבות: התאמה לשמות מקובלים (WALL, A-WALL, MUR, קיר → walls; DOOR, A-DOOR, דלת → openings; WIND, GLAZ, חלון;
  FURN, EQPM, ריהוט → objects; ROOM, AREA, חדר → rooms). מסך המיפוי מציג לכל שכבה: ספירת ישויות, דוגמה, וההצעה —
  אפשר לשנות.
- בלוקים (INSERT): שם הבלוק + מידות ה־bounding box → התאמה לפריט ספרייה לפי מילים (door → דלת; chair → כיסא; bed →
  מיטה) עם ברירת מחדל "עצם כללי (קופסה)" במידות הבלוק.
- קירות מקווים כפולים (שני קווים מקבילים במרחק 10–40 ס"מ) → קיר אחד עם עובי.
- כל התוצאות במטרים אמיתיים (היחידות ידועות) → `measured`.

### 9.5 המועמדים, האישור ונקודת החיבור ל־AI
- פורמט מועמד = עצם במסמך v2 עם `provenance: auto`, `confidence`, ו־`detector: {name, version, params}`.
- מסך האישור: שכבת מועמדים על המפה; לחיצה = קבל/דחה; "קבל הכול מעל 0.8"; עריכה לפני קבלה; "החלף אוטומטיים
  קודמים" (כמו `replace_auto` בחדרים). כל קבלה נרשמת באודיט עם הספירה.
- **AI (עתידי, T060):** מנתח חיצוני שיחזיר מסמך v2 עם `provenance: auto, detector: {name: "ai:<provider>"}`
  ייכנס לאותו מסך אישור בלי שינוי בממשק. ההסכמה, התקציב ומדיניות הפרטיות — לפי פרק 17; לא נבנה בשלבים 1–6.

### 9.6 ביצועים
כל השלבים ב־numpy ללא תלויות חדשות; יעד: תוכנית A3 סרוקה ב־1600 px → מועמדים תוך ≤ 15 שניות על ה־HA host (Intel
N100), timeout 60 שניות; הריצה סינכרונית עם מחוון התקדמות בלקוח.

## 10. תצוגת 3D

### 10.1 ספרייה ואריזה
`three` (MIT) דרך npm, בצרור נפרד (`manualChunks: three`) שנטען רק בלחיצה על "3D"; יעד ≤ 200 KB gzip ל־chunk.
בלי CDN, בלי טעינה בזמן ריצה — נשמר כלל ה־Ingress (URL יחסי). OrbitControls, GLTFExporter מ־`three/examples/jsm`.

### 10.2 בנאי הסצנה (דטרמיניסטי)
קלט: המסמך + מצבים חיים (ישויות, מצלמות) + tokens. פלט: גרף סצנה. הקצה ל־`x` (מזרח) = ציר x של התוכנית, `z` =
ציר y של התוכנית (למטה בתוכנית = +z), `y` = גובה; יחידות מטרים (בלי כיול: יחידת תוכנית עם הודעת "משוער").
- **רצפה:** לוח לכל מפלס בגובהו; חדרים כצבע רצפה עדין (מ־tokens); מחוץ לחדרים — צבע קנבס.
- **קירות:** extrusion של הפוליליין ברוחב `thickness_m` לגובה `height_m` מ־`base_z_m`; פתחים בלי CSG: הקיר מפוצל
  לאורך `t` ל־[לפני | פתח | אחרי], ובקטע הפתח נבנות קופסאות: דלת — משקוף מעל `height_m`; חלון — קיר עד `sill_m`
  ומעל `sill_m+height_m`; מעבר — כלום. הדלת עצמה: לוח דק בזווית פתיחה לפי מצב הישות (סגור/פתוח 80°), חלון — לוח
  שקוף.
- **עצמים:** לפי `shape`: box/cylinder/extruded_polygon/stepped (טריבונה = N קופסאות מדורגות)/composite (רשימת
  חלקים יחסיים מהספרייה). מופעים חוזרים (כיסאות) ב־`InstancedMesh`. כל עצם `userData = {id, kind}` לבחירה.
- **מצלמות:** גוף קטן + קונוס שקוף לפי `rotation/fov/coverage_radius`, מוטה ב־10° מטה (ברירת מחדל; ניתן לשינוי
  בפאנל העוגן: `tilt_deg`, שדה חדש בעוגן). **ישויות HA:** סמל מרחף עם צבע מצב; מנורות — הילה ואור נקודתי חלש
  כשדולקות; דלתות/מנעולים — מצב פתוח/נעול.
- **מפלסים ומחברים:** לוחות בגבהים שונים; מדרגות = קופסאות מדורגות בין הגבהים; מעלית = פריזמה שקופה.
- **תוויות:** שמות חדרים כ־sprites בגובה 0.1 מ׳; שמות עצמים בריחוף.

### 10.3 שליטה וסנכרון
Orbit/zoom/pan; תצוגות מוכנות (למעלה, איזומטרי, "לפי מצלמה X" — המצלמה הווירטואלית בעמדת המצלמה); שכבות
כמו ב־2D; מתג מפלס; לחיצה בוחרת עצם ומסנכרנת עם ה־2D (מצב בחירה משותף); ריחוף = tooltip; לחיצה על מצלמה = אריח
לייב (קיים); לחיצה על מעגל = הפעולה הקיימת של HA (הרשאה + אישור). קיצור: `3` פותח/סוגר.

### 10.4 רמות איכות
1. **סכמטית (שלב 4):** חומרים שטוחים, תאורה סביבתית + כיוונית, בלי צללים; 60 fps בדסקטופ, ≥ 30 fps בטלפון
   (עד 3,000 עצמים בזכות instancing; מעבר לזה — הסתרת עצמים קטנים לפי מרחק).
2. **ריאליסטית (שלב 6):** מתג "איכות": PBR, צללים רכים, טקסטורות מהספרייה (עץ, בטון, זכוכית), שמיים ו"שעה ביום".
3. **סיור בגובה עין (שלב 6):** pointer-lock + WASD/מסך מגע, גובה 1.7 מ׳, התנגשות בקירות (בדיקת קטע מול קירות
   2D — זול ומדויק), כניסה דרך דלתות פתוחות.

### 10.5 דטרמיניזם ובדיקות
`scene-builder.ts` מייצר "תיאור סצנה" (רשימת meshes עם מיקום/מידות/צבע) לפני היצירה ב־three; בדיקות snapshot על
התיאור לכל תוכנית מסט הבדיקה; צילומי מסך (Playwright, WebGL תוכנתי) לעין אנושית בלבד.

## 16. החלטות שנקבעו בתכנון (לא פתוחות)

1. חדרים נשארים ב־`spatial_zones` (עם `level_id`); המסמך מפנה אליהם — לא מכפילים פוליגונים.
2. עצמים: מיקום ב־0–1, מידות במטרים; כיול מחדש לא מזיז עצמים (6.4).
3. פתחים ב־3D בפיצול קיר, לא CSG.
4. three.js כספריית 3D, ב־chunk נפרד; בלי CDN.
5. הספרייה המובנית היא קובץ JSON עם גרסה; פריטים מותאמים בטבלה; "מבוסס על" שומר קשר לפריט המובנה.
6. זיהוי סינכרוני עם timeout, לא מנגנון jobs (הזמן קצר; jobs נשמרים ל־AI העתידי).
7. ייצוא PNG בשרת מרסטר את הפרימיטיבים ישירות (Pillow), בלי ספריית SVG חדשה.
8. הסכימה הישנה `plan.schema.json` יוצאת משימוש לטובת v2 (הפרומפט העתידי יפנה ל־v2).
9. שם הרכיב: "סטודיו התוכנית" (Plan Studio); בממשק — לשונית "סטודיו" בעורך ומתג "3D" בצופה ובעורך.
