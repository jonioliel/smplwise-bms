# SMPLWISE VMS — חבילת פיתוח וניהול

**גרסה 1.1.0-planning · 14.09.2026**

מפרט בעברית, ההדמיות המקוריות, **83 משימות, 166 דרישות, 166 בדיקות קבלה מתוכננות ו־32 מסכים**. זו חבילת תכנון, לא מערכת מותקנת. שום בדיקת VMS/HA/NVR חיה לא הורצה במסגרת עדכון זה.

## מתחילים כאן

חַלץ לתיקייה חדשה או שלב בענף עבודה עם diff, בלי לדרוס קוד/ניהול קיים. פתח את תיקיית הפרויקט ב־Codex המקומי והדבק את `prompts/SEND_TO_CODEX_HE.md`. אין צורך להעתיק את כל המסמכים לפרומפט. יש להעמיד בסביבה גם את מקור המערכת הישנה והוראות ההרצה; סיסמאות מחוץ למאגר.

קרא `MASTER_SPEC_HE.md` — המפרט המאוחד העדכני. הפרק החדש 40 והמסמך `docs/security/HA_IDENTITY_RBAC_HE.md` מפרטים את ההרחבה. קובצי PDF/Word המקוריים נשמרו ללא שינוי ב־`docs/archive/v1.0/`, ולכן אינם משמשים כמפרט v1.1.

## מה נוסף ב־1.1

- Add-on/App ייעודי ל־HAOS עם Ingress הוא תוצר מחייב; go2rtc חיצוני. גשר הזהות ופעולות HA בפיילוט, הכרטיסים המורחבים בהמשך.
- משתמשים קיימים מ־HA, קבוצות ותפקידים מקומיים של VMS. משתמש HA רגיל יכול להיות editor/site_admin בקומה/אתר מוגדרים בלי מנהל HA ובלי מנהל מערכת VMS.
- ניהול משתמשים בסיסי קודם לשחרור Pilot: T076–T081/T083 הם P0. האצלה ותפקידים מותאמים מתקדמים ב־T082/V1.
- בדיקות scope, אי־הסלמה, זיוף זהות, ביטול sessions, שמירת הרשאות HA וגישה של משתמש רגיל דרך Ingress.

## ניהול מצב

`management/tasks.json` הוא מקור סטטוס המשימות. `management/test_catalog.json` הוא מקור תוצאות בדיקה. `management/requirements.json` הוא מקור הדרישות. לשינוי דרישה משתמשים ב־Change Request; כל הקשרים נשמרים.

```bash
python scripts/project_status.py
python scripts/project_status.py --write
```

הכלי מקומי, ללא רשת וללא הפעלת agents. הוא מחדש `PROJECT_BOARD.html`, STATUS, TRACEABILITY וכרטיסי משימות. לוח HTML הוא Snapshot לקריאה, לא מערכת שמפעילה את Codex. Python 3.10 ומעלה.

## מבנה

`MASTER_SPEC_HE.md` — 40 פרקים; `AGENTS.md` — גבולות פעולה; `docs/design/` — נכסי מקור וחוזה עיצוב; `docs/security/` — זהות, קבוצות ו־RBAC; `docs/changes/` — שינוי מאושר; `docs/legacy/` — חמישה מסמכים היסטוריים, לא המקור הפעיל; `contracts/` — חוזי תכנון ו־fixtures; `management/` — משימות/דרישות/בדיקות; `prompts/` — הפעלה ו־AI תוכניות; `templates/` — החלטות ותיעוד.

## כללים שלא השתנו

Legacy-first; מפות במרכז; אין שינוי בהקלטה המקורית; UTC/IANA ולא offset קבוע; סודות בשרת; מדיה ו־WebRTC נבדקים בנפרד מ־Ingress; AI אינו מפעיל ציוד או מפרסם תוכנית ללא אישור; כל UI חייב להתאים לנכסי העיצוב.

סדר הקדימות: שינוי דרישה מאושר → המפרט העדכני וחוזי אבטחה → AGENTS → משימה → עיצוב → ארכיון. סתירה נרשמת ולא נפתרת בשקט באמצעות בחירת גרסה נוחה.
